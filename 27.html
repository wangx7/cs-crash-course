3D 图形

3D Graphics

屏幕是平的，世界是立体的。把三维的东西画到二维屏幕上，要经过一整条流水线：投影、拼三角形、扫描线填色、处理遮挡、打光、贴纹理——最后交给成千上万个核心的 GPU 并行去算。

第 0 节

3D 投影：把立体"拍平"

嗨，我是 Carrie Anne，欢迎收看计算机科学速成课！过去五集，我们从基于电传打字机的文字界面，讲到了像素化的位图图形，上集又讲了图形用户界面和它的种种美妙。但这些例子都是 2D 的。可我们生活在 3D 世界里——"我也是个三维女孩"！所以今天来讲 3D 计算机图形的一些基本方法，以及怎么把 3D 图形渲染到 2D 屏幕上。

之前讲过，可以写一个函数，在任意两点 A 和 B 之间画一条线（课程说是第 24 集，实际在第 23 集）。通过控制 A 和 B 的 (X, Y) 坐标，就能控制这条线。在 3D 图形里，点的坐标不再是两个值，而是三个：X、Y、Z。当然，2D 的屏幕上不可能真有 XYZ 立体坐标轴，所以有图形算法负责把 3D 坐标"拍平"，显示到 2D 屏幕上。这叫 3D 投影。

所有点都从 3D 转成 2D 之后，就可以用画 2D 线段的函数把这些点连起来。这叫线框渲染（wireframe rendering）。想象用筷子做一个立方体，然后用手电筒照它：墙上的影子就是投影，是平的。如果旋转立方体，投影看起来就像个 3D 物体，尽管投影面是平的。计算机也是这样把 3D 转成 2D 的，只不过用的是大量数学，而不是筷子。

动手：旋转一个线框立方体

3D 投影有好几种。上面一开始看到的叫正交投影（orthographic projection），立方体里互相平行的边，在投影里也互相平行。但在真实的 3D 世界里，平行线越远越会汇聚到一点，就像远处的马路汇成一点。这叫透视投影（perspective projection）。过程类似，只是数学稍有不同。有时你想要透视效果，有时不想，这由开发者决定。

两种投影的数学差在哪 正交投影直接丢掉 Z：屏幕坐标 = (X, Y) × 缩放。透视投影要除以距离：屏幕坐标 = (X, Y) × 缩放 ÷ (Z + 相机距离)。离得越远（Z 越大），除出来越小，所以远处的边缩短、平行线汇聚。上面读数里那个点的坐标变化就是这么算的。CSS 里的 perspective 属性做的也是这件事。
第 1 节

多边形与网格：三角形万岁

画立方体这种简单图形，直线就够了。但对更复杂的图形，三角形更好。在 3D 图形学里，我们把三角形叫作多边形（polygon）。看看这个用多边形拼成的漂亮茶壶。一堆多边形的集合叫网格（mesh）。网格越密，表面越光滑，细节越多，但也意味着更多计算量。游戏设计者要在角色的真实感和多边形数量之间取得平衡：数量太多，帧率就会掉到肉眼能感觉到的程度，用户会觉得卡。所以有专门简化网格的算法。

之所以常用三角形，而不是正方形或其他更复杂的形状，是因为三角形简单：空间中三个点确定一个平面。给我三个 3D 点，我就能画出一个平面，而且只有这一个答案。四个或更多点就不一定了；两个点又不够，只能确定一条线段。所以 3 是最完美的数字。三角形万岁！

茶壶从哪来 课程里那只茶壶很有名，叫"犹他茶壶"：1975 年犹他大学的研究者马丁·纽厄尔照着自家茶壶建了模型，后来几十年里成了图形学测试渲染算法的标准道具。本页用一个球来代替它，网格、光照、纹理的道理完全一样。
第 2 节

扫描线渲染与抗锯齿

线框渲染虽然很酷，但 3D 图像需要填充。填充图形的经典算法叫扫描线渲染（scanline rendering），1967 年诞生于犹他大学。为了简单，我们只看一个多边形，想想它怎么变成一块填满像素的区域。

先铺一层像素网格。扫描线算法先读多边形的三个点，找出最大和最小的 Y 值，只在这两者之间工作。然后从上往下，一次处理一行：计算这一行和多边形相交的两个点——因为是三角形，如果和一条边相交，就必然和另一条边也相交——然后把两个交点之间的像素填满。下一行，再下一行……所以叫扫描……线……渲染。扫到底部就完成了。计算机填充多边形的速度叫填充率（fillrate）。

动手：一行一行地扫

当然，这样的三角形挺丑的，边缘全是锯齿。像素小的时候不那么明显，但你肯定在游戏里见过这种效果，特别是在配置低的电脑上。减轻锯齿的一种方法叫抗锯齿（antialiasing）。与其每个像素都涂成一样的颜色，不如看多边形切过这个像素的程度来调整颜色：像素完全在多边形内部，就直接涂色；多边形只划过像素的一部分，颜色就浅一些。这种边缘羽化的效果看起来舒服多了。

抗锯齿用得很广，比如字体和图标。如果你把脸贴近屏幕——近点……再近点——就能看到浏览器里的字是抗锯齿的，超级平滑。

第 3 节

遮挡：画家算法与深度缓冲

3D 场景里到处都是多边形，但只有一部分能看见，其他的被挡住了。这叫遮挡（occlusion）。最直接的处理办法是用排序算法，把多边形从远到近排好，然后从远到近渲染。这叫画家算法（Painter's Algorithm），因为画家也是先画背景，再画近处的东西。

看这个例子：三个互相重叠的多边形，为了简单画成不同颜色，并假设它们都和屏幕平行（实际应用里，比如游戏中，多边形可能是倾斜的）。三个多边形 A、B、C，距离分别是 20、12、14。

还有一种方法叫深度缓冲（Z-buffering），做的事情一样，但方法不同。它不用排序，所以更快。简单说，深度缓冲会记录场景里每个像素和摄像机的距离，在内存里存一个数字矩阵，叫 Z 缓冲区。

动手：两种算法处理同一个场景

深度缓冲的过程是这样的：一开始，每个像素的距离都初始化为"无限大"。然后从列表里第一个多边形开始处理，这里是 A。它和扫描线算法的逻辑相同，只是不给像素涂色，而是把多边形的距离和 Z 缓冲区里记录的距离比较，总是记下更小的那个。A 距离 20，每次都比"无限大"小，所以缓冲区记下 20。处理完 A，再处理列表里的下一个，以此类推。因为没有对多边形排序，后处理的多边形不一定会覆盖前面的：处理 C 时，缓冲区里只有一部分值被换成了新的最小距离。

完成的 Z 缓冲区会和一个更高级的扫描线算法配合使用：它不仅计算交点，还会查一下这个像素在最终画面里是否可见；不可见就跳过，继续往下。

两个多边形距离相同时，会出现一个有趣的问题。比如 A 和 B 距离都是 20，该画哪个在上面？多边形在内存里不断被挪来挪去，访问顺序一直在变；再加上浮点运算天生有舍入误差，所以哪个画在上面往往无法预测。结果就是一种闪烁效果，叫 Z-fighting。如果你玩过 3D 游戏，肯定见过。

说到故障，3D 图形里还有一个常见的优化，叫背面剔除（back-face culling）。想想看，三角形有两面：正面和背面。像游戏角色的头部、游戏里的地面，你只应该看到一面——朝外的那一面。所以为了节省处理时间，渲染流水线经常忽略多边形的背面，这样要处理的多边形面数少了一半。这很好，但有个 bug：如果你钻进模型内部往外看，头和地面会消失。下面的球可以打开背面剔除，看看少处理了多少三角形。

第 4 节

光照与纹理

接下来讲光照，也叫明暗处理（shading），因为 3D 场景里物体表面应该有明暗变化。回到茶壶网格：用扫描线算法渲染所有多边形后，茶壶看起来是这样——没什么 3D 感。我们来加点光照，提高真实感。

从茶壶不同位置挑三个多边形。和之前的例子不同，这次要考虑这些多边形面朝的方向：它们不平行于屏幕，而是朝着不同的 3D 方向倾斜。多边形面朝的方向叫表面法线（surface normal），可以用一个垂直于表面的小箭头来表示。

现在加一个光源。每个多边形被照亮的程度不同，有的更亮，因为它们的朝向让更多光反射到观察者这里。比如底部的多边形向下倾斜、背离光源，所以更暗；最右边的多边形更背对光源，所以只被照亮一部分；左上角的多边形朝向的角度会把光反射到我们这里，所以显得更亮。对每个多边形都这样做，茶壶看起来就真实多了！这叫平面着色（flat shading），是最基本的光照算法。

不幸的是，平面着色让多边形的边界非常明显，看起来不光滑。所以人们开发了更多算法，比如高洛德着色（Gouraud shading）和冯氏着色（Phong shading）。它们不是给整个多边形涂一种颜色，而是用巧妙的方式在多边形内部改变颜色，效果更好。

还要说说纹理。图形学里的纹理指的是外观，而不是手感。和光照算法一样，纹理也有多种算法，能做出各种花哨效果。最简单的是纹理映射（texture mapping）。回到单个多边形：用扫描线算法填充时，可以去查内存里的一张纹理图像，决定每个像素用什么颜色。为此，需要把多边形的坐标和纹理的坐标对应起来。扫描线算法要填第一个像素时，纹理算法会去查纹理，从相应区域取平均颜色，填进多边形。重复这个过程，就贴上了纹理。

把这集讲的所有技巧结合起来，就能得到一只精致的小茶壶。这只茶壶还可以放进一个更大的场景里，场景由数百万个多边形组成。渲染这样的场景需要大量计算，但重要的是，不管场景多大，过程都一样：对数百万个多边形，一遍又一遍地做扫描线填充、抗锯齿、光照和纹理。

第 5 节

GPU：为图形专门造的处理器

不过，有几种办法可以加速渲染。第一，可以为这类特定运算造专门的硬件，让它快如闪电。第二，可以把 3D 场景分解成很多小块，然后并行渲染，而不是一块接一块按顺序渲染。

CPU 不是为此设计的，所以图形运算不快。于是计算机工程师给图形做了专门的处理器，叫 GPU（图形处理单元，Graphics Processing Unit）。GPU 在显卡上，周围有专用的 RAM，所有网格和纹理都放在里面，让 GPU 的众多核心能高速访问。现代显卡，比如 GeForce GTX 1080 Ti，有 3584 个处理核心，提供大规模并行处理，每秒能处理上亿个多边形！

GPU 后来不只画图 "大量简单运算同时做"这个特点，后来被发现特别适合神经网络训练——那也是海量的乘法和加法。今天 AI 用的加速卡，就是从显卡演化来的（第 34 集讲机器学习）。浏览器里的 WebGL / WebGPU，就是让网页的 JavaScript 能把这类工作交给 GPU。

第 6 节

本集小结

步骤做什么关键词
投影3D 坐标 (X, Y, Z) 拍平成 2D 屏幕坐标正交投影、透视投影、线框渲染
建模用三角形拼出物体表面；三点定一个平面多边形、网格、多边形数量 vs 帧率
填充逐行算出和三角形边的交点，填满中间的像素扫描线渲染（1967，犹他大学）、填充率、抗锯齿
遮挡近的挡住远的画家算法（排序）、深度缓冲（Z-buffer）、Z-fighting、背面剔除
光照按表面法线和光源的夹角决定明暗平面着色、高洛德着色、冯氏着色
纹理按纹理坐标去图像里取颜色纹理映射
加速专用硬件 + 分块并行GPU、显存，GTX 1080 Ti 有 3584 个核心
一句话 3D 渲染就是对海量三角形重复同一套流程：投影到屏幕、扫描线填像素、用深度缓冲决定谁在前面、按法线打光、按纹理坐标贴图。因为每个三角形、每个像素的工作都一样且互不相干，所以最适合交给成千上万个核心的 GPU 并行去做。

合上页面，试着回答

1. 正交投影和透视投影有什么区别？
正交投影里，物体中平行的边在投影后仍然平行，远近一样大；透视投影模拟真实世界，越远越小，平行线在远处汇聚到一点。
2. 3D 图形为什么偏爱用三角形拼网格？网格越密有什么好处和代价？
三个点恰好确定唯一一个平面，四个以上的点不一定共面，两个点不够。网格越密表面越光滑、细节越多，但计算量越大，多了会让帧率下降、画面卡顿。
3. 画家算法和深度缓冲各怎么处理遮挡？A、B、C 距离 20、12、14 时，深度缓冲处理完 C 后哪些格子会变？
画家算法把多边形从远到近排序，按顺序画，近的盖住远的。深度缓冲不排序，给每个像素记一个最近距离（初始为无限大），处理每个多边形时只在它更近的像素上更新。处理 C（14）时，只有 C 和 A 重叠、而 B 没盖住的那些格子（原来是 20）和原来空着的格子会变成 14；被 B（12）占着的格子不变。
4. 平面着色有什么缺点？GPU 为什么比 CPU 更适合做图形运算？
平面着色给整个多边形一个颜色，多边形边界很明显、看起来不光滑，所以有了高洛德、冯氏着色。图形运算是对大量多边形和像素重复同样的简单计算，可以拆成小块并行；GPU 有成千上万个核心和专用显存，正为此设计。
