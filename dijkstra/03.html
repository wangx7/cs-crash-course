第 1 章

图怎么存进电脑：邻接表

代码不认识图画，我们得把地图变成数据。最常用的方式叫邻接表：给每座城市列一张清单，写上"从这里出发能直接到哪、路多长"。

const graph = {
  HG: [['KL', 8], ['RR', 10], ['PY', 14]],          // 高庭
  KL: [['HG', 8], ['TR', 5], ['RR', 25]],           // 君临
  RR: [['HG', 10], ['KL', 25], ['TR', 2], ['PY', 3]], // 奔流城
  TR: [['KL', 5], ['RR', 2], ['WF', 10]],           // 三叉戟河
  PY: [['HG', 14], ['RR', 3], ['WF', 18]],          // 派克城
  WF: [['TR', 10], ['PY', 18]],                     // 临冬城
};

注意每条路出现了两次：高庭的清单里有 ['KL', 8]，君临的清单里也有 ['HG', 8]。因为路是双向的。如果是单行道（有向图），就只写一次。

🔍 另一种存法：邻接矩阵，以及什么时候用它

也可以画一张 N × N 的表格，第 i 行第 j 列写"i 到 j 的路长"，没有路就写 ∞。这叫邻接矩阵。它查"i 和 j 之间有没有路"只要一步，但不管路多不多都要占 N² 个格子。

道路网这种图，每个路口只连着三四条路，矩阵里绝大部分是 ∞，非常浪费。所以导航软件这类场景都用邻接表。1959 年 Dijkstra 的原论文其实没有规定存法，他的分析默认每一轮要把所有节点扫一遍，这在矩阵上和在表上一样。

第 2 章 · 本篇核心

原版代码：一行一行跑给你看

下面是和 1959 年原版思路一致的写法：每一轮把所有城市扫一遍，找出最小的候选。左边高亮的是正在执行的那一行，右边是此刻所有变量的值。

对照上一篇，每一行都能找到对应：

代码行对应的步骤
2–4三本账，初始化：起点 0，其他 ∞，确定名单为空
7–9① 挑最小：扫一遍所有城市，记住没确定的里 dist 最小的
10没有候选了（剩下的都是 ∞，从起点到不了），结束
11把 u 加入确定名单
13–17② 松弛 u 的每条边
🔍 第 13 行为什么没有跳过已确定的邻居

上一篇说"松弛还没确定的邻居"，代码里却对所有邻居都做了比较。这样写不会出错：已确定的邻居 v，dist[v] 已经是最短距离，dist[u] + w 不可能比它小（边权 ≥ 0，而且 dist[u] ≥ dist[v]，因为 v 比 u 先确定），比较自然不成立，什么也不会改。少写一个判断，代码更短。想省掉这几次比较，加一句 if (done.has(v)) continue; 也可以。

把路线倒推出来，再跑一次真的

function pathTo(prev, target) {
  const path = [target];
  while (prev[target] !== undefined) {   // 起点没有 prev，到起点就停
    target = prev[target];
    path.unshift(target);                // 往前插，最后就是正序
  }
  return path;
}

第 3 章

慢在哪里：数一数每一行跑了几次

刚才运行的时候，代码下面的计数器记下了每部分执行的次数。设城市数为 N，路的条数为 L：

  • 第 9 行（扫描找最小）：外层循环每轮确定一座城市，一共 N 轮；每轮把 N 座城市都扫一遍。共约 N × N = N² 次。地图上是 7 × 6 = 42 次（6 轮各确定一座城市，第 7 轮扫完才发现没有候选了，退出）。
  • 第 14 行（松弛）：每座城市确定时，把它的清单走一遍。所有清单加起来，每条路出现两次，共 2L 次。地图上是 18 次。

路网里每个路口通常只连三四条路，L 大约是 N 的一两倍。所以 N 很大时，松弛部分只是 N 的几倍，真正要命的是扫描找最小的 N²。

瓶颈 每一轮都把所有城市从头扫一遍，只为了找出一个最小值。可是两轮之间，账本只有几个邻居的成本变了，其余几乎全没动。每次都从头扫，大部分工作都是重复的。
要是有一种容器，能随时直接拿出最小的，同时改一个数也很便宜就好了。这种容器叫优先队列，最常见的实现叫堆。
第 4 章

堆：随时拿到最小值的容器

二叉堆（binary heap，1964 年由 J. W. J. Williams 提出）是一棵按规则摆放的树：

  • 形状规则：从上到下、从左到右一层层填满，中间不留空。所以它可以直接存进一个数组：位置 i 的两个孩子在 2i+1 和 2i+2，父亲在 ⌊(i−1)/2⌋。
  • 大小规则：每个节点都不大于它的孩子。所以最小的那个永远在最顶上（数组第 0 位）。

它只支持两个操作，都只沿着一条从上到下的路径走：

  • 放进去（push）：先放到最末尾，然后和父亲比，比父亲小就交换，一路上浮。
  • 取最小（pop）：拿走顶上的，把最末尾的一个挪到顶上，然后和较小的孩子比，比孩子大就交换，一路下沉。

动手：往堆里放数、取最小

它在数组里的样子：

动画里橙色的是正在比较/交换的节点。数一数每次操作交换了几次

一棵堆每多一层，能装的节点数就翻一倍：1 层 1 个，2 层 3 个，3 层 7 个……20 层就能装 100 万个。所以 N 个元素的堆只有大约 log₂N 层，上浮或下沉最多走 log₂N 步。100 万座城市，每次取最小只要约 20 步，而不是扫描 100 万次。

📦 封装：优先队列（用二叉堆实现）
push(x)
放进一个元素，约 log N 步
pop()
取出并删除最小的元素，约 log N 步
承诺
任何时候 pop 出来的都是当前最小的
JavaScript 没有内置的堆（Python 有 heapq、Java 有 PriorityQueue、C++ 有 priority_queue），下面的折叠框里给出一个 30 行的实现。
🔍 一个完整的最小堆实现（可直接复制） 
class MinHeap {
  constructor() { this.a = []; }           // 元素是 [优先级, 值]
  get size() { return this.a.length; }
  push(x) {
    const a = this.a;
    a.push(x);
    let i = a.length - 1;
    while (i > 0) {                         // 上浮
      const p = (i - 1) >> 1;
      if (a[p][0] <= a[i][0]) break;
      [a[p], a[i]] = [a[i], a[p]];
      i = p;
    }
  }
  pop() {
    const a = this.a, top = a[0], last = a.pop();
    if (a.length) {
      a[0] = last;
      let i = 0;
      for (;;) {                            // 下沉
        const l = 2 * i + 1, r = l + 1;
        let m = i;
        if (l < a.length && a[l][0] < a[m][0]) m = l;
        if (r < a.length && a[r][0] < a[m][0]) m = r;
        if (m === i) break;
        [a[m], a[i]] = [a[i], a[m]];
        i = m;
      }
    }
    return top;
  }
}
第 5 章

堆版代码，以及一个偷懒的技巧

把"扫描找最小"换成堆。但有个麻烦：松弛把某个城市的成本从 13 改成 12 时，堆里那个"13"怎么办？标准的二叉堆不支持"修改中间某个元素"。

实际写代码时最常用的办法是懒删除：不去改旧的，直接把新的 [12, 三叉戟河] 再放进去一份。旧的 [13, 三叉戟河] 留在堆里当垃圾。以后它被取出来时，发现它比账本上的 dist 大（13 > 12），说明是过期记录，直接扔掉。

堆里的记录（按成本排列，划掉的是过期记录）：

跑完会看到两条过期记录 [13, 三叉戟河] 和 [14, 派克城] 被取出来又扔掉。第 9 行那一句 if (d > dist[u]) continue; 就是懒删除的全部代价。

这个版本里，不再需要"确定名单"：一座城市第一次从堆里被取出（且不是过期记录）时，就是它被确定的时刻；之后再取出它的记录，都会被第 9 行挡掉。

🔍 懒删除会不会让堆变得很大

只有松弛成功时才 push。而每座城市只会被确定一次，它的每条路也只在那一刻被看一次，所以 push 的次数不超过路的条数（无向图每条路算两个方向），再加上起点那一次。堆里最多约 L 条记录，每次操作约 log L 步。而 L ≤ N²，log L ≤ 2 log N，量级上和 log N 一样。

教科书里的另一种做法是"降低键值"（decrease-key）：在堆里找到那个城市，直接把 13 改成 12 再上浮。它需要额外记录每个城市在堆数组里的位置，代码更长，实际速度往往还不如懒删除。

第 6 章

到底快多少，以及原版什么时候反而更好

版本挑最小松弛总复杂度
原版：每轮扫描（1959）N 轮 × NLO(N²)
二叉堆 + 懒删除（最常用）最多 L 次 pop × logL 次 push × logO((N + L) log N)
斐波那契堆（1984）N 次 × log NL 次 × 几乎 1 步O(N log N + L)

第 13 集说的 "N log N + L" 是最后一行，用的是 1984 年 Fredman 和 Tarjan 发明的斐波那契堆，它让"降低某个城市的成本"几乎不花时间。它理论上最好，但实现复杂、常数大，实际工程中很少用；二叉堆版本已经快得足够。

动手：比较三种写法要走多少步

一个反直觉的结论 在稠密图里（L 接近 N²），堆版本是 N² log N，反而比原版的 N² 更慢。所以"原版 N²"不是过时的写法，它是稠密图的最佳选择。选哪种实现，要看你的图长什么样。
第 7 章

写代码时的细节清单

情况该怎么办
有两个候选成本一样挑哪个都行，最终成本一样。只是最短路线可能不止一条，挑法不同，得到的那条可能不同。
有的城市从起点根本到不了它的 dist 会一直是 ∞，prev 为空。原版代码第 10 行在剩下全是 ∞ 时退出，堆版本则是堆空了自然退出。
只关心一个终点在终点被取出/确定的那一刻 break。不能在它第一次被松弛到时就停。
单行道（有向图）邻接表里只写一个方向。算法本身一个字都不用改。
两城之间有好几条路邻接表里都写上就行，松弛自然会选更短的那条。
边权是 0没问题，证明只要求 ≥ 0。
边权是负数不能用 Dijkstra，结果可能是错的，而且不会报错。改用 Bellman-Ford（第 4 篇）。
成本是小数可以，但浮点数相加有误差，两条"一样长"的路比较时可能差一点点。要求精确时可以换成整数单位（比如米代替公里）。
要求"经过的边最少"而不是成本最小那是 BFS（第 1 篇第 3 章），比 Dijkstra 更简单更快。
起点到所有点 vs. 所有点两两之间Dijkstra 算的是一个起点到所有点。所有点两两之间可以对每个起点各跑一次，或者用 Floyd-Warshall 算法。
