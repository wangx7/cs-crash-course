第 0 节

更快的晶体管之外：更多专用指令

随着这个系列的推进，我们看到计算机从每秒大概只能算一次的机械设备，发展到了以千赫、兆赫运行的 CPU。你现在看视频用的设备几乎肯定以吉赫的速度运行——每秒执行几十亿条指令。相信我，这是非常大的计算量！

在电子计算的早期，提升处理器速度的办法通常是缩短芯片里晶体管的切换时间——就是组成逻辑门、ALU 以及前几集讲过的其他部件的那些晶体管。但光让晶体管更快、更高效只能走这么远，所以处理器设计者发展出各种技术来提升性能，不仅让简单指令跑得快，还能执行复杂得多的操作。

上一集，我们给 CPU 写了一个能做除法的小程序，方法是连续做很多次减法。比如 16 除以 4，可以拆成更小的问题：16 − 4 − 4 − 4 − 4，碰到 0 或负数就知道算完了。但这种方法会吞掉很多时钟周期，效率不高。所以今天的大多数处理器把除法作为 ALU 能在硬件里直接完成的一条指令。

当然，这些额外的电路让 ALU 更大、设计起来更复杂，但也更能干——这种"用复杂度换速度"的权衡，在计算史上出现过很多次。比如，现代计算机处理器有专门的电路来做图形运算、解码压缩视频、加密文件，这些操作如果用标准指令来完成，要花非常非常多的时钟周期。你可能听说过带 MMX、3DNow! 或 SSE 的处理器，它们就是有额外花哨电路、能执行额外花哨指令的处理器，用于游戏、加密之类的场景。

这些指令集扩展越来越多，而一旦有人写了利用它们的程序，就很难再把它们删掉。所以指令集往往越来越大，为了向后兼容，所有旧的操作码都会保留下来。英特尔 4004，第一个真正集成的 CPU，有 46 条指令，足够造出一台功能完整的计算机；而现代计算机处理器有上千条不同的指令，用到了各种巧妙复杂的内部电路。

第 1 节

缓存：把一小块 RAM 放进 CPU

高时钟速度和花哨的指令集又带来另一个问题：怎样足够快地把数据送进、送出 CPU。就像有一台强劲的蒸汽机车，却没法足够快地往里铲煤。这里的瓶颈是 RAM。

RAM 通常是 CPU 外面的一个内存模块，这意味着数据要沿着一组叫总线（bus）的数据线在 CPU 和 RAM 之间传来传去。总线也许只有几厘米长，别忘了电信号的传播速度接近光速，但当你以吉赫的速度运行——也就是十亿分之一秒的量级——就连这么一点延迟也开始成问题了。RAM 本身查找地址、取出数据、配置好输出也需要时间。所以一条"从 RAM 读取"的指令可能要几十个时钟周期才能完成，而这段时间里处理器只能闲坐着等数据。

解决办法之一是在 CPU 上直接放一小块 RAM，叫缓存（cache）。处理器芯片上空间不多，所以大多数缓存只有几 KB 或几 MB，而 RAM 通常是几 GB。

缓存提速的方式很巧妙。当 CPU 向 RAM 请求某个内存位置时，RAM 可以不只传回那一个值，而是传回一整块数据。这只多花一点点时间，却能把这一块数据存进缓存。这往往非常有用，因为计算机数据经常是按顺序排列、按顺序处理的。

比如，处理器在给一家餐厅统计当天的销售总额。它先从 RAM 的内存地址 100 取出第一笔交易。RAM 不只送回这一个值，而是送回从地址 100 到 200 的一整块数据，全部复制进缓存。现在，当处理器要下一笔交易、地址 101 的值来累加时，缓存会说："哦，这个值我这儿已经有了，马上给你！"根本不用跑去 RAM。因为缓存离处理器很近，通常一个时钟周期就能给出数据，不用等待。这比每次都在 RAM 之间来回跑要快得多。

当请求的数据已经在缓存里时，叫缓存命中（cache hit）；如果请求的数据不在缓存里，只好去 RAM 取，叫缓存未命中（cache miss）。

第 2 节

缓存当草稿纸，以及"脏位"

缓存还可以当作草稿空间，在做比较长或比较复杂的计算时存放中间值。接着餐厅的例子：假设处理器算完了当天所有的销售额，想把结果存到内存地址 150。和之前一样，它不必一路跑回 RAM 去存，而是存进缓存里的副本——这样存得更快，如果之后还要接着算，取起来也更快。

但这引出了一个有意思的问题：缓存里的数据副本，现在和 RAM 里存的"真正版本"不一样了。这种不一致必须记录下来，以便在某个时候把一切同步好。为此，缓存为它存的每一块内存都配了一个特殊标记，叫"脏位"（dirty bit）——这可能是计算机科学家发明过的最好的术语。

同步最常发生在缓存已经满了、而处理器又请求一块新内存的时候。缓存在清掉旧的一块腾出空间之前，会先检查它的脏位：如果是"脏"的，就先把这块旧数据写回 RAM，再载入新的一块。

为什么"顺序处理的数据"特别占便宜 上面的模拟器里，读 100~119 这 20 笔只有 2 次未命中：第一次读 100 时把 100~109 一起搬了进来，接下来 9 次都是命中。如果数据东一个西一个（比如随机访问一个很大的数组），每次都可能未命中，缓存就帮不上忙了。写前端时也会遇到同样的道理：连续的数组遍历比到处跳的链表、对象访问更快，部分原因就在这里。
第 3 节

指令流水线

另一种提升 CPU 性能的技巧叫指令流水线（instruction pipelining）。想象你要洗一整个酒店的床单，但只有一台洗衣机和一台烘干机。一种做法是按顺序来：把一批床单放进洗衣机，等 30 分钟洗完；然后把湿床单拿出来放进烘干机，再等 30 分钟烘干。这样每小时能洗完一批。

（插一句：如果你有能在 30 分钟内烘干一批衣服的烘干机，请在评论里告诉我品牌和型号，我家的至少要 90 分钟。）

但就算有这台神奇的烘干机，如果把工作并行起来，还能更快。和之前一样，先把一批床单放进洗衣机，等 30 分钟洗完，再把湿床单放进烘干机。但这次，与其干等烘干机的 30 分钟，你同时往洗衣机里放进另一批。现在两台机器同时在转。再等 30 分钟，一批完成了，一批完成一半，还有一批准备放进去。这实际上让你的吞吐量翻了一倍。

处理器设计也能用同样的思路。第 7 集里，我们的示例处理器按顺序、不停地循环执行"取指令—解码—执行"：取指令、解码、执行，取指令、解码、执行……这意味着我们的设计执行一条指令需要三个时钟周期。但这三个阶段用的是 CPU 的不同部分，这就有了并行的机会！在执行一条指令的同时，可以解码下一条指令，再从内存里取再下一条。这些不同的过程可以重叠，让 CPU 的所有部分在任何时刻都在工作。在这种流水线设计里，每个时钟周期都能执行完一条指令，吞吐量变成了三倍。

第 4 节

流水线的麻烦：依赖和条件跳转

但和缓存一样，流水线也会带来一些棘手的问题。一大风险是指令之间的依赖。比如，你可能取到了一个数据，而正在执行的那条指令马上就要修改它，结果流水线里拿到的就是旧值。为了弥补这一点，流水线处理器必须提前查看数据依赖，必要时让流水线停顿（stall），避免出问题。

高端处理器，比如笔记本和智能手机里的那些，更进一步：它们能动态地重新排列有依赖关系的指令，尽量减少停顿、让流水线一直流动，这叫乱序执行（out-of-order execution）。你可以想象，算清楚这一切的电路复杂得难以置信。尽管如此，流水线极其有效，今天几乎所有处理器都实现了它。

另一大风险是条件跳转指令，上一集我们讲过一个例子：JUMP_NEGATIVE。这类指令会根据某个值改变程序的执行流程。一个简单的流水线处理器看到跳转指令时，会长时间停顿，等这个值最终确定下来；只有知道了跳转结果，处理器才开始重新填满流水线。但这会造成很长的延迟，所以高端处理器也有对付这个问题的技巧。

把即将到来的跳转指令想象成路上的一个岔路口——一个分支。高级 CPU 会猜自己要走哪条路，并按照猜测提前把指令填进流水线，这种技术叫推测执行（speculative execution）。当跳转指令最终有了结果，如果 CPU 猜对了，流水线里已经装满了正确的指令，可以毫不延迟地继续跑。但如果猜错了，就必须丢掉所有推测出来的结果，执行一次流水线清空（pipeline flush）——有点像你错过了一个路口，只好掉头回到正路上，好让导航别再一个劲儿地喊。

为了尽量减少清空的影响，CPU 厂商开发了复杂的方法来猜测分支会往哪边走，叫分支预测（branch prediction）。今天的处理器不是五五开地瞎猜，往往能猜对 90% 以上！

分支预测靠什么猜 最简单的线索是"上次怎么走，这次多半还怎么走"。比如上一集求余数的循环，JUMP_NEG 前几次都不跳，只有最后一次跳——按"和上次一样"去猜，只会在最后错一次。真实的预测器会记录每个跳转指令最近的历史，猜得更准。
第 5 节

超标量：一个周期执行好几条

理想情况下，流水线让你每个时钟周期完成一条指令。后来超标量处理器（superscalar）出现了，它们每个时钟周期能执行不止一条指令。即便在流水线设计里，执行阶段时处理器也可能有一整块区域完全闲着。比如执行一条从内存取值的指令时，ALU 就坐在那儿，什么也不干。那为什么不一次取指令、解码好几条，并且只要有可能，就同时执行需要 CPU 不同部分的指令呢？

还可以更进一步：为常用的指令复制几套电路。比如，很多处理器有四个、八个甚至更多完全相同的 ALU，能并行执行很多条数学运算指令！

第 6 节

多核、多 CPU 和超级计算机

好，目前讲的这些技术，主要是优化一个指令流的执行吞吐量。另一种提升性能的方法是用多核处理器同时运行好几个指令流。你可能听过双核或四核处理器，意思是一个 CPU 芯片里有多个独立的处理单元。这在很多方面很像有多个独立的 CPU，但因为它们紧密集成在一起，可以共享一些资源，比如缓存，让多个核心能一起完成共同的计算。

但当核心再多也不够用时，可以造带多个独立 CPU 的计算机！高端计算机，比如 YouTube 数据中心里正在给你传这个视频的服务器，往往需要额外的马力，才能让同时观看的几百人都流畅播放。目前最常见的是双 CPU 和四 CPU 的配置。

可有时候，就连这么多处理能力也不够。于是我们人类变得更加野心勃勃，造出了超级计算机！如果你要做真正的怪兽级计算——比如模拟宇宙的形成——就需要非常强大的计算能力。给台式机多加几个处理器根本不够，你需要很多处理器。不……不……比那还多。多得多！

在这个视频制作时，世界上最快的计算机位于中国无锡的国家超级计算中心。神威·太湖之光有令人脑袋融化的 40,960 个 CPU，每个有 256 个核心！加起来超过一千万个核心……每个核心以 1.45 GHz 运行。这台机器每秒总共能处理 9.3 亿亿（93 千万亿）次浮点数学运算，这个指标叫 FLOPS（每秒浮点运算次数）。相信我，这是非常多的 FLOPS！它能不能用最高画质跑《孤岛危机》还没人说过，但我猜大概可以。

现在的纪录 视频发布于 2017 年。之后榜首换了好几次：2022 年起出现了每秒超过百亿亿次（10¹⁸，1 EFLOPS）浮点运算的机器，比太湖之光快十几倍。思路仍然和课程讲的一样：更多核心、更多处理器，再加上大量专门做并行计算的加速芯片。

长话短说，这些年来计算机处理器不仅快了很多，还复杂了很多，用上了各种巧妙的技巧，在每个时钟周期里榨出越来越多的计算。我们的任务，是用这股不可思议的处理能力去做又酷又有用的事——这就是编程的本质，我们下一集开始讲。下周见！

第 7 节

本集小结

招数解决什么带来的新麻烦
专用电路 / 指令集扩展除法、图形、视频、加密不用拆成几百步电路更复杂；为了兼容，指令只增不减
缓存RAM 太远太慢，CPU 空等缓存和 RAM 不一致 → 脏位、写回
流水线取指、解码、执行可以重叠，每周期完成一条数据依赖 → 停顿 / 乱序执行；条件跳转 → 推测执行、分支预测、猜错清空
超标量执行阶段有部件闲着要同时调度多条指令
多核 / 多 CPU / 超算同时跑多个指令流程序要能拆成可以并行的部分

合上页面，试着回答

1. 缓存为什么能让顺序读取的数据变快？命中和未命中分别是什么？
未命中时，RAM 不只送回请求的那个值，而是送回一整块，存进缓存。之后读相邻地址时，数据已经在离 CPU 很近的缓存里，一个周期就能拿到，这叫命中；不在缓存里、只好去 RAM 取，叫未命中。
2. 脏位是干什么的？什么时候会把数据写回 RAM？
数据写进缓存后，缓存副本和 RAM 不一致，脏位标记这一块"被改过"。等缓存满了、要清掉这一块给新数据腾地方时，如果它是脏的，就先写回 RAM，再载入新块。
3. 流水线为什么能让吞吐量变成三倍？
取指令、解码、执行用的是 CPU 的不同部分。顺序执行时每条指令占 3 个周期，其余部分闲着；流水线让第 n 条执行、第 n+1 条解码、第 n+2 条取指令同时进行，稳定后每个周期都能完成一条。
4. 推测执行猜错了会怎样？为什么分支预测这么重要？
猜错时，流水线里按猜测提前放进去的指令全部作废，要清空流水线、从正确的地址重新取，白白浪费几个周期。程序里跳转非常多，所以猜得越准（今天常常超过 90%），浪费越少。
