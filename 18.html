Operating Systems

计算机快到"人往读卡器里塞程序"比程序本身跑得还慢的时候，就需要一个程序来管理其他程序了。这一集讲操作系统怎样一步步学会批处理、驱动设备、多任务、虚拟内存、内存保护和分时。

第 0 节

从人工上机到批处理

嗨，我是 Carrie Anne，欢迎收看计算机科学速成课！

1940 年代和 50 年代初的计算机，一次只运行一个程序。程序员在自己桌上写好程序，比如写在穿孔卡上，然后拿到一个摆着房间大小计算机的机房，交给专门的计算机操作员。等计算机下一次空闲时，操作员把程序送进去，计算机运行它，吐出一些输出，然后停机。

当计算机还很慢、运行一个程序动辄要几小时、几天甚至几周的时候，这种非常手工的流程还能接受。但上一集说过，计算机变得越来越快……越来越快……呈指数级地快！很快，人跑来跑去往读卡器里塞程序的时间，比运行程序本身的时间还长。我们需要一种让计算机自己操作自己的方式，于是操作系统诞生了。

操作系统，简称 OS，其实也只是程序。但它在硬件上有特殊权限，可以运行和管理其他程序。它通常是计算机开机后第一个启动的程序，之后所有的程序都由操作系统启动。

操作系统起步于 1950 年代，那时计算机变得越来越普及、越来越强大。最早的操作系统改进了手工加载程序这件枯燥的事：计算机不再一次只接收一个程序，而是可以一次接收一批。一个程序跑完，它会自动、几乎立刻开始下一个，不再有停机时间让人满办公室去找下一个要运行的程序。这叫批处理（batch processing）。

第 1 节

设备驱动：不用再"插上祈祷"

计算机变快的同时也变便宜了，于是它们出现在世界各地，尤其是大学和政府机构。很快，人们开始分享软件。但有一个问题。

在哈佛马克一号或 ENIAC 那种"独一份"的计算机时代，程序员只需要为那一台机器写代码，处理器、读卡器、打印机都是已知的、不变的。但随着计算机越来越普及，它们的配置并不总是相同，比如两台计算机 CPU 一样，打印机却不一样。这让程序员非常头疼：他们不仅要操心写自己的程序，还要操心怎样和每一种型号的打印机打交道，以及计算机连接的所有设备——这些统称外部设备（peripherals）。

和早期外部设备打交道非常底层，程序员需要了解每台设备的硬件细节。更糟的是，程序员很少能拿到所有型号的外设来测试代码，所以只能看着手册尽力去写，然后祈祷分享出去以后能用。那时候可不是"即插即用"（plug-and-play），更像是"插上祈祷"（plug-and-pray）。

这显然很糟糕。所以为了让程序员轻松一点，操作系统站出来，充当软件程序和硬件外设之间的中间人。更具体地说，操作系统通过 API 提供了一种软件抽象，叫设备驱动程序（device driver），让程序员能用标准化的方式和常见的输入输出硬件——简称 I/O——打交道。比如，程序员只要调用一个像 print(highscore) 这样的函数，操作系统就会完成把它印到纸上的那些繁重工作。

和前端的类比 这和浏览器很像：你写 fetch()，不用关心电脑用的是网线还是 Wi-Fi、是哪家的网卡——浏览器和操作系统替你处理了。好的抽象，就是让上一层只面对一个统一的接口。
第 2 节

多任务：Atlas 让 CPU 不再闲着

到 1950 年代末，计算机已经快到经常闲着，等待打印机、读卡器这些慢吞吞的机械设备。当程序阻塞在 I/O 上时，昂贵的处理器就在那儿发呆……不是反派那种"冷血"，只是在放空。

50 年代末，英国的曼彻斯特大学开始研制一台叫 Atlas 的超级计算机，它是世界上最早的超级计算机之一。他们知道这台机器会快得吓人，所以需要一种方法来最大限度地利用这台昂贵的机器。他们的解决方案是一个叫 Atlas Supervisor 的程序，于 1962 年完成。这个操作系统不仅能像早期的批处理系统那样自动加载程序，还能在它唯一的 CPU 上同时运行好几个程序。它靠的是巧妙的调度（scheduling）。

假设 Atlas 上正运行着一个游戏程序，我们调用了 print(highscore)，让 Atlas 把变量 highscore 的值打印到纸上，好向朋友炫耀我们是虚拟弹珠游戏的终极冠军。这个函数调用要花一阵子，相当于几千个时钟周期，因为机械打印机和电子 CPU 比起来太慢了。所以 Atlas 不去等 I/O 完成，而是让我们的程序休眠，然后挑选另一个正在等待、准备好运行的程序来运行。最终，打印机会向 Atlas 报告 highscore 已经打印完了，Atlas 就把我们的程序标记为可以继续，在之后某个时刻，它会被再次安排到 CPU 上运行，接着执行 print 语句之后的下一行代码。

这样，Atlas 就能让一个程序在 CPU 上做计算，同时另一个程序在打印数据，还有一个在从纸带上读数据。Atlas 的工程师在这个想法上加倍下注，给计算机配了 4 台纸带读取器、4 台纸带打孔机和多达 8 台磁带机。这让很多程序可以同时进行，共享一个 CPU 的时间。这种由操作系统提供的能力，叫多任务处理（multitasking）。

动手：一个 CPU，三个程序

实心格 = 在 CPU 上运行；虚线灰格 = 在等打印机 / 纸带（I/O）；红色虚线 = CPU 空闲

第 3 节

内存分配与虚拟内存

不过，在一台计算机上同时运行很多程序有一个大问题：每个程序都需要一些内存，而且切换到另一个程序时，不能把这个程序的数据弄丢。解决办法是给每个程序分配一块属于自己的内存。比如，假设一台计算机一共有 10,000 个内存位置，程序 A 可能分到地址 0 到 999，程序 B 分到 1000 到 1999，以此类推。如果某个程序请求更多内存，操作系统决定能不能批准，如果能，再决定接下来分配哪一块。

这种灵活性很好，但带来一个怪现象：程序 A 最后分到的内存块可能不连续，比如地址 0 到 999，加上 2000 到 2999。这还只是个简单例子，真实的程序可能分到几十块，散落在内存各处。可以想象，这会让程序员很难追踪。比如内存里有一长串销售数据，程序每天下班要把它们加起来，可这串数据被存在一堆不同的内存块里。

为了隐藏这种复杂性，操作系统把内存地址虚拟化了。有了虚拟内存（virtual memory），程序可以认为自己的内存总是从地址 0 开始，简单又一致。而实际在计算机内存里的物理位置，被操作系统隐藏和抽象了。又一层新的抽象。

拿程序 B 举例，它分到了从地址 1000 到 1999 的一块内存。在程序 B 看来，这是一块从 0 到 999 的内存。操作系统和 CPU 会自动处理虚拟地址到物理地址的重新映射，所以如果程序 B 请求内存地址 42，实际读到的是地址 1042。

这种内存地址虚拟化对程序 A 更有用。在我们的例子里，它分到了两块彼此隔开的内存，这对程序 A 同样是不可见的：在它看来，自己分到的是一整块连续的 2000 个地址。当程序 A 读内存地址 999 时，碰巧映射到物理地址 999；但如果它读下一个地址 1000，背后会映射到物理地址 2000。

动手：虚拟地址 → 物理地址

程序：

这种机制让程序的内存大小可以灵活增减，叫动态内存分配（dynamic memory allocation），而在程序看来内存始终是连续的。它让一切都变简单了，也给操作系统同时运行多个程序带来了极大的灵活性。

和你写的代码有什么关系 你在 JS 里 new Array(1e6) 或往对象里塞东西时，JS 引擎会向操作系统要内存；操作系统给的是虚拟地址，物理上可能七零八落，但你的程序完全感觉不到。每个浏览器标签页是一个独立进程、有自己的虚拟地址空间，一个页面崩了不会拖垮别的页面——这就是下一节说的内存保护。
第 4 节

内存保护

给每个程序分配自己的内存还有一个好处：程序之间隔离得更好。如果一个有 bug 的程序跑偏了，开始乱写一通，它只能糟蹋自己的内存，影响不到其他程序。这个特性叫内存保护（memory protection）。

它对防范恶意软件，比如病毒，也非常有用。比如，我们一般不希望其他程序能读取或修改我们邮件程序的内存。有了那种权限，恶意软件就可能以你的名义发邮件，甚至窃取个人信息。可不好！

Atlas 既有虚拟内存，也有内存保护，它是第一台支持这些功能的计算机和操作系统！

第 5 节

终端、分时与 Multics

到了 1970 年代，计算机已经足够快、足够便宜，大学之类的机构可以买一台计算机让学生使用。它不仅快到能同时运行好几个程序，还能让好几个用户同时交互地使用。这是通过终端实现的：终端就是一个键盘加一块屏幕，连到一台大计算机上，本身没有任何处理能力。一台冰箱大小的计算机可能连着 50 个终端，供多达 50 个用户使用。

现在操作系统不仅要处理多个程序，还要处理多个用户。为了不让任何一个人吃光计算机的全部资源，人们开发了提供分时（time-sharing）的操作系统。分时意味着每个用户只能使用计算机处理器、内存等资源的一小部分。因为计算机非常快，即使只拿到 1/50 的资源，也足够个人完成许多任务。

早期分时操作系统中最有影响力的是 Multics（Multiplexed Information and Computing Service，多路信息与计算服务），于 1969 年发布。Multics 是第一个从一开始就按安全来设计的主要操作系统。开发者不希望调皮的用户访问他们不该访问的数据，比如学生想登进教授的账户去看期末考试题。这样的功能让 Multics 在当时非常复杂，大约要占用 1 兆位（Megabit）的内存，这在当时可是很多了！光运行操作系统就可能占掉计算机一半的内存！

Multics 的研究人员之一 Dennis Ritchie 曾说：

"Multics 在商业上没能成功，一个明显的原因是它在某种意义上被过度设计了，里面东西实在太多。"—— Dennis Ritchie
第 6 节

Unix：精简的内核

这让 Dennis 和另一位 Multics 研究员 Ken Thompson 决定自立门户，打造一个新的、精简的操作系统，叫 Unix。他们想把操作系统分成两部分：第一部分是操作系统的核心功能，比如内存管理、多任务和 I/O 处理，这叫内核（kernel）；第二部分是一大堆和内核打包在一起、但不属于内核的有用工具，比如各种程序和程序库。

打造一个紧凑、精简的内核，意味着要有意舍弃一些功能。另一位 Multics 开发者 Tom Van Vleck 回忆说："我跟 Dennis 说，我在 Multics 里写的代码，足足有一半是错误恢复代码。"Dennis 说："这些东西我们在 Unix 里全都省掉了。如果出了错，我们有个叫 panic 的例程，一调用它，机器就崩溃，然后你冲着走廊大喊：'嘿，重启一下！'"

你可能听说过内核恐慌（kernel panic），这个词就是这么来的。它指的就是内核崩溃了、没有办法恢复，于是调用一个叫"panic"的函数。最初这个函数做的事只是打印"panic"这个词，然后进入一个无限循环。

这种简单让 Unix 能在更便宜、更多样的硬件上运行，因此在 Dennis 和 Ken 工作的贝尔实验室里大受欢迎。随着越来越多开发者用 Unix 来编写和运行自己的程序，大家贡献的工具也越来越多。1971 年发布后不久，它就有了不同编程语言的编译器，甚至还有了文字处理器，很快成为 1970、80 年代最流行的操作系统之一。

Unix 的后代 你的 Mac 的 macOS、iPhone 的 iOS 都是 Unix 一脉；Linux 是照着 Unix 的样子重写的，安卓、绝大多数服务器、你以后部署前端项目用的云主机，跑的都是它。你在终端里敲的 ls、cd、grep，就是当年那些"内核之外的工具"的后代。
第 7 节

个人电脑的操作系统

与此同时，到 1980 年代初，一台基础计算机的价格已经降到个人买得起的程度，叫个人电脑或家用电脑。它们比大学、公司和政府里的大型主机简单得多，所以操作系统也得同样简单。比如，微软的磁盘操作系统 MS-DOS 只有 160 KB，正如它的名字所说，一张磁盘就装得下。它在 1981 年首次发布，成为早期家用电脑上最流行的操作系统，尽管它没有多任务，也没有内存保护。这意味着程序可能、也确实会经常把整个系统搞崩溃。虽然很烦人，但这是可以接受的权衡，因为用户可以把自己的电脑关掉再打开！

就连微软 1985 年首次发布、整个 90 年代主宰操作系统市场的早期 Windows，也缺乏强有力的内存保护。程序行为不端时，你可能会看到"死亡蓝屏"，这表示某个程序崩溃得太厉害，把整个操作系统都拖垮了。幸运的是，新版 Windows 有了更好的保护，通常不会那么频繁地崩溃。

今天，计算机运行着现代操作系统，比如 Mac OS X、Windows 10、Linux、iOS 和 Android。尽管我们拥有的计算机大多只有一个人在用——就是你！——但它们的操作系统全都有多任务、虚拟内存和内存保护。所以它们能同时运行很多程序：你可以在浏览器里看 YouTube，在 Photoshop 里修图，用 Spotify 放音乐，同时让 Dropbox 同步文件。如果没有几十年来对操作系统的研究和发展，这一切都不可能实现——当然，还需要合适的存储器来存放这些程序，我们下周讲。

第 8 节

本集小结

  • 1950s批处理：一批程序自动接连运行，不用人来回换
  • 设备驱动操作系统做程序和外设之间的中间人，程序只调用 print()
  • 1962Atlas Supervisor：程序等 I/O 时让它休眠、换别的程序上 CPU —— 多任务；还首次有了虚拟内存和内存保护
  • 1969Multics：分时、多用户、从设计起就考虑安全，但过度设计
  • 1971Unix：精简的内核 + 内核外的工具；出错就 panic
  • 1981MS-DOS：160 KB，没有多任务和内存保护，崩了就重启
  • 今天macOS、Windows、Linux、iOS、Android 都有多任务、虚拟内存、内存保护
一句话 操作系统是一个有特殊权限、负责管理其他程序的程序：它替程序跟硬件打交道（驱动），让一个 CPU 轮流跑很多程序（多任务、分时），给每个程序一块看起来从 0 开始、连续的私有内存（虚拟内存、内存保护）。

合上页面，试着回答

1. 设备驱动解决了什么问题？
不同计算机接的外设型号不同，程序员没法为每一种写底层代码、也没法每种都测试。操作系统通过驱动提供统一的 API，程序只要调用 print(...)，具体怎么驱动这台打印机由驱动负责。
2. Atlas 只有一个 CPU，怎么做到"同时"运行多个程序？
调度：一个程序要等慢速 I/O（比如打印）时，操作系统让它休眠，把 CPU 交给另一个准备好的程序；I/O 完成后再把它标记为可运行，之后轮到它时接着往下执行。CPU 不再空等，多个程序轮流共享 CPU 时间。
3. 程序 A 分到物理地址 0~999 和 2000~2999。它读自己的地址 1000，实际读到哪里？为什么要这样设计？
物理地址 2000。虚拟内存让程序看到一块从 0 开始、连续的内存，不用管它在物理上被拆成了几块、在哪里；操作系统和 CPU 自动做映射。这样内存可以灵活增减（动态分配），程序也写得简单。
4. Unix 的"内核"包括什么？为什么说它的精简是一种取舍？
内核只包含核心功能：内存管理、多任务、I/O 处理；其余程序和库都放在内核之外。精简意味着故意舍弃功能，比如大量错误恢复代码——出错就 panic、重启。换来的是能在更便宜、更多样的硬件上运行。
