Data Structures

第 0 节

数组：一个挨一个

上一集讲了一些经典算法，比如给数组排序、在图里找最短路径。我们没讲的是：算法处理的数据，在内存里是以什么格式存放的。你肯定不希望数据乱得像 John Green 的大学宿舍，食物、衣服、纸张丢得到处都是。我们希望数据是有结构的，这样才高效、方便读取。为此，计算机科学家发明了数据结构！

上一集我们已经介绍了一种基本数据结构：数组（array），在有些编程语言里也叫列表（list）或向量（vector）。它是存在内存里的一串值。所以，不再像之前那样一个变量只存一个值，比如 j = 5，我们可以在一个数组变量里存好几个值。要取出数组里的某个值，就要指定一个下标（index）。几乎所有编程语言里，数组下标都从 0 开始，用方括号表示访问。所以，如果想把数组 j 第一个和第三个位置的值加起来、结果存进变量 a，可以写：a = j[0] + j[2]。

数组在内存里的存法非常直接。为了简单，假设编译器从内存地址 1000 开始存数组。这个数组有 7 个数，按顺序一个挨一个存着。如果写 j[0]，程序会去内存地址 1000，加上 0 个偏移，得到地址 1000，读出那里的值：5。如果想取 j[5]，程序去内存地址 1000，加 5 个偏移，得到地址 1005，读出值：4。

动手：下标 → 内存地址

j[0] = 5、j[5] = 4 来自课程，其余数值为示意

"数组里第 5 个数"和"下标为 5 的数"很容易搞混，它们不是一回事。记住，下标 5 其实是数组里的第 6 个数，因为下标是从 0 开始数的。

数组是用途极其广泛的数据结构，一直被用到，所以几乎所有编程语言都自带了大量处理数组的函数。比如给数组排序的函数很常见：只要把数组传进去，它就返回排好序的数组，你不必自己写排序算法。

为什么下标从 0 开始 看上面的图就明白了：下标就是"离起点的偏移"。j[i] 的地址 = 起始地址 + i。第一个元素离起点 0 格，所以是 j[0]。CPU 算地址只要一次加法，这就是数组按下标访问特别快的原因。（真实计算机里一个数通常占好几个字节，地址要再乘以每个元素的大小，课程为了简单当成每个占 1 格。）
第 1 节

字符串：以 null 结尾的字符数组

数组的近亲是字符串（string），它其实就是一串字母、数字、标点和其他书面字符组成的数组。第 4 集讲过计算机怎样存储字符。写代码时，通常用一对引号把文字括起来，比如 j = "STAN ROCKS"。它看起来不像数组，但确实是。在幕后，内存是这样的：

注意最后一格：不是字符"0"，而是二进制值 0。

注意，字符串在内存里以 0 结尾——不是字符"0"，而是二进制值 0。它叫 null 字符，标志着字符串的结尾。这个字符非常重要：如果调用 print 函数在屏幕上显示文字，它会从起始位置开始，一个一个字符地往屏幕上打印，但它得知道什么时候停下来！否则它会把内存里的每一样东西都当成文字打印出来。这个 0 告诉函数什么时候停。

因为计算机经常和文字打交道，所以有很多专门处理字符串的函数。比如很多编程语言有个叫 strcat（string concatenate，字符串连接）的函数，它接收两个字符串，把第二个复制到第一个的末尾。

"停不下来"的危险 上面"删掉 null"后打印出来的那串乱码，就是真实世界里一类经典漏洞的样子：程序读过了字符串的边界，把相邻内存里的数据（可能是密码）一起读出来、发了出去。C 语言的字符串就是这种以 null 结尾的格式；JavaScript 的字符串则另外记着长度，不靠结尾的 0，所以你写 JS 时碰不到这个问题。
第 2 节

矩阵：数组的数组

我们可以用数组表示一维的列表，但有时需要处理二维数据，比如电子表格，或者屏幕上的像素。为此我们需要矩阵（matrix）。你可以把矩阵看成数组的数组！所以一个 3 × 3 的矩阵其实是一个大小为 3 的数组，它的每个位置又存着一个大小为 3 的数组。我们可以这样初始化一个矩阵，它在内存里是这样排列的。

要取出一个值，需要两个下标，比如 j[2][1]。这告诉计算机：找数组 2 里位置 1 的元素，得到的值是 12。

内存里：一行接一行，排成一条

j[2][1] = 12 来自课程，其余数值为示意

矩阵酷的地方在于，它不局限于 3 × 3，可以是任意大小、任意维度。比如可以做一个五维矩阵，然后这样访问：a = j[2][0][18][18][3]。没错，你现在知道怎么访问五维矩阵了——快去告诉你的朋友！

第 3 节

结构体：把相关的变量捆在一起

到目前为止，我们存的都是单个数字或字母，放进数组或矩阵里。但有时把一组相关的变量存在一起会很有用，比如一个银行账号和它的余额。像这样捆在一起的一组变量叫结构体（struct）。现在我们可以存不同类型的数据了，这些数据不再是单个数字，而是复合的数据结构，能一次存好几样数据。我们甚至可以做由自己定义的结构体组成的数组，它们在内存里会被自动打包在一起。如果访问 j[0]，拿回的是存在那里的整个结构体，然后可以取出其中的账号和余额。

这种结构体数组和其他任何数组一样，在创建时就有固定的大小，不能扩大来容纳更多的值。而且数组在内存里必须按顺序存储，所以很难在中间插入一个新值。但结构体这种数据结构可以用来构建更复杂的数据结构，消除这些限制。

第 4 节

指针与链表

来看这个叫节点（node）的结构体。它存着一个变量，比如一个数字，还有一个指针（pointer）。指针是一种特殊的变量，它的名字就来自它的作用：指向计算机内存里的某个位置。

用这个结构体，我们可以创建链表（linked list）。它是一种灵活的数据结构，能存很多个节点。它靠每个节点指向链表中的下一个节点来做到这一点。假设内存里存着三个节点结构体，分别在地址 1000、1002 和 1008。它们之所以隔开，可能是因为在不同时间创建的，中间夹着别的数据。

可以看到，第一个节点存着值 7，它的"下一个"指针里是地址 1008，这意味着链表中的下一个节点位于内存地址 1008。走到那里，下一个节点存着值 112，指向地址 1002。跟过去，看到一个值为 14 的节点，这个节点又指回地址 1000，也就是第一个节点。这种链表叫循环链表。但链表也可以是非循环的：最后一个指针设为 0，也就是"null"，表示到了链表的尽头。

程序员使用链表时，很少去看"下一个"指针里存的具体内存地址，而是用链表的抽象模型，就像下面右边那样，这样更容易理解。

动手：链表的两种看法

数组的大小必须预先定好，而链表可以动态地变大变小：可以创建新节点，通过修改指针值把它插进链表。链表也很容易重新排序、从两端缩短、拆成两半、反转等等，超级方便！链表还很适合上集讲的那些排序算法。因为这么灵活，很多更复杂的数据结构都建立在链表之上，最有名、最普遍的是队列和栈。

第 5 节

队列与栈

队列（queue）就像邮局里排队：谁先来，谁就先被服务。哪怕你只想买张邮票，而前面那个人要寄 23 个包裹。这叫先进先出（FIFO，first-in first-out）——我是说队列，不是说那 23 个包裹。

想象我们有一个叫"邮局队列"的指针，指向链表的第一个节点。服务完 Hank 之后，读取 Hank 的"下一个"指针，把"邮局队列"指向下一个人。这样我们就把 Hank 出队（dequeue）了——他办完了，离开队列。如果想把某人入队（enqueue），也就是加进队列，就要沿着链表一直走到末尾，把末尾节点的"下一个"指针指向新来的人，比如 Nick。

只要稍作修改，我们也能用链表做栈（stack），栈是后进先出（LIFO，last-in first-out）的。你可以把它想成一叠松饼：做好一个新松饼，就把它叠到之前那些上面；吃的时候，先吃最上面那个。美味！数据不叫入队和出队，而是入栈（push）和出栈（pop）。没错，这些就是正式的术语！

你天天在用 第 12 集那个"调用栈"就是栈：最后调用的函数最先返回。浏览器的"后退"按钮是栈；JavaScript 的事件循环里，等待执行的回调排的是队列。
第 6 节

树与图

如果把节点结构体改一下，让它不只有一个指针，而是有两个，就能构建树（tree），另一种在很多算法里用到的数据结构。同样，程序员很少去看这些指针的具体值，而是把树抽象成这样：最上面的节点叫根节点（root），根节点下面的所有节点都叫子节点（children）。任何一个子节点直接上方的那个节点，叫它的父节点（parent）。这个例子能说明托马斯·杰斐逊是阿伦·伯尔的父亲吗？这就留给你们的同人小说来决定吧。没有任何子节点的节点——也就是树到头的地方——叫叶节点（leaf）。

在我们的例子里，节点最多只能有两个子节点，所以这种树叫二叉树（binary tree）。但你完全可以改成三个、四个或更多，甚至可以让节点用链表来存它所有的子节点。不管是现实中的树还是数据结构里的树，一个重要的性质是：从根到叶是单向的。如果根连着叶、叶又连回根，那就很奇怪了。

如果数据是随意连接的，包括存在循环，可以用图（graph）来表示。还记得上一集用道路连接城市的那张图吗？这种结构可以用带多个指针的节点来表示，所以没有根、叶、子节点、父节点这些概念，任何节点都可以指向任何其他节点！

以上概述了计算机科学中最主要的一些数据结构。在这些基本结构之上，程序员还做出了各种具有不同性质的新变体，比如"红黑树"和"堆"，我们没时间讲了。不同的数据结构适用于不同的场景，为工作选对数据结构能让事情简单得多，所以花时间考虑用哪种数据结构是值得的。幸运的是，大多数编程语言都自带了预先打包好的数据结构库，比如 C++ 有它的标准模板库，Java 有 Java 类库。这意味着程序员不必浪费时间从零开始实现，可以把时间花在更有趣的事情上——又往上提升了一层抽象！下周见！

第 7 节

本集小结

数据结构怎么存特点
数组一个挨一个连续存放按下标取值极快（起始地址 + 下标）；大小固定，中间插入难
字符串字符数组，以 null（二进制 0）结尾函数靠 0 知道在哪停
矩阵数组的数组，在内存里一行接一行多个下标 j[2][1]，任意维度
结构体把几个相关变量捆在一起可以组成数组，也是构建复杂结构的零件
链表节点 = 值 + 指向下一个节点的指针节点可以散在内存各处；动态增减、插入只改指针
队列 / 栈建在链表之上队列先进先出（入队 / 出队）；栈后进先出（push / pop）
树节点有多个指向子节点的指针根、父、子、叶；从根到叶单向
图节点可以随意指向任何节点可以有循环，没有根和叶
一句话 数组靠"连续存放 + 下标偏移"换来速度，代价是死板；链表靠"指针"换来灵活，代价是只能一个个顺着找。队列、栈、树、图都是用指针把节点按不同规则连起来。选对数据结构，算法会简单很多。

合上页面，试着回答

1. 数组从地址 1000 开始，j[5] 在哪个地址？它是数组里的第几个数？
1000 + 5 = 1005。下标从 0 开始，所以 j[5] 是第 6 个数。
2. 字符串结尾的 null 是做什么的？如果它丢了会怎样？
它是二进制值 0，标志字符串结束。print 之类的函数从开头逐个处理字符，遇到 0 才停。丢了的话，函数会一直读下去，把后面不相干的内存也当成文字处理。
3. 在数组中间插入一个值很难，在链表中间插入为什么容易？
数组必须连续存放，插入要把后面所有元素往后挪（而且大小固定）。链表的节点可以放在内存任何地方：新节点随便放，只要让前一个节点的指针指向它、它的指针指向原来的下一个节点，改两个指针就行。
4. 队列和栈的区别？各举一个生活中的例子。
队列先进先出（FIFO），像邮局排队；栈后进先出（LIFO），像一叠松饼，最后放上去的最先被吃。
