第 1 节 · P81

面向对象是什么

很多人听说面向对象非常难。其实多半是没想清楚它到底是什么、能解决什么事。从字面上理解：面向，就是"拿"或者"找"；对象，就是能干活的东西。合起来：在代码里想完成一件事的时候，拿对应的东西来做这件事。

其实我们早就是面向对象的程序员了，只是没注意到。回头看以前写的代码：

  • 要获取一个随机数，找的是 Random；
  • 要在控制台输出内容，找的是 System；
  • 要获取键盘录入的数据，找的是 Scanner。

做什么事都找对应的东西来解决，这种思路就叫面向对象编程。就这么简单。

为什么 Java 要采取这种方式？因为它和现实生活的套路一模一样：洗衣服不是自己洗，找洗衣机；扫地找扫地机器人；和女朋友聊天通过手机。现实里想干什么都是找一个个东西来解决，程序里也这样做，更符合人类的思维习惯，编程更简单、更好理解。

面向对象到底要学什么？两件事：

① 获取已有的对象并使用

比如获取随机数的 Random、键盘录入的 Scanner。随着课程深入，还会学到很多能解决其他事情的对象。

② 自己设计对象并使用

要做的事没有现成的东西帮你做怎么办？想用锤子砸钉子，手上没有锤子，就得先自己造一个再去用。这里就涉及面向对象的语法了。

这一章的课程结构：先学如何自己设计对象并使用；设计时遇到有争议的问题，用封装思想解决；然后是几个基本语法：this 关键字、构造方法、标准的 JavaBean；再讲对象在内存里是怎么回事；最后补一个小知识点，成员变量和局部变量。本篇讲到封装，后面的内容在下一篇和再下一篇。

第 2 节 · P82

类和对象：先有设计图，才能造东西

对象是能帮我们解决问题的东西，但它们不是凭空出现的：造东西之前要先有设计图。在 Java 里，设计图就叫类，用来描述一类事物；根据设计图造出来的东西，才是能帮我们干活的对象。所以写代码时，必须先设计类，才能获取对象。

类里面能写很多东西，重点先看两个：

成员变量：属性

一般是名词。手机的品牌、价格、颜色……

成员方法：行为

一般是动词，表示这类事物能干什么。手机能打电话、发短信、玩游戏……

新建一个类，描述手机这类事物，类名见名知意叫 Phone：

public class Phone { // 属性 String brand; double price; // 行为 public void call() { System.out.println("手机在打电话"); } public void playGame() { System.out.println("手机在玩游戏"); } }

两个要注意的地方：属性只定义、不给值，因为类只是表示手机这类事物，并不是一部真正的手机；行为以方法的形式体现，只不过和以前相比，方法不加 static。

设计图有了，再新建一个带 main 方法的类（叫测试类）来创建对象。格式是：

类名 对象名 = new 类名();

拿到对象之后，用"对象名 . 成员变量"来获取值或者赋值，用"对象名 . 成员方法()"让它做事：

public class PhoneTest { public static void main(String[] args) { // 创建手机的对象 Phone p = new Phone(); // 给手机赋值 p.brand = "小米"; p.price = 1999.98; // 获取手机对象中的值 System.out.println(p.brand); // 小米 System.out.println(p.price); // 1999.98 // 调用手机中的方法 p.call(); // 手机在打电话 p.playGame(); // 手机在玩游戏 // 第二部手机：把上面的代码再写一遍 Phone p2 = new Phone(); p2.brand = "苹果"; p2.price = 8999; p2.call(); p2.playGame(); } }

new Phone() 一执行，代码世界里就有了一部手机；再 new 一次，就有了第二部。两部手机用的是同一张设计图，但各有各的品牌和价格。

最多造 3 部
设计图：Phone 类（不是手机）String brand; double price; void call() void playGame()
这一节的小结 类是共同特征的描述，可以理解成设计图；对象是真正存在的具体实例，能帮我们做事。得到对象的步骤：先写类（成员变量表示属性，成员方法表示行为），再用 类名 对象名 = new 类名(); 创建，然后用对象名去访问成员变量、调用成员方法。
第 3 节 · P82

定义类的几个注意点

先认识一个专业名词。用来描述一类事物的类，专业叫法是 JavaBean 类，在 JavaBean 类里是不写 main 方法的。那以前写的那些带 main 方法的类呢？它们叫测试类。我们在测试类里创建 JavaBean 类的对象，进行赋值、调用。到这里已经学了两种类，要区分开。

比如定义一个 Student 类描述学生这个群体，属性写姓名和身高，行为写学习和睡觉：

public class Student { String name; double height; public void study() { ... } public void sleep() { ... } }

这段代码在幻灯片上，字幕里只念了"两个属性：姓名、身高；两个行为：学习、睡觉"，变量名和方法名是按讲解还原的。

  • 类名首字母建议大写，见名知意，驼峰命名（大驼峰），不能是关键字，满足标识符的规定；
  • 一个 Java 文件里可以写多个 class，但只能有一个用 public 修饰，而且 public 修饰的类名必须和文件名一致。不过一个文件写多个类没什么实际意义，实际开发中建议一个文件只写一个类；
  • 成员变量的完整格式是 修饰符 数据类型 变量名 = 初始化值;。修饰符暂时空着不写，本篇最后一节就会讲。初始化值一般也不写，只定义不给值。

为什么只定义不给值？Student 这个类不是特指某个具体的学生，它描述的是学生这个群体，而每个学生的姓名、身高都不一样。如果强行在类里写 String name = "张三";，语法没错，但意思成了所有学生都叫张三，和实际不符。所以给属性赋值不是在类里赋，而是创建了对象之后再赋：创建出来的对象才真正表示某一个特定的学生。

练习：女朋友类

需求：编写一个女朋友类，创建女朋友类的对象，给属性赋值，再调用类中的方法。

分析：描述女朋友这类事物，要用到属性和行为。属性都是名词：姓名、性别、身高、体重……很多；行为都是动词：睡觉、吃饭、逛街、撒娇……课上属性写了三个、行为写了两个，自己练习时可以多写。先自己试着写一写，再往下看。

public class GirlFriend { // 属性：只定义，不给值 String name; int age; String gender; // 行为 public void sleep() { System.out.println("女朋友在睡觉"); } public void eat() { System.out.println("女朋友在吃饭"); } }

JavaBean 类定义好了，再写测试类 GirlFriendTest，在 main 方法里创建对象。如果一个值都不赋就直接打印 gf1.name，看到的是默认初始化值 null，这肯定不行，所以先赋值再获取：

public class GirlFriendTest { public static void main(String[] args) { // 创建女朋友的对象 GirlFriend gf1 = new GirlFriend(); gf1.name = "小诗诗"; gf1.age = 18; gf1.gender = "萌妹子"; System.out.println(gf1.name); // 小诗诗 System.out.println(gf1.age); // 18 System.out.println(gf1.gender); // 萌妹子 gf1.eat(); // 女朋友在吃饭 gf1.sleep(); // 女朋友在睡觉 // 第二个对象：把上面的代码重复写一遍，注意把 gf1 都改成 gf2 GirlFriend gf2 = new GirlFriend(); gf2.name = "小丹丹"; gf2.age = 19; gf2.gender = "萌妹子"; System.out.println(gf2.name); // 小丹丹 System.out.println(gf2.age); // 19 System.out.println(gf2.gender); // 萌妹子 gf2.eat(); gf2.sleep(); } }

易错点：第二个对象的代码是粘贴过来的，变量名要全部改成 gf2，漏改一处就成了操作第一个对象。一行一行改麻烦，IDEA 可以竖着选中批量修改：按住鼠标滚轮（中键）不松往下拖，光标变成一竖排，敲一个 2，几行同时改完。没有滚轮就按住 Alt 不松，用鼠标左键拖。

Mac 上的对应操作 竖着选中（列选择）：按住 Option（⌥）用鼠标或触控板拖动；触控板没有中键，用这个就行。课上把两个文件左右并排看的操作是右键点击文件标签 → 拆分并右移，Mac 上菜单相同。
第 5 节 · P82

实际开发里，类里到底写什么：名词提炼法

学生类、女朋友类这些小案例有什么用？以后工作中到底怎么写？实际开发中设计一个类，写什么属性、什么行为不是随便乱写的，而是根据具体的需求来定。

比如大学里用过的学生管理系统，要把一个个学生对象存起来，就得定义学生类。分享一个小技巧，叫名词提炼法：从需求里提炼出名词，这些都可以写成属性；这类事物能干什么，一般是动词，定义成行为。系统里要存学生的学号、姓名、性别、年龄、学校，都是名词，所以属性写 id、name、gender、age、schoolName；学号后面还有一个"验证学号"（验证学号是否合法、可用），这是动词，定义成行为。

加大难度：给一个考试系统的页面，要定义哪些类？第一步先看需求里有几类事物：左边的菜单有班级、老师、学生、试卷，四类事物就定义四个 JavaBean：Grade、Teacher、Student、Exam。再以试卷为例，点开试卷管理的页面，用名词提炼法分一分：

动手：哪些是属性，哪些是行为

点一下词语在 属性 和 行为 之间切换，都分好了点"检查"。

以后怎么设计一个 JavaBean 类 不是自己凭空捏造，而是先把需求拿过来：先看需求里有几类事物，每一类事物定义为一个单独的类；这类事物的名词写成属性；这类事物能干什么（动词）定义成行为。
第 6 节 · P83

封装思想：这个行为该写在哪个类里

前面的场景都比较简单。如果一个需求里有多个事物，有的行为不知道该归哪个类，怎么办？这就用到封装。封装是面向对象的三大特征之一（另外两个是继承和多态，后面学），它的作用是告诉我们：拿到一个需求之后，该如何正确设计对象的属性和方法。

简单的需求不用想：设计一个人，有姓名、年龄、吃饭、睡觉。定义 Person 类，姓名年龄作属性，吃饭睡觉作方法。但实际开发中经常涉及多个对象。比如这个需求：人画圆。涉及两个对象：人（Person）和圆（Circle）。画圆是一个行为，要定义一个方法，这个方法该放在人里，还是圆里？先自己选：

动手：这个方法归谁

大部分人刚接触时会想："人画圆嘛，画圆当然是人的方法。"这是错误的理解。这里要讲封装思想里一个非常重要的原则：

封装的原则 对象代表什么，就得封装对应的数据，并提供数据对应的行为。
  • 人画圆：Circle 类代表圆，封装了圆的信息，比如半径。画圆要根据什么来画？根据半径。Circle 既然封装了半径，就得提供和半径相关的画圆方法。换个角度想：这个圆不是人画的，是圆"自己画"的，人只是调用了圆的方法去画了一个圆。
  • 人关门：更直观一点。人做的事只是给门一个作用力，然后门自己把自己关上了。门是开还是关，是门这个对象的一个状态数据；门封装了这个数据，开门、关门的方法当然就是门的方法。
  • 张三砍了李四，李四凉了（开玩笑的例子）：李四是自己凉的。"凉凉"这个行为应该设计在李四那里；用程序语言描述，就是张三调用了李四的凉凉方法。

这几个例子有点哲学，和现实生活里的直观感受不一样。一时不理解也不用担心，后面会有大量的对象来加深理解。

理解封装的好处：有事找对象，调方法

Sun 公司为了让 Java 好用，基本上把程序员可能要干的事情都提前想好了，设计了很多对象给我们用，汇总在一份文档（API 文档，后面会专门学）里。它设计的每个对象都代表一个事物，也按上面的原则来：提供属性封装对应的数据，再提供处理这些数据的方法。这就意味着：将来要干什么事，找到对应的对象，把要处理的数据交给它，调用它的方法就可以了，不用自己写。

比如处理字符串非常常见，Java 提供了代表字符串的 String。虽然还没学，但用封装思想想一想：String 既然代表字符串，就一定封装了我们要处理的那串字符，并提供处理字符串的各种方法。

String s = "abc"; int len = s.length(); // 获取长度 System.out.println(len); // 3 String up = s.toUpperCase(); // 全部变成大写，方法的结果就是转换之后的字符串 System.out.println(up); // ABC

课上是"随便写一个字符串"，字幕里没有念出具体内容，这里的 "abc" 和变量名是示例。

文档里 String 的方法往下拉有很多很多。万一找完了也没有合适的方法？那就埋怨一下 Sun 公司不够体贴，然后自己写代码处理。再举一个没学过的例子：网络编程里，Java 提供了 Socket 对象代表网络连接。它既然代表一个连接，就必定有属性记住"连谁"，也会提供连接的方法、发送数据的方法。所以用 Java 做网络编程，说白了也是创建对象、调方法。

还有一个好处：降低学习成本。String 的方法那么多，要不要挨个讲、挨个学？绝对不要。String 代表要处理的字符串，方法就算有一百个，也都是用来处理这个字符串的；以后想处理字符串，来这里找就行，挨个学没必要，学了也记不住。老师顺带提醒：把对象的方法一个一个罗列着讲的课、把书写厚的"字典式"教材，价值都不大。

"Sun 公司"现在是 Oracle Java 最初由 Sun Microsystems 公司开发，2010 年 Sun 被 Oracle（甲骨文）收购，现在的 JDK 和 API 文档都由 Oracle 维护。课上沿用了老叫法。
第 7 节 · P83

private 与 get / set：把属性保护起来

属性和行为封装进对象之后，代码怎么写才安全？按之前的写法，有一点不安全。创建女朋友对象，gf1.age = 18; 是正常操作；但别人小手一抖写成 gf1.age = -18;，代码不会报错：age 是 int 类型，int 的取值范围包括负数，语法没问题。可是这和实际情况不符，找女朋友不能找上辈子的。

解决办法是一个关键字：private。

  • private 是一个权限修饰符；
  • 可以修饰成员（成员变量和成员方法）；
  • 最重要的一句：被 private 修饰的成员，只能在本类中才能访问，其他类里不能使用。

成员变量前面加上 private，它就"私有"了，可以理解成藏起来了：只能在 GirlFriend 这个类里用。测试类里再写 gf1.age = -18; 就会报错。数据安全的问题解决了，但带来一个新问题：gf1.age = 18; 这个正确的赋值也不行了。

我们真正想要的是：正确的数据能正常赋值，错误的数据不能赋值。有同学会想：不写 private，在测试类里赋值之前先判断一下不就行了？不行，两个理由：

  • 如果有三千个女朋友对象，每一次赋值都要判断一下，太麻烦；
  • 按封装的原则，GirlFriend 代表女朋友，封装了女朋友的属性，那么对这些属性进行校验的方法，也必须写在 GirlFriend 这个类里。

所以最标准的写法是：所有属性加上 private，不让外界直接访问；同时针对每一个私有的属性，提供一对用 public 修饰的 set 方法和 get 方法。public 也是权限修饰符，和 private 反过来，表示公共的：所有类里都可以使用它修饰的成员。

setXxx(参数)：给成员变量赋值

  • 有参数：要赋值，就得把值给我，我用一个形参去接；
  • 没有返回值，写 void：赋完就完事了，不需要把结果告诉你；
  • 赋值之前可以对传过来的数据做校验。

getXxx()：对外提供成员变量的值

  • 没有参数：对外提供，不需要接收数据；
  • 有返回值，返回值类型和这个成员变量的类型一致：name 是 String 就写 String，age 是 int 就写 int；
  • 方法体就是 return 这个变量。

把女朋友类改写一遍。年龄的要求不要卡太死，一定要 18 岁要求有点高，18 到 50 之间都算正常：

public class GirlFriend { private String name; private int age; private String gender; // 针对每一个私有化的成员变量，都要提供 get 和 set 方法 // set：给成员变量赋值 // get：对外提供成员变量的值 public void setName(String n) { name = n; } public String getName() { return name; } public void setAge(int a) { if (a >= 18 && a <= 50) { age = a; } else { System.out.println("非法参数"); } } public int getAge() { return age; } public void setGender(String g) { gender = g; } public String getGender() { return gender; } // sleep()、eat() 两个行为和之前一样，略 }

setGender 里其实也可以做判断（比如只有"女"才能赋值成功），但字符串的判断还没学，这里先直接赋值。有了 set 和 get，代码里就好比有了一条过滤通道：外界调用 setAge，传来 -18 就提示非法数据，传来 18 才放行、赋值成功。

测试类里不能再用"对象名.属性"了，赋值和获取都得走方法。get 方法的返回值可以用变量接收，也可以直接写在输出语句里，打印方法的结果：

GirlFriend gf1 = new GirlFriend(); // 赋值 gf1.setName("小诗诗"); gf1.setAge(18); gf1.setGender("女"); // 获取 System.out.println(gf1.getName()); // 小诗诗 System.out.println(gf1.getAge()); // 18 System.out.println(gf1.getGender()); // 女

如果把 18 改成 -18 再运行：控制台先打印"非法参数"，表示没有赋值成功；后面 getAge() 拿到的还是默认初始化值 0。

第 8 节

小结

面向对象要干什么事，找能干这件事的东西（对象）来做；没有现成的，就自己设计
类设计图，描述一类事物：成员变量 = 属性（名词），成员方法 = 行为（动词，不加 static）
对象类名 对象名 = new 类名(); 造出来的具体实例；用"对象名.成员"访问
JavaBean 类 / 测试类描述事物的类不写 main；带 main 的测试类里创建对象并使用
成员变量类里只定义不给值，创建对象后再赋；不赋值有默认值：0、0.0、false、null
名词提炼法需求里有几类事物就定义几个类；名词写成属性，动词写成行为
封装对象代表什么，就得封装对应的数据，并提供数据对应的行为
private权限修饰符，修饰的成员只能在本类中访问
set / getpublic 修饰；setXxx(参数) 给成员变量赋值，可以校验；getXxx() 对外提供值，返回值类型与变量一致
一句话 类是设计图，new 出来的才是能干活的对象；数据归谁，处理这份数据的方法就写在谁那里，属性用 private 藏好，只留 set / get 这一条通道。

自测

1. 类和对象是什么关系？Phone 类里写了 String brand;，为什么不在这里直接写上"小米"？
类是一类事物共同特征的描述（设计图），对象是照着它造出来的具体实例。类不代表某一部真正的手机，在类里给 brand 赋值就等于说所有手机都是小米；应该创建对象之后，再给这个特定的对象赋值。
2. GirlFriend gf = new GirlFriend(); 之后什么都不赋值，直接打印 gf.name 和 gf.age，结果分别是什么？
null 和 0。成员变量有默认初始化值：String 是引用数据类型，默认 null；int 默认 0。
3. JavaBean 类和测试类有什么区别？成员方法和以前写的方法在写法上有什么不同？
JavaBean 类用来描述一类事物，里面写属性和行为，不写 main 方法；测试类带 main 方法，在里面创建 JavaBean 类的对象并赋值、调用。成员方法不加 static。
4. 需求"人关门"，关门的方法应该写在 Person 类还是 Door 类？依据是什么？
Door 类。封装的原则：对象代表什么，就得封装对应的数据，并提供数据对应的行为。门是开是关是门的状态数据，操作这个数据的开门、关门方法属于门；人只是调用了门的方法。
5. age 用 private 修饰之后，测试类里写 gf1.age = 18; 会怎样？想赋值该怎么办？
编译报错，private 修饰的成员只能在本类中访问，哪怕 18 是个合理的值也不行。要在 GirlFriend 类里提供 public 的 setAge(int a) 方法，测试类里写 gf1.setAge(18);；取值用 gf1.getAge()。
6. 按本篇的 setAge（18 到 50 才赋值），执行 gf1.setAge(18); gf1.setAge(60); System.out.println(gf1.getAge()); 控制台有哪些输出？
先打印"非法参数"（60 不在范围内，没有赋值），再打印 18：第一次赋的 18 还在，没有被覆盖。
