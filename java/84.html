第 1 节 · P84

改个名字，结果变成了 null

上一篇写的 GirlFriend 类：每个成员变量都加了 private，保证安全；又针对每个私有的成员变量提供了 get 和 set 方法，get 对外提供属性的值，set 用来赋值。但代码还有个小细节要改进：

public void setName(String n) { name = n; }

以前说过起名字要见名知意，这里的 n 不合规矩。对姓名来说，哪个单词最合适？就是 name。可如果把形参写成 name，就和上面的成员变量 private String name; 重复了：

public void setName(String name) { name = name; }

重名会不会有问题？改完运行测试类：gf1.setName("小诗诗"); 之后，gf1.getName() 打印出来的是 null。setName 没有赋值成功。为什么？

第 2 节 · P84

成员变量、局部变量与就近原则

先认识两个专业名词：

局部变量

定义在方法里面的变量。

成员变量

定义在方法的外面、类的里面的变量。

看这段代码。成员变量 age 没有赋值，是默认初始化值 0；method 方法里又定义了一个局部变量 age，赋值 10。成员变量和局部变量重名了，输出 age，是 10，还是成员变量的值？

public class GirlFriend { private int age; // 成员变量，默认 0 public void method() { int age = 10; // 局部变量 System.out.println(age); // ？ } }

这里涉及一个理论，叫就近原则：谁离我近，我就用谁。对输出语句来说，局部位置的 age 离它更近，所以打印的是 10。

如果就是想用成员位置的 age 呢？在前面加一个 this.：System.out.println(this.age); 它就不会用方法里的 age，而是直接使用成员位置的 age，打印 0。

还有一种情况：方法里那个局部变量不写了。此时局部位置没有 age，只能到成员位置去找。这种情况下前面的 this 可以省略不写，age 和 this.age 打印出来都是成员位置的 0。

动手：这个 age 到底是哪个 age

输出语句里写
两行代码的区别 System.out.println(age); 前面没有 this：先到局部位置找 age，有就用它；局部位置没有，再到成员位置去找。
System.out.println(this.age); 不会到局部位置找，直接使用成员位置的 age。
第 3 节 · P84

用 this 改写 set 方法

知道了就近原则，第 1 节的现象就能解释了。name = name; 里两个 name 前面都没有 this，都触发就近原则，都是形参那个局部变量：它就是自己赋值给了自己，和成员变量没有任何关系，成员变量还是原来的默认初始化值 null。

正确的写法：

public void setName(String name) { this.name = name; }
  • 等号右边的 name 前面没有 this，触发就近原则，是形参这个局部变量。它记录的是测试类调用 setName 时传过来的数据"小诗诗"；
  • 等号左边的 this.name 是成员位置的 name。

整句话就是：把传过来的"小诗诗"用局部变量 name 接收，再把它记录的值赋给成员位置的 name。age 和 gender 也照这样改：形参 a 改成 age、g 改成 gender，赋值的地方写 this.age = age;、this.gender = gender;。

public void setAge(int age) { if (age >= 18 && age <= 50) { this.age = age; } else { System.out.println("非法参数"); } } public void setGender(String gender) { this.gender = gender; }

动手：三种写法的 setName

这一节的小结 就近原则：谁离我近，我就用谁。this 的作用：区分成员变量和局部变量。至于 this 的本质、它在内存里是怎么回事，对象内存图那一篇会补上，现在掌握这个最基本的作用就可以了。
IDEA 其实提醒过你 写下 name = name; 时，IDEA 会给这一行标一个黄色警告：Variable 'name' is assigned to itself（变量赋值给了它自己）。它不是错误，编译运行都能过，所以容易被忽略。以后看到黄色波浪线，把鼠标移上去看一眼。
第 4 节 · P85

构造方法：创建对象的同时赋值

构造方法也叫构造器、构造函数，平时习惯叫构造方法。它的作用：在创建对象的时候，给成员变量进行初始化。"初始化"是专业说法，就是赋值的意思。以前创建对象时 new Student() 的小括号里什么都不写，其实调用的就是空参的构造方法。

格式：

修饰符 类名(参数) { 方法体; // 给成员变量赋值的代码 }

特点：

  • 方法名和类名完全一样，大小写也要一致；
  • 虽然叫方法，但没有返回值类型，连 void 都不能写；
  • 没有具体的返回值，大括号里不能写 return，一旦写了代码就要报错。

Student 类里有 name 和 age 两个属性（都是 private，各有 get / set），可以写两个构造：

public class Student { private String name; private int age; // 空参构造：一般空着，什么都不写 public Student() { } // 带全部参数的构造：给所有成员变量赋值 public Student(String name, int age) { this.name = name; this.age = age; } // get / set 方法略 }
  • 用空参构造创建对象：成员变量都是默认初始化值。还想赋值，只能再调用 set 方法，这是一套体系；
  • 用有参构造创建对象：创建的同时 name 和 age 就有值了，省得再去调用 set，代码更简单。
Student s = new Student("张三", 23); System.out.println(s.getName()); // 张三 System.out.println(s.getAge()); // 23

它是怎么赋值的？创建对象时，系统根据小括号里的参数去调用对应的构造。这里传了两个参数，一个字符串、一个整数，所以调用的是有参构造；"张三"和 23 被形参 name、age 接收，再赋给成员变量 name、age。之后用 get 方法就能拿到对象里的值。

还有两个细节：构造方法不能自己手动调用，是创建对象时由虚拟机自动调用的；而且每创建一次对象，构造方法就被调用一次，创建十个对象就调用十次。可以在空参构造里打印一句话来验证：

public Student() { System.out.println("看看我执行了吗？"); }

测试类里一写 Student s = new Student();，控制台就打印出了这句话，说明这行代码自动调用了空参构造。

第 5 节 · P85

构造方法的注意点

刚才有个疑问：以前的类里压根没写空参构造，new Student() 怎么没报错？

  1. 构造方法的定义：如果一个构造方法都没有写，系统会给出一个默认的无参构造方法（就是上面那个空着的 public Student() { }）。如果自己定义了构造方法，系统就不再提供默认的无参构造。比如类里只写了带参构造，测试类里再写 new Student() 就报错了：现在没有无参构造可调用。
  2. 构造方法的重载：带参构造和无参构造，两者方法名相同、参数不同，可以同时存在，这就是构造方法的重载。
  3. 推荐的使用方式：不管什么情况，无参构造和带全部参数的构造，两个都手动写上。不管用不用，都写。

有同学会想：有参构造这么方便，以后只写它不就行了？想得对，说明思考了，但两种构造都有应用场景。有时候创建对象时并不知道属性值，比如属性值是键盘录入来的：只能先用空参构造把对象创建出来，等用户录入了，再用 s.setName(...) 赋值。另外实际开发中一个项目是很多人一起写的，你只用到了有参构造，怎么保证别人用不到无参的呢？

构造方法不是用来"创建对象"的

很多资料和书会说"构造方法的作用就是创建对象"，这句话是不对的。真正创建对象的是 new 关键字。虚拟机创建对象有很多步骤，调用构造方法只是其中一步，这一步的作用是给成员变量进行初始化。创建对象到底有哪些步骤，对象内存图里会讲明白。

这一节的小结 作用：创建对象时由虚拟机自动调用，给成员变量进行初始化。两种：无参（空参）构造，成员变量都采用默认值；有参构造，创建对象的同时给属性赋值。建议：任何情况下都自己写上空参构造和带全部参数的构造。
更正：return 和 void 的两处说法 ① "不能写 return"说得太宽了。构造方法里不能写的是带数据的 return 值;，JDK 8 的报错是 错误: 不兼容的类型: 意外的返回值。单独一句 return;（只表示方法到此结束）是允许的，实际跑过：public Student() { System.out.println("看看我执行了吗？"); return; } 能正常编译运行。幻灯片上的原话多半是"没有具体的返回值（不能由 return 带回结果数据）"，课上口头说简略了。

② "连 void 都不能写"：写了并不报错，后果更隐蔽。public void Student() { } 能通过编译，但它不再是构造方法，而是一个恰好和类同名的普通成员方法。于是这个类"一个构造方法都没写"，系统照样送一个默认的无参构造；你写在里面的初始化代码，new 的时候一行都不会执行。

③ 小结里"任何类默认自带无参构造，写不写都是有的"这句也说过头了，准确的规则就是上面的第 1 条：只有一个构造都没写的时候才有；写了任何一个构造，默认的就没有了。课上紧接着的下一句也是这么说的。
第 6 节 · P86

标准的 JavaBean

到这里，面向对象的基本语法学完了：封装里的 private、区分重名变量的 this、创建对象时赋值的构造方法……新概念很多，感觉好像听懂了又有点懵，这是正常的，后面会不断用到，慢慢沉淀。现在把它们合起来：一个标准的 JavaBean 到底怎么写？有四条规矩：

  1. 类名见名知意，驼峰命名。描述老师叫 Teacher，描述学生叫 Student。
  2. 成员变量全部用 private 修饰，保证数据的安全。
  3. 构造方法至少提供两个：空参构造、带全部参数的构造。
  4. 成员方法：每一个私有的成员变量都提供对应的 set 和 get。如果还有其他行为（学生的学习、吃饭，老师的上课），题目有需求就写上，没有就不用写。

练习：用户类

需求：某网站的用户注册页面上要填用户名、密码、邮箱、性别、年龄。写一个标准的 JavaBean 来描述用户。

分析：描述用户，类名叫 User；属性就是页面上那五项：用户名、密码、邮箱是字符串；性别只有男、女两个，可以用 char，也可以用 String；年龄是整数。构造写空参和全参两个；五个成员变量，get / set 一共要写十个。

老师的"君子约定"：下一节会教快捷键和一键生成的插件，但刚开始练习请先不要用，自己一个一个手打出来。标准 JavaBean 里细节很多，快捷键用熟了，这些细节就顾不到了；等能从头到尾写顺了，再用快捷键生成。

public class User { // 属性 private String username; private String password; private String email; private String gender; private int age; // 空参 public User() { } // 带全部参数的构造 public User(String username, String password, String email, String gender, int age) { this.username = username; this.password = password; this.email = email; this.gender = gender; this.age = age; } // get 和 set 方法 public void setUsername(String username) { this.username = username; } public String getUsername() { return username; } // password、email、gender、age 照同样的套路各写一对，一共十个方法 }

gender 的类型，字幕里只说了"可以写 char，也可以写 String"，听不出最后敲的是哪个，这里用 String。

易错点：全参构造的形参是把上面的属性复制粘贴下来的，大括号里五行赋值也是复制一行再改，改漏了就会出现 this.password = username; 这种把一个值赋给了别的属性的错误；每一行都别忘了 this.，否则就是自己赋值给自己。写的时候会觉得有点痛苦，但它是固定的套路，耐下性子写熟。

动手：按四条规矩生成一个 JavaBean

先自己在纸上或 IDEA 里写一遍，再用它核对。属性可以增删改，换成你自己想描述的事物。

第 7 节 · P86

快捷键与插件：一秒生成

写熟了之后会发现，这样的代码写起来简直是体力活。IDEA 提供了快捷生成的方式，快捷键是 Alt + Insert（有的电脑按了没反应，就多按一个 Fn：Alt + Fn + Insert）。

  • 生成空参构造：Alt + Insert，选第一个 构造函数（就是构造方法）。弹窗默认选中了第一个属性，这时不能直接点“确定”，否则生成的是只带这一个参数的构造；要点下面的 无选择，表示什么属性都不选；
  • 生成全参构造：Alt + Insert → 构造函数，按住 Shift 再点最后一个属性把所有属性全选（或者按 Ctrl + A），点“确定”；
  • 生成 get / set：Alt + Insert，注意选的不是 Getter、也不是 Setter，而是第四个 Getter 和 Setter，Ctrl + A 全选，点“确定”。

这还不是最终方案。再分享一个插件 PTG，可以一秒生成标准 JavaBean。安装：电脑连上外网，点 文件 → 设置… → 插件，中间有两个选项卡，Marketplace 是下载页面，“已安装”是已经安装的插件；在 Marketplace 的搜索框里输入 PTG，回车，点“安装”，等进度条走完，点“确定”。

使用：成员变量写好之后，在代码空白处点右键，选 Ptg To JavaBean。空参构造、全参构造、所有的 get / set 都自动生成了，连注释都有。它还会多生成一个 toString 方法，这个暂时还没学，先删掉就好。

Mac 上的对应操作
  • “生成”菜单：⌘ + N，或者 Control + Enter。Mac 键盘没有 Insert 键；也可以用菜单 代码 → 生成…；
  • 弹窗里全选：⌘ + A；“无选择”按钮和 Shift 连选的用法相同；
  • 插件界面：菜单 IntelliJ IDEA → 设置…（⌘ + ,）→ 插件。新一些的 IDEA 装完插件不一定要重启，点“确定”或“应用”即可；
  • 右键菜单里的 Ptg To JavaBean 位置不变。
第 8 节

小结

局部 / 成员变量方法里面的是局部变量；类里面、方法外面的是成员变量
就近原则谁离我近就用谁：先找局部位置，没有再找成员位置
this.变量直接用成员位置的变量；用来区分重名的成员变量和局部变量
set 方法形参和成员变量同名，写 this.name = name;
构造方法方法名与类名相同，没有返回值类型（不写 void）；创建对象时由虚拟机自动调用，给成员变量初始化
空参 / 有参一个构造都没写，系统送一个空参的；写了任何构造就不送了。可以重载；建议空参、全参都写上
谁创建对象new 关键字。调用构造方法只是创建对象的其中一步
标准 JavaBean类名见名知意；成员变量全部 private；空参 + 全参构造；每个成员变量一对 set / get；需要的其他行为
快捷生成Alt + Insert（Mac：⌘N）→ 构造函数 / Getter 和 Setter；PTG 插件右键 Ptg To JavaBean
一句话 没有 this 就近找，有 this 找成员；构造方法在 new 的时候把属性赋好；private 属性、空参全参两个构造、每个属性一对 set / get，凑齐了就是标准 JavaBean。

自测

1. public void setName(String name) { name = name; }，调用 setName("小诗诗") 后 getName() 返回什么？为什么？怎么改？
返回 null。两个 name 都没有 this，按就近原则都是形参，等于形参自己赋值给自己，成员变量没被动过，还是默认值 null。改成 this.name = name;。
2. 成员变量 int age;（没赋值），方法里 int age = 10;，接着打印 age 和 this.age，分别是多少？把方法里的那行定义删掉呢？
10 和 0：age 就近用局部变量，this.age 直接用成员变量（默认值 0）。删掉局部变量后，age 在局部位置找不到，到成员位置找，两个都是 0，此时 this 可以省略。
3. 构造方法在写法上和普通的成员方法有哪些不同？它什么时候执行？
方法名必须和类名完全一样；没有返回值类型，连 void 都不写；不能用 return 带回数据。它不由我们手动调用，而是每次 new 创建对象时由虚拟机自动调用一次。
4. Student 类里只写了 public Student(String name, int age) { ... }。测试类里 new Student() 能通过编译吗？
不能。自己定义了构造方法，系统就不再提供默认的无参构造，现在类里没有无参构造可调用。所以建议空参和全参两个构造都手动写上。
5. "构造方法是用来创建对象的"，这句话对吗？
不对。创建对象的是 new 关键字；虚拟机创建对象有很多步，调用构造方法只是其中一步，它的作用是给成员变量进行初始化。
6. 一个标准的 JavaBean 有 4 个成员变量，按规矩它至少有几个构造方法、几个成员方法？
2 个构造方法（空参、带全部 4 个参数的）；8 个成员方法（每个成员变量一个 set、一个 get）。有其他行为的需求再另外加。
