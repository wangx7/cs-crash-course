How Computers Store Data

第 1 节 · P22

计算机里只有三类数据

计算机里的数据一般分三类：文本、图片、声音。有人说还有视频，其实视频就是很多图片和声音的组合。文本又包括数字、字母和汉字。

先看结论：在计算机中，任意数据都是以二进制的形式来存储的。"任意"就是不管文本、图片还是声音，都一样。零基础的同学看到这句话，心里一般会冒出两个问题：

  1. 什么是二进制？
  2. 计算机为什么要用二进制，不用别的？

下面一个一个解释。每种数据的存储方式里都藏着一些新知识点，认真听。

第 2 节 · P22

二进制，以及八进制、十六进制

直接说二进制容易懵，先从熟悉的十进制说起。十进制由 0~9 这十个数字组成，规则是逢十进一，借一当十（小学二年级的口诀）。

  • 1 + 1 = 2：没超过 10，不用进位。
  • 9 + 1：个位满 10，往前进一，个位变 0；十位没有数，进上来的 1 落下来，得 10。
  • 99 + 1：别直接说 100，看过程：个位 9+1=10，个位写 0 进 1；十位 9+进上来的 1=10，又写 0 进 1；百位只有进上来的 1。合起来 100。
  • 15 − 9：个位 5 减 9 不够，向十位借一当十，15−9=6；十位的 1 被借走了，没东西落下来，结果 6。

二进制也类似：只由 0 和 1 组成，规则是逢二进一，借一当二。

  • 十进制 0 → 二进制 0；1 → 1。
  • 十进制 2：二进制里 1+1 满二了，进一，原位写 0，结果是 10。所以有个梗："1+1 什么时候不等于 2？"在二进制里，它等于 10。
  • 十进制 3：在 10 的基础上加 1，没满二不用进位，11。
  • 十进制 4：11 + 1，最右边 1+1=2，写 0 进 1；进上来的 1 和左边的 1 相加又是 2，再写 0 进 1。结果 100。

常见的进制除了十进制和二进制，还有：

  • 八进制：由 0~7 组成，逢八进一。
  • 十六进制：逢十六进一。0~9 只有 10 个数字不够用，于是用字母 a~f 表示 10~15：a=10，b=11，c=12，d=13，e=14，f=15。

这么多进制会出问题吗？会：代码里写一个 1，怎么知道它是几进制？所以 Java 做了规定（JDK 7 起支持这些写法，大小写都可以）：

二进制以 0b 开头0b101
十进制默认，不加前缀101
八进制以 0 开头0101
十六进制以 0x 开头0x101

考考你：这些是几进制？

补充：0b 写法的版本和一个坑 严格地说，0 开头的八进制和 0x 开头的十六进制从 Java 一开始就有，JDK 7 新增的是 0b 二进制写法（还有可以在数字里加下划线，比如 1_000_000）。
坑在八进制：平时我们觉得 017 和 17 是一回事，但在 Java 里 017 是八进制，等于十进制 15。写代码时别随手在数字前面补 0。
第 3 节 · P22

计算机为什么用二进制

用二进制存数据，看起来很反人类，其实有个小故事。上个世纪的计算机用打孔纸带：纸带就是写好的程序，打了孔是 0，没打孔是 1，想让计算机执行，就把纸带交给它。视频放了一段 1958 年的电脑录像：把纸带送进机器，打印出来的纸就是程序运行的结果。

编程得先准备很长的纸带，用打孔器一个个打。手一抖打错了怎么办？当年的程序员还有两件神器：胶水和改正纸，多打的孔就糊上；错得太多，只能重新打。

纸带上只有两种状态：有孔和没孔，所以计算机就用二进制来表示。如果用十进制，就得在纸带上做出 10 种完全不同的状态。打 1/2、1/3、1/4 个孔？不行：孔本来就很小，当时的机器也没那么精密，只能区分有孔和没孔。

这个习惯一直延续到今天。现在计算机里是电路板，常用 5 伏的电路，规定大于 3.3 伏为 1，小于 3.3 伏为 0。所以计算机用二进制，就是因为只要两种状态就能表示：以前是有孔、没孔，现在是高电压、低电压。用十进制要 10 种完全不同的状态，太麻烦了。

更正：电压的"门限" 电路判断 0 和 1 不是靠一条线，而是两个区间，中间留一段"缓冲带"防止误判。比如经典的 5 伏 TTL 电路：输入高于约 2 伏算 1，低于约 0.8 伏算 0。3.3 伏本身是现在很常见的一种芯片工作电压，不是 5 伏电路的分界线。不过视频想说的道理完全对：只区分"高"和"低"两种状态，最简单、最不容易出错。
打孔纸带的约定也是各家不同，比较常见的是有孔表示 1。这些细节不影响结论。想看 0 和 1 怎样用电路做加法，可以看本站的 速成课第 3 集"布尔逻辑与逻辑门"。
第 4 节 · P22

进制之间的转换

进制之间当然可以互相转换，分两种：任意进制转十进制，十进制转任意进制。

任意进制 → 十进制：系数 × 基数的权次幂，再相加

  • 系数：每一位上的数字；
  • 基数：当前是几进制，基数就是几；
  • 权：从右往左依次是 0、1、2、3……

三个例子：

  • 二进制 101：1×2² + 0×2¹ + 1×2⁰ = 4 + 0 + 1 = 5。
  • 八进制 101：1×8² + 0×8¹ + 1×8⁰ = 64 + 0 + 1 = 65。（任何数的 0 次幂都是 1。）
  • 十六进制 abc：10×16² + 11×16¹ + 12×16⁰ = 2560 + 176 + 12 = 2748。

二进制转十进制还有个快速方法：8421 快速转换法。二进制每一位上的 1 都代表一个固定的值，从右往左是 1、2、4、8、16、32、64、128（每次翻倍，因为逢二进一）。把是 1 的那些位代表的数加起来就行。比如 1101：8 + 4 + 1 = 13（是 0 的位不用管）。上面计数器里每盏灯下面的数字就是这张表。

十进制 → 任意进制：除基取余法

不断除以基数（转几进制就除几），记下余数，一直除到商为 0，再把余数倒着拼起来。

  • 11 转二进制：11÷2=5 余 1，5÷2=2 余 1，2÷2=1 余 0，1÷2=0 余 1。倒着拼：1011。
  • 7 转二进制：7÷2=3 余 1，3÷2=1 余 1，1÷2=0 余 1。倒着拼：111。
  • 转八进制，就把除 2 换成除 8。

有些资料除到商为 1 就停了，再把最后的商 1 和余数一起倒着拼，结果一样，只是偷了个懒。正统的做法是除到商为 0。

数字就是这样存的：转成二进制再存。比如 99 转成二进制是 1100011，课件里写成 01100011，前面补了个 0（为什么补，后面会讲）。这些转换其实不需要口算，讲它是为了长见识，真要算就用电脑的计算器：左上角三道杠 → 程序员模式，有 HEX、DEC、OCT、BIN 四种进制。选二进制时只有 0 和 1 能按，选八进制时 8 和 9 按不了，选十六进制时 A~F 也能按了。在十进制下输入 99，点一下二进制，就是 1100011。

为什么补成 8 位 计算机存储的基本单位是字节（byte），1 字节 = 8 个二进制位（bit）。99 只需要 7 位，存进一个字节时左边空着的那位就补 0，所以写成 01100011。8 位最大能表示 11111111 = 255，这个数第 6 节还会出现。
Mac 自带的"计算器"也有程序员模式：菜单"显示 → 程序员"，或按 ⌘+3。

第 5 节 · P22

文本：字母和汉字靠查码表

弄懂二进制，剩下的就 so easy 了。存一个小写字母 a，它和二进制是怎么对应上的？靠一张码表：ASCII（American Standard Code for Information Interchange，美国信息交换标准码，读作"阿斯克"）。在 ASCII 码表里，每个字母都和一个唯一的数字对应，比如小写 a 对应十进制 97。存字母时就查码表，找到对应的数字，再转成二进制存进计算机。

可 ASCII 码表里没有汉字：它是外国人做的，没考虑中文。没有码表，汉字就没法存进计算机。为了解决这个问题，中国自己推出了码表：

GB23121981 年 5 月 1 日发布。收录 7000 多个图形字符，其中 6000 多个汉字，只有简体。从这时起汉字才能在计算机里存储和运行
BIG51984 年台湾地区推出，收录的是繁体字。一个国家出现了两张码表，不统一
GBK视频说是2000 年 3 月 17 日推出，为了统一成一张码表。收录 2 万多个汉字，包括繁体字，还有日文、韩文。目前简体中文 Windows 默认使用的码表。不足是一些欧洲、非洲国家的文字还没有
Unicode由美国国家标准学会提出，叫"万国码"。"万"是虚词，表示包含了世界上大多数国家的文字

小结一下：数字直接转成二进制存；字母和汉字先查对应的码表，找到数字，再转成二进制存。码表不用自己下载，每个操作系统都内置了。

更正与补充：几张码表的时间 GBK 是 1995 年发布的（微软 Windows 95 简体中文版开始用它）；2000 年 3 月 17 日发布的是更大的国家标准 GB18030，后来又在 2005 年、2022 年两次扩充。ASCII 是 1963 年由美国标准协会（美国国家标准学会的前身）制定的，只有 128 个字符（0~127），可能视频把它和 Unicode 记混了。Unicode 由统一码联盟（Unicode Consortium）在 1991 年推出第一版，现在已经收录了 15 万多个字符，连表情符号都在里面。
再细一点："码表"其实分两层：字符集规定"哪个字对应哪个编号"（比如 Unicode 里"中"是 4E2D），编码方式规定"编号怎么变成字节"。Unicode 最常用的编码方式是 UTF-8：英文字母 1 个字节（和 ASCII 完全一样），常用汉字 3 个字节。GBK 里汉字是 2 个字节。上面的演示可以对比。同一串字节用错了码表来读，就是乱码，P6–11 那篇的编码演示讲过这件事。现在网页、Mac、Linux 和 JDK 18 以后的 Java 默认都是 UTF-8。
第 6 节 · P22

图片：像素和三原色

图片分三种：黑白图、灰度图和平时看得最多的彩色图。讲图片的存储，先要知道显示器的三个概念：分辨率、像素、三原色。

分辨率：常听说的 2K 屏、4K 屏，说的是最大分辨率。最常见的是 2K 屏里的 1920×1080 和 4K 屏里的 3840×2160。

像素：1920×1080 的意思是，显示器宽有 1920 个小方格，高有 1080 个小方格，整个屏幕由这么多方形小格子组成，每个小格子叫一个像素。画一张小图再放大，边缘会有锯齿，就是因为屏幕由方格组成。以后写软件设置窗口大小，比如宽 514 像素、高 595 像素，大概占屏幕宽的 1/4、高的 1/2。后面的拼图游戏会用到像素，到时候说"宽高 100 像素"，你得知道大概多大。

  • 黑白图：给每个像素涂颜色，白色是 1，黑色是 0。视频画了个笑脸，两个黑点是眼睛，一道黑色弯钩是嘴。
  • 灰度图：有一张灰度表，0 是纯黑，255 是纯白，中间是不同层次的灰。视频画了个 8：没有笔画的地方是 0，笔画上是不同程度的灰，比如 4、62、146、182……

动手：像素就是一格一格的数字

彩色图怎么记录颜色？小学美术课学过三原色红、黄、蓝，叫美学三原色。计算机里也有三原色：红、绿、蓝，叫光学三原色。把屏幕放大看，每个像素内部就是红、绿、蓝三个小点组成的。给三种颜色设置不同的值，值越大颜色越浓，越小越淡。比如红 43、绿 123、蓝 194，就像用 43 份红颜料、123 份绿颜料、194 份蓝颜料一搅和，得到一种说不出名字但挺好看的蓝。

  • 每种颜色的取值范围是 0~255（包含 0 和 255）。255 0 0 是纯红，0 255 0 纯绿，0 0 255 纯蓝。
  • 也可以用十六进制写：十进制 255 正好是 FF，所以每种颜色是 00~FF。
  • 取三种颜色英文的首字母（Red、Green、Blue），叫 RGB。

动手：调一个颜色

彩色图片里，每个像素就是搭配了不同的三原色。手机里那些舍不得删的照片，其实就是一组又一组数字搭配出来的颜色。从计算机的角度看，两张照片没什么区别，都只是数字。

一张照片有多大 RGB 每种颜色 0~255，正好用 1 个字节，所以一个彩色像素占 3 字节。一张 1920×1080 的图，如果原样存，就是 1920×1080×3 ≈ 622 万字节，约 6 MB。实际的 JPG、PNG 文件小得多，是因为做了压缩：PNG 找重复的规律来省空间，一点不丢；JPG 会扔掉一些人眼不太看得出的细节，换来更小的体积。
第 7 节 · P22

声音：对波形采样

声音的存储涉及波形图。波形上的每个点都可以对应一个数字，比如 100、101、110、111……存声音时会对声波进行采样，每个采样点记一个数字。

听音乐时，"氪金"的音质好，没氪金的朋友听的是"全损音质"，技术上怎么做到的？氪了金，采样点多，记录的数据多，播放时能最大程度地还原；采样点少，还原时只能把这些点连起来，像波峰上冒尖的地方，因为没有采样点，就还原不出来了。

动手：采样点越少，还原得越差

红线是原本的声音，黑点是采样点，黑线是用这些点还原出来的声音。拖动滑块改变采样点的数量。

采样点：
真实的数字和"音质" CD 的标准是每秒采样 44100 次（44.1 kHz），每个采样点用 16 位二进制记录（能分出 65536 个高低层次），左右两个声道。这样一分钟的音乐约 10 MB。平时听的 MP3、AAC 文件小得多，是像 JPG 一样做了有损压缩，扔掉人耳不太听得出的部分。音乐 App 里"标准""高品质""无损"的区别，主要就是压缩扔掉了多少（码率高低），而不只是采样点多少。
第 8 节

小结

结论计算机里任意数据都以二进制存储。因为二进制只需要两种状态（有孔/没孔、高电压/低电压）
进制二进制 0、1，逢二进一；八进制 0~7；十六进制 0~9 加 a~f。Java 前缀：0b 二进制、无前缀十进制、0 八进制、0x 十六进制
转换任意→十进制：系数×基数权再相加（二进制可用 8421）；十进制→任意：除基取余，除到商为 0，余数倒着拼
文本数字直接转二进制；字母、汉字查码表（ASCII、GB2312、BIG5、GBK、Unicode）得到数字再转二进制
图片由像素组成；黑白 0/1，灰度 0~255，彩色每个像素是 RGB 三原色，各 0~255（00~FF）
声音对波形采样，每个采样点记一个数字再转二进制；采样点越多越接近原声
一句话 文字查码表变成数字，图片拆成像素的 RGB 数字，声音采样成一串数字。所有数字最后都写成 0 和 1。

自测

1. 二进制 1101 是十进制几？十进制 11 是二进制多少？
1101 用 8421：8+4+1 = 13。11 除基取余：11÷2=5…1，5÷2=2…1，2÷2=1…0，1÷2=0…1，余数倒着拼：1011。
2. Java 代码里 System.out.println(017); 和 System.out.println(0x1F); 分别打印什么？0b102 呢？
017 是八进制，1×8+7 = 15；0x1F 是十六进制，1×16+15 = 31；0b102 语法错误，二进制里没有 2。
3. 为什么计算机用二进制而不是十进制？
二进制只需要两种状态：以前纸带上有孔、没孔，现在电路里高电压、低电压。十进制需要 10 种能可靠区分的状态，机器做不到或者太容易出错。
4. 字母 a 是怎么存进计算机的？汉字呢？
查 ASCII 码表，a 对应 97，再把 97 转成二进制 01100001 存起来。ASCII 里没有汉字，要查 GBK、Unicode 这类包含中文的码表得到数字，再转二进制。
5. RGB(255, 255, 0) 是什么颜色？用十六进制怎么写？
红和绿开满、不要蓝，是黄色（光的三原色里，红 + 绿 = 黄）。十六进制写作 FF FF 00，网页里常写成 #FFFF00。
