第 1 节 · P68

什么是方法的重载

先看一个小练习。定义方法求两个整数的和，方法名可以叫 sum2，两个形参；求三个整数的和，叫 sum3；求四个整数的和，叫 sum4。到这里有没有一丢丢不爽？如果没有，再加个需求：定义方法求两个小数的和。代码很简单，可方法名怎么取？会的单词在上面都用完了。就算查了字典，知道可以叫 sumTwoDecimals，也好难受。

这么多方法名字都不一样，定义的时候痛苦，使用的时候也痛苦：每次调用都得先查一查方法叫什么。所以 Java 做了一个规定：这些功能相同的方法可以起同一个名字，都叫 sum，但方法的形参不能一样。这就叫方法的重载。

不重载：一个功能四个名字

int sum2(int a, int b)
int sum3(int a, int b, int c)
int sum4(int a, int b, int c, int d)
double sumTwoDecimals(double a, double b)
→

重载：都叫 sum，靠参数区分

int sum(int a, int b)
int sum(int a, int b, int c)
int sum(int a, int b, int c, int d)
double sum(double a, double b)

完整的概念：在同一个类中，定义了多个同名的方法，这些同名的方法具有相同的功能，每个方法具有不同的参数类型或参数个数，这些同名的方法就构成了重载关系。精华版：

简单记 同一个类中，方法名相同、参数不同的方法，就是重载。与返回值无关。

判断两个方法是否构成重载，只看两点：① 是不是同一个类里名字相同的方法；② 它们的形参是不是不一样。不看返回值。其中"参数不同"有三种情况，有一个不同就行：

  • 个数不同：一个方法两个参数，另一个三个参数；
  • 类型不同：一个是 int 类型，另一个是 double 类型；
  • 顺序不同：下一节单独看例子。

虚拟机怎么区分这些同名的方法？看一个案例：同一个类里有 sum(int a, int b) 和 sum(int a, int b, int c)，方法名相同、参数个数不同，构成重载。调用时 Java 虚拟机会根据不同的参数来区分：写 sum(10, 20)，传了两个实参，调用的就是两个形参的那个；写 sum(10, 20, 30)，就是三个形参的那个。这又印证了之前学的：调用方法时，实参和形参要一一对应。

"区分"这件事发生在编译时 视频说"虚拟机根据参数来区分"，意思没错，但更准确地说，选哪个方法是编译器（javac）在编译时就定下来的：它看调用处实参的个数和类型，挑出匹配的那个方法，把结果写进 class 文件，运行时虚拟机照着执行。所以 IDEA 不用运行就能知道你调的是哪一个（没被用到的方法名显示成灰色，下面第 3 节会用到这个特性）。
第 2 节 · P68

判断是否构成重载

关于重载要掌握两个能力：一是能判断几个方法是否构成重载关系，二是能自己定义重载的方法。先练第一个。下面五组代码，每组想五秒钟（老师说没有弹幕的视频是不完整的，答案请打在弹幕里）：

public class MethodDemo { public static void fn(int a) { … } public static int fn(int a) { … } }
不构成。同一个类、方法名相同，但形参一模一样，只有返回值不同。重载不看返回值。
public class MethodDemo { public static float fn(int a) { … } public static int fn(int a, int b) { … } }
构成。同一个类、方法名相同；上面一个形参，下面两个形参，个数不同。
public class MethodDemo01 { public static void fn(int a) { … } } public class MethodDemo02 { public static int fn(double a) { … } }
不构成。两个 fn 不在同一个类里，不在一个类里的方法不构成重载关系。
public class MethodDemo { public static void fn(int a) { … } public static void fn(double a) { … } }
构成。同一个类、方法名相同；一个是 int，一个是 double，类型不同。
public class MethodDemo { public static void fn(int a, double b) { … } public static void fn(double a, int b) { … } }
构成。个数一样、类型也一样，但顺序不一样：上面是 int、double，下面是 double、int。这就叫顺序不同。

五组代码在幻灯片上，字幕里没有念出来，这里按老师对每一题的讲解还原，返回值类型是随手填的。

最后一组要多说一句：类型的顺序不同可以构成重载，但不建议。从实际开发的角度想，上面的方法和下面的方法有什么不一样？调用时把实参前后颠倒一下不就行了。所以以后几乎不会用这种方式重载。

顺序不同的重载还会坑到自己 有了 fn(int, double) 和 fn(double, int)，写 fn(1, 2) 会怎样？两个实参都是 int：把第二个提升成 double 能匹配上面那个，把第一个提升成 double 能匹配下面那个，两个都行、谁也不比谁更合适，编译器直接报错 对 fn 的引用不明确（reference to fn is ambiguous）。必须写成 fn(1, 2.0) 或 fn(1.0, 2) 才能编译。这是"不建议"的另一个实在的理由。
第 3 节 · P68

自己定义重载方法

需求：使用方法重载的思想，设计比较两个整数是否相同的方法，要兼容全部的整数类型（byte、short、int、long）。可以先暂停自己写一写，再对照。

要比较 byte、short、int、long，就设计四个方法，名字都叫 compare，形参分别是两个 byte、两个 short、两个 int、两个 long。写完第一个，复制三份改类型就行：

public static void compare(byte b1, byte b2) { System.out.println(b1 == b2); } public static void compare(short s1, short s2) { System.out.println(s1 == s2); } public static void compare(int i1, int i2) { System.out.println(i1 == i2); } public static void compare(long n1, long n2) { // 不叫 l1：小写 l 和数字 1 长得太像 System.out.println(n1 == n2); }

把相同功能的方法名写成一样的，好处有两个：定义方法时不用想那么多单词；调用方法时也不麻烦，相同功能的只要记一个方法名。

怎么调用？在 main 里写 compare(10, 20);，调用的是 int 的那个。怎么知道？IDEA 有个特性：变量或方法没被用到，名字就是灰色的，此时另外三个 compare 都是灰的。还可以在四个方法里分别加一句打印 byte、short、int、long 来验证，运行后第一行打印的是 int。

想调用别的怎么办？只要保证实参和形参一一对应：

  • 整数默认是 int 类型，所以不能直接写 10 和 20；可以强转：compare((byte) 10, (byte) 20);，这时 byte 的方法名亮了，其余三个变灰；
  • 以后用得更多的方式：先定义两个 byte 类型的变量 byte b1 = 10; byte b2 = 20;，调用时传变量 compare(b1, b2);。

想调用 short、long 的也是同样的道理。

练习：遍历数组

方法该掌握的知识点学完了，接下来做四个练习：数组的遍历、求数组的最大值、判断是否存在、复制数组。每一题都在前一题的基础上加了难度，要一题一题做，不要跳。

需求：设计一个方法用于数组遍历，要求遍历的结果在一行上，例如：[11, 22, 33, 44, 55]。

先在 main 里定义数组 int[] arr = {11, 22, 33, 44, 55};。以前是在 main 里直接遍历，现在专门定义一个方法，以后还想遍历就不用再写，直接调方法。定义方法，问自己三个问题：

  • 我要干嘛？遍历数组。
  • 需要什么才能完成？你得把数组给我，不给我遍历个毛。所以形参是一个 int 类型的数组。
  • 调用处是否需要继续使用结果？题目没要求返回，说直接打印就行，所以不需要返回值。

不太会写没关系，想到多少先写多少，再根据打印结果去改。先写最朴素的 arr.fori + println(arr[i])，调用 printArr(arr);：遍历是遍历了，可每个数占一行，和题目要求不一样。

正式改写之前，重新认识一下输出语句：

System.out.println("abc");先打印 abc，再换行
System.out.print("abc");只打印 abc，不换行。下面再打印 bcd，会接在 abc 后面。ln 就表示换行
System.out.println();不打印任何数据，只做换行处理

于是一步步改：① 把 ln 删掉，数据后面拼接 ", "：在同一行了，可是开头没有左括号、结尾没有右括号，55 后面还多了一个逗号空格；② 循环开始前打印 [，循环结束后打印 ]（用 println，顺便换行）；③ 循环里做判断：是最大索引 arr.length - 1 的数据就只打印数据，否则才拼上逗号空格。

public static void main(String[] args) { int[] arr = {11, 22, 33, 44, 55}; printArr(arr); // [11, 22, 33, 44, 55] } public static void printArr(int[] arr) { System.out.print("["); for (int i = 0; i < arr.length; i++) { if (i == arr.length - 1) { System.out.print(arr[i]); // 最后一个：只打印数据 } else { System.out.print(arr[i] + ", "); // 前面的：数据 + 逗号空格 } } System.out.println("]"); }

运行结果和题目要求相比：不能说有点类似，只能说完全一样。

动手：一版一版改出来

数组
JDK 里有现成的 这个格式不是随便定的：java.util.Arrays.toString(arr) 返回的字符串正是 [11, 22, 33, 44, 55]，写 System.out.println(Arrays.toString(arr)); 一行就能打印（课程后面讲 Arrays 工具类时会正式介绍）。先自己写一遍 printArr，以后就知道它里面大概干了什么。试试把上面的数组清空：④ 打印的是 []，和 Arrays.toString 对空数组的结果也一致。

练习：求数组的最大值

需求：设计一个方法求数组的最大值，并将最大值返回。

三个问题：我要干嘛？求最大值。需要什么？你要把数组给我，没有数组我求个毛。要不要返回？题目明确说了返回。所以返回值类型是 int，形参是数组：

public static void main(String[] args) { int[] arr = {1, 5, 7, 3, 8, 10}; int max = getMax(arr); // 写完 getMax(arr) 按 Ctrl+Alt+V 自动生成左边 System.out.println(max); // 10 } public static int getMax(int[] arr) { int max = arr[0]; // 参照物：不能写 0，必须是数组里的数据 for (int i = 1; i < arr.length; i++) { // 从 1 开始，少循环一次 if (arr[i] > max) { max = arr[i]; } } return max; }

方法体就是 数组那章的擂台法，两个细节再强调一遍：max 的初始值不能写 0（数组里全是负数就错了），要用数组里的数据，一般用 0 索引；循环从 0 开始也没错，只是第一次是自己跟自己比，多此一举，从 1 开始能少循环一次。

数组里的数据视频说"可以随便写"，字幕里只知道运行结果是 10，这里的 {1, 5, 7, 3, 8, 10} 是随手填的。

练习：判断是否存在

需求：定义一个方法，判断数组中的某一个数是否存在，将结果返回给调用处。

三个问题：我要干嘛？判断数字在数组中是否存在。需要什么？数组，还有要查的那个数字，所以两个形参。要不要返回？题目明确要返回；返回什么？把查询的结果告诉调用处：true 表示存在，false 表示不存在，所以返回值类型是 boolean。方法名叫 contains（是否包含）。

方法体：遍历数组，拿到每个数据和要查找的数字比，找到一样的，直接 return true。那什么时候 return false？有人说简单，else 里 return false 呗。推导一下对不对：数组是 {1, 5, 8, 12, 56, 89, 34, 67}，查 89。第一次循环拿到 1，和 89 不一样，判断为假，直接 return false，说不存在。这肯定不对。

什么时候才能断定 89 不存在？数组里所有的数据全部比较完毕之后。所以 return false 不能写在 if 下面，要写在循环的外面：循环结束，表示所有数据都比过了，还没有一样的，才返回 false。

public static void main(String[] args) { int[] arr = {1, 5, 8, 12, 56, 89, 34, 67}; boolean flag = contains(arr, 89); System.out.println(flag); // true；换成 189 就是 false } public static boolean contains(int[] arr, int number) { for (int i = 0; i < arr.length; i++) { if (arr[i] == number) { return true; // 找到了：方法直接结束 } } return false; // 全部比完还没找到，才能断定不存在 }

还有个小问题：找到之后为什么不写 break？借机回顾一下 return 和 break 的区别：

return和循环没什么关系，和方法有关：① 结束方法；② 返回结果。方法执行到 return，整个方法全部结束，里面的循环也随之结束
break和方法没什么关系，和循环、switch 有关：结束循环或者 switch

打个比方（只是假设）：有一天地球寿命到了，爆炸了，地球上有个人才 20 岁，寿命还没到，他还能活吗？地球都炸了还活什么。整个方法都结束了，方法里其他的代码也随之结束。所以这里写 return 表示：找到了，方法直接结束，把 true 返回给调用者，后面的代码不再执行；如果写的是 break，方法没结束，只是把 for 循环结束，跳到循环下面接着走。

第 7 节 · P70

练习：拷贝数组

需求：定义一个方法 copyOfRange(int[] arr, int from, int to)，功能：将数组 arr 中从索引 from（包含 from）开始，到索引 to 结束（不包含 to）的元素复制到新数组中，将新数组返回。

这题比前面难一点。先别忙着写代码，先分析。很多同学看到稍微复杂的题就没思路，就是因为之前学习时忽略了分析的过程。以后工作中也一样，分析占的时间往往比写代码更多。

假设原始数组长度是 9，存着 1~9，索引 0~8。现在要把 3 索引到 7 索引之间的数据拷贝到新数组：from 是 3，to 是 7，不包含 to，所以真正要拿的是 3、4、5、6 索引上的数据：4、5、6、7。新数组的长度应该是 4，正好是 7 - 3。

开始写。方法名、形参题目都给了，返回值类型暂时不知道，先空着。方法体分三步：

  1. 定义新数组。静态初始化还是动态初始化？静态是知道所有元素的时候用，现在压根不知道要存什么，用动态；动态要知道存几个，可以算出来：new int[to - from]。
  2. 把原数组 from 到 to 的元素拷贝过去。循环的起始不是 0 了，从 from 开始，到 to 结束，不包含 to，所以条件是 i < to。赋值语句右边是 arr[i]，左边 newArr[?] 的方括号里写什么？不能写 i：i 的范围是 3 到 6，可 newArr 的长度才 4，压根没有这些索引。新数组的索引应该从 0 开始依次增长，而现在没有一个变量能表示这个变化范围。没有，就定义一个：int index = 0;，用一次，加加一次。这叫伪造索引的思想：代码里没有变量能表示当前索引的变化范围，就伪造一个。
  3. 把新数组返回：return newArr;。返回的是数组，所以返回值类型不能写 int（那表示返回一个整数），要写 int[]。调用处也要拿一个数组去接收。
public static void main(String[] args) { int[] arr = {1, 2, 3, 4, 5, 6, 7, 8, 9}; // 1. 定义原始数组 int[] copyArr = copyOfRange(arr, 3, 7); // 2. 调用方法拷贝数据 for (int i = 0; i < copyArr.length; i++) { // 3. 遍历 copyArr System.out.print(copyArr[i] + " "); // 4 5 6 7 } } public static int[] copyOfRange(int[] arr, int from, int to) { int[] newArr = new int[to - from]; // 1. 定义新数组 int index = 0; // 伪造索引的思想 for (int i = from; i < to; i++) { // 2. 拷贝 [from, to) 上的元素 newArr[index] = arr[i]; index++; } return newArr; // 3. 把新数组返回 }

运行结果 4 5 6 7，和分析的一模一样。课后练习时不要忙着写代码，先把分析的过程想明白，思路清楚了再动手。

动手：拷贝 [from, to)

arr（原始数组）
newArr
这个方法也是照着 JDK 写的 java.util.Arrays.copyOfRange(arr, from, to) 是 JDK 自带的方法，名字、参数、"包含 from、不包含 to"（包头不包尾）的规则都和这道题一样。Java 里凡是用一对索引表示范围的地方，几乎都是包头不包尾，比如之前的 r.nextInt(10) 是 0~9，以后字符串的 substring(3, 7) 也是。好处就是分析里用到的那一条：长度 = to − from，不用加一减一。
两个版本的差别在边界：把上面的 from 拖到比 to 大，课上的写法会在 new int[to - from] 处抛 NegativeArraySizeException（JDK 的版本抛 IllegalArgumentException）；to 超过 arr 的长度，课上的写法会索引越界，而 JDK 的版本会用 0 把新数组后面补齐。
第 8 节

小结

重载同一个类中，方法名相同、参数不同（个数 / 类型 / 顺序）；与返回值无关
怎么区分调用时根据实参的个数和类型，对应到形参匹配的那个方法
整数默认 int想调 byte 版本：强转，或先定义 byte 变量再传变量
三种输出println(x) 打印并换行；print(x) 只打印；println() 只换行
printArr先 [，中间的数据拼 ", "、最后一个不拼，最后 ]
contains找到就 return true；return false 写在循环外面
return / breakreturn 结束方法（循环也跟着结束）；break 只结束循环或 switch
copyOfRange新数组长度 to - from；i 从 from 到 to；新数组用伪造的 index；返回值类型 int[]
一句话 重载让同一个功能只用记一个名字；写方法先分析：干什么、要什么、调用处还用不用结果，想清楚了代码就是抄思路。

自测

1. int sum(int a, int b) 和 double sum(int a, int b) 写在同一个类里，构成重载吗？
不构成，而且会编译报错（方法重复定义）。重载只看方法名和形参，不看返回值；这两个方法形参完全一样。
2. 有 byte、short、int、long 四个版本的 compare，compare(10, 20) 调用哪个？怎么调用 byte 的版本？
int 的版本，整数默认是 int 类型。调 byte 版本：compare((byte) 10, (byte) 20)，或者先定义 byte b1 = 10, b2 = 20; 再 compare(b1, b2)。
3. System.out.print("a"); System.out.println(); System.out.println("b"); 的输出是几行？
两行：第一行 a，第二行 b。print 不换行，空的 println 只换行。
4. contains 方法里，把 return false 写进 if 的 else 里，查 {1, 5, 8} 里有没有 8，结果是什么？
false。第一次循环拿 1 和 8 比，不相等，直接走 else 返回 false，方法结束，后面的 5、8 根本没比。只有全部比完才能断定不存在，所以 return false 要写在循环外。
5. copyOfRange(arr, 2, 5)，arr 是 {1, 2, 3, 4, 5, 6, 7, 8, 9}，新数组长度是多少、内容是什么？为什么不能写 newArr[i] = arr[i]？
长度 5 - 2 = 3，内容是 2、3、4 索引上的 3、4、5。i 从 2 走到 4，而 newArr 只有 0、1、2 三个索引，i 到 3 时就越界了；而且就算不越界，数据也没有从 0 索引开始放。所以要伪造一个从 0 开始的 index。
