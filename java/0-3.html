Declarations, conditions, methods and arrays

第 1 节

先判断四段代码

先看四段很短的代码。它们都放在 Java 程序的入口方法 main 中；System.out.println 会打印括号里的值。凭直觉选一个答案，看看哪些习惯可以直接带过来，哪些需要调整。

① 数字能直接当条件吗？

int stock = 3;
if (stock) {
    System.out.println("有库存");
}

Condition.java:4: error: incompatible types: int cannot be converted to boolean
        if (stock) {
            ^
1 error

编译失败。stock 是 int，不会因为非零就被当成 true。这里可以写 if (stock > 0)。

② int 没赋值，会自动是 0 吗？

int count;
System.out.println(count);

Unassigned.java:4: error: variable count might not have been initialized
        System.out.println(count);
                           ^
1 error

编译失败。这是方法里的局部变量，使用前必须明确赋过值。“整数默认为 0”适用于字段和数组元素，不能直接套在这里。

③ 单引号和双引号一样吗？

String grade = 'A';

Quote.java:3: error: incompatible types: char cannot be converted to String
        String grade = 'A';
                       ^
1 error

编译失败。'A' 是 char，"A" 才是字符串。可以改成 String grade = "A";，或者保留单引号，把变量类型改成 char。

④ 接收变量是 double，结果是多少？

double average = 5 / 2;
System.out.println(average);

2.0

5 和 2 都是整数，先做整数除法得到 2，再转换成 double 的 2.0。左边的类型不会让已经丢掉的小数回来。

第 2 节

把语法放回一个完整程序

假设要检查五种文具的库存：负数标为“数据异常”，零标为“缺货”，大于零但少于 5 件标为“需补货”，其余标为“正常”。最后只把正数库存加起来。下面的名称、库存和阈值都是为本篇构造的示例数据。

先不用逐行读。找到 names 和 stocks 两个数组：同一个下标放的是同一件文具的名称和库存。按上面的规则，先判断库存为 −2 的尺子和库存为 3 的文件夹会显示什么，再点代码下面的“运行”。

public class InventoryReport {
    public static void main(String[] args) {
        String[] names = {"钢笔", "笔记本", "尺子", "文件夹", "橡皮"};
        int[] stocks = {8, 0, -2, 3, 12};
        final int threshold = 5;

        for (int i = 0; i < stocks.length; i++) {
            String status = statusOf(stocks[i], threshold);
            System.out.println(names[i] + "：" + status);
        }
        System.out.println("可用库存合计：" + totalAvailable(stocks));
    }

    static String statusOf(int stock, int threshold) {
        if (stock < 0) {
            return "数据异常";
        }
        if (stock == 0) {
            return "缺货";
        }
        return stock < threshold ? "需补货" : "正常";
    }

    static int totalAvailable(int[] stocks) {
        int total = 0;
        for (int stock : stocks) {
            if (stock <= 0) {
                continue;
            }
            total += stock;
        }
        return total;
    }
}
钢笔：正常
笔记本：缺货
尺子：数据异常
文件夹：需补货
橡皮：正常
可用库存合计：23

尺子被标为“数据异常”，没有计入合计；文件夹显示“需补货”，但它的 3 件仍然算在可用库存里。这是两个不同的判断，代码也把它们分给了两个方法：statusOf 选状态，totalAvailable 算合计。

再看程序的外形：最外面的 class InventoryReport 声明一个类，main 是程序入口，另外两个方法由它调用。三个方法都写在类的大括号内，彼此并列。现在只要能找到这三块，就可以接着往下读。

main 的 String[] args 接收命令行参数，本例没有使用。其余代码承担两件具体的事：为每个库存数选一个状态，以及累计有效库存。下面逐块读这段程序。

第 3 节

类型写在名字前，检查发生在编译时

int total = 0; 从左往右是“类型、变量名、初始值”。Java 8 的普通局部变量声明要写出类型；后面再赋值时，编译器仍然按这个类型检查。total 不能一会儿装整数，一会儿又装字符串。

类型在这里先怎么读声明例子
byte / short / int / long四种范围不同的整数类型；本篇库存用 int。int count = 3;
float / double两种浮点数类型。double rate = 0.5;
boolean只有 true 和 false 两个值。boolean enabled = count > 0;
char一个 UTF-16 代码单元；这里用普通字母 A 举例。char grade = 'A';
String字符串，是类类型。String title = "A";
int[] / String[]数组类型，方括号写在元素类型后面。int[] stocks = {8, 0, 3};

前四行合起来正好是 Java 的八种基本类型。String 和数组属于引用类型。本篇先记住声明的写法；也不要把 char 理解成“任意一个肉眼看到的字”，有些字符需要两个 UTF-16 代码单元。

字面量本身也有类型。较大的整数后面常见 L，表示 long 字面量；小数默认是 double，需要 float 字面量时写 F。看下面的声明，留意类型名、引号和数字后缀的位置：

int count = 3;
long id = 9007199254740993L;
float ratio = 0.5F;
double rate = 0.5;
boolean enabled = count > 0;
char grade = 'A';
String title = "A";

同样交给 double，为什么结果不同？

回到开头的除法。把除数从 2 改成 2.0，其余不动，先猜两个输出。

double a = 5 / 2;
double b = 5 / 2.0;
System.out.println("division=" + a + "," + b);
division=2.0,2.5

第一行先做整数除法；第二行的 2.0 使运算采用 double，所以保留了小数。你要改变的是参与运算的值的类型。整数除法更准确的规则是向零截断，因此负数情形也不能笼统理解成“向下取整”。

“默认值”要看变量放在哪里

方法里的 int count; 可以先声明，但必须在每条可能读到它的执行路径上先赋值，编译器才允许读取。字段和新建数组的元素则有默认值。这里的 fieldCount 声明在类的大括号内、所有方法之外：static int fieldCount;。再创建两个数组，一起打印，看看哪些位置会自动得到初始值：

int[] numbers = new int[3];
String[] names = new String[2];
System.out.println("defaults=" + fieldCount + ","
        + Arrays.toString(numbers) + "," + Arrays.toString(names));
defaults=0,[0, 0, 0],[null, null]

new int[3] 创建三个整数元素，初始都是 0；new String[2] 创建两个字符串引用，初始都是 null。这里的 Arrays.toString 是把数组元素格式化成便于查看的文字，需要文件开头的 import java.util.Arrays;。

第 4 节

条件必须给出布尔结果

库存程序里写的是 if (stock < 0)，而不是 if (stock)。条件要表达具体判断：库存小于零、等于零，或小于阈值。数字和字符串不能直接按“真假值”使用。

规范允许 if 条件的类型为 boolean 或 Boolean；Boolean 会先自动拆箱。本篇使用的比较表达式直接产生 boolean。

本篇出现的写法结果或用途
stock == 0比较两个整数是否相等，结果是 boolean；= 是赋值。
stock > 0 && stock < 5两项都满足。左边为 false 时，右边不求值。
stock < 0 || stock == 0至少一项满足。左边为 true 时，右边不求值。
!name.isEmpty()把 isEmpty 的布尔结果取反。
stock < threshold ? "需补货" : "正常"按条件从两个字符串中选择一个，得到一个值。

这里会调用 null 上的方法吗？

如果商品名称缺失，name 的值是 null。下面同时检查“不是 null”和“不是空字符串”。先判断：它会输出 false，还是调用方法时抛异常？

String name = null;
boolean hasName = name != null && !name.isEmpty();
System.out.println("shortCircuit=" + hasName);
shortCircuit=false

name 是 null，所以 name != null 为 false，后面的 name.isEmpty() 没有执行。这一行安全结束，并不是 null 能调用方法。把检查顺序反过来，就失去了这层保护。

&&、|| 的短路行为是语言规则。单个 & 和 | 也可以用于布尔运算，但会求值两边，不能在这个例子中随手替换。

第 5 节

方法声明里，输入和输出都写明白

库存程序用 statusOf(stocks[i], threshold) 取得一个状态。找到方法声明后，可以把它拆成四块：

static类方法
String返回值类型
statusOf方法名
(int stock, int threshold)参数类型和参数名

static 表示这个方法属于类，可以在这里直接调用，无须先创建一个 InventoryReport 对象。参数各有类型；调用时传入的值必须符合相应参数的类型要求。返回类型 String 则约束了每个 return 交出去的值。

static String statusOf(int stock, int threshold) {
    if (stock < 0) {
        return "数据异常";
    }
    if (stock == 0) {
        return "缺货";
    }
    return stock < threshold ? "需补货" : "正常";
}

负数在第一个 return 就结束方法；零走到第二个；正数走到最后一行，在“需补货”和“正常”之间选一个。调用者得到返回的字符串，再把它和商品名拼起来。return 结束的是当前这一次方法调用。

main 的返回类型是 void，表示不返回一个值；totalAvailable 的返回类型是 int，因此最后返回累计值。不要省略这些返回类型。

如果有一条路径没有 return，编译器会怎样？ 
public class MissingReturn {
    static String statusOf(int stock) {
        if (stock > 0) {
            return "正常";
        }
    }
}
MissingReturn.java:6: error: missing return statement
    }
    ^
1 error

当 stock 不大于零时，方法可以走到右大括号，却没有返回 String，因此编译失败。这个例子可以在 if 后补一个返回值。准确的规则是：声明了返回值类型的方法体不能正常走到末尾；抛异常、一直不结束等情况另有规则。

把输入、输出和执行路径一起读 看到一个方法，先找参数类型和返回类型，再沿每个分支找它从哪里结束。方法名可以提示用途，类型和 return 给出的是编译器会检查的约束。
第 6 节

数组固定长度，两种 for 操作的地方不同

int[] stocks = {8, 0, 3}; 创建了一个有三个元素的数组。stocks.length 是长度，后面没有括号；下标范围是 0 到 2。数组一旦创建，长度就不变，不能靠给 stocks[3] 赋值来追加元素；越界访问会抛出 ArrayIndexOutOfBoundsException。

假设现在要把这三个库存都清零。下面两种循环都能编译；区别只在于赋值给 stock，还是赋值给 stocks[i]。先选一种运行，再换另一种，看看数组有没有改变。

从同一个数组出发：{8, 0, 3}

int[] stocks = {8, 0, 3};
for (int stock : stocks) {
    stock = 0;
}
System.out.println(Arrays.toString(stocks));
stocks[0]8
stocks[1]0
stocks[2]3

数组仍是 [8, 0, 3]。stock = 0 改的是本轮的局部变量，没有给数组元素赋值。

for (int stock : stocks) 每轮取出一个整数值，赋给本轮的局部变量 stock；给它赋 0，不会写回数组。下标循环里写的是 stocks[i] = 0，赋值目标才是数组中的元素。

这也解释了库存程序为什么用了两种 for：打印状态时，要同时取出 names[i] 和 stocks[i]，下标把它们对应起来；累计库存时只需要逐个取值，就可以用增强 for。

这个实验讨论的是 int 数组 增强 for 并不意味着“循环体永远改不了原数据”。如果元素是对象引用，通过它调用方法可以改变对象的状态；本例之所以不变，关键是 stock 是接收整数值的局部变量。

final 固定的是哪个东西？

库存阈值用了 final，赋值后不能再改。把它放到数组变量前，会不会连数组元素也一起固定？先运行下面这段。

final int[] fixed = {8, 0};
fixed[0] = 9;
System.out.println("finalArray=" + Arrays.toString(fixed));
finalArray=[9, 0]

这段代码能编译运行。final 使 fixed 在赋值后不能再指向另一个数组，数组里的元素仍可改变。对照开头的 final int threshold = 5;：它保存的就是整数值 5，后面不能改成 6。

第 7 节

循环和分支在哪里结束

库存汇总时遇到 0，应该跳过它，还是连后面的库存也不再检查？这取决于写的是 continue 还是 break。读到跳转语句时，先找它结束的是哪一段。

库存汇总方法用了 continue：库存小于等于零时跳过本轮加法，接着检查后面的元素。要找第一个有货的位置，则可以在找到后 break：

int first = -1;
int[] quantities = {0, 3, 8};
for (int i = 0; i < quantities.length; i++) {
    if (quantities[i] > 0) {
        first = i;
        break;
    }
}
System.out.println("firstAvailableIndex=" + first);
firstAvailableIndex=1
在本篇代码里执行后去哪里
continue;跳过本轮剩余部分。普通 for 仍先执行更新表达式，再检查条件。
break;离开最近一层包围它的循环或 switch。本例跳出 for 后，继续打印找到的下标 1。
return value;结束当前方法调用，把值交回调用处。

表中讨论不带标签的 break、continue，以及没有 try/finally 干预的这些示例。

while 的条件和更新写在哪里？

while 的条件同样必须得到布尔结果。下面每轮在循环体中更新 attempt；当它变成 2，下一次判断为 false，循环结束。

int attempt = 0;
while (attempt < 2) {
    attempt++;
}
System.out.println("while=" + attempt);
while=2

Java 8 的 switch 在哪里停下？

同一个变量要和几个离散值匹配时，可以写 switch。Java 8 支持用 String 匹配 case；下面选择 "DRAFT"，输出“草稿”后由 break 离开整个 switch：

String status = "DRAFT";
switch (status) {
    case "DRAFT":
        System.out.println("switch=草稿");
        break;
    case "LIVE":
        System.out.println("switch=已上架");
        break;
    default:
        System.out.println("switch=未知状态");
}

switch=草稿
删掉第一个 break，会不会只输出“草稿”？ 
switch (status) {
    case "DRAFT":
        System.out.println("fallThrough=草稿");
    case "LIVE":
        System.out.println("fallThrough=已上架");
        break;
    default:
        System.out.println("fallThrough=未知状态");
}
fallThrough=草稿
fallThrough=已上架

会继续执行后一个 case 下的语句，直到遇到 break。它不会因为走到新的 case 标签就重新做一次匹配。这里正好连续输出两行。

第 8 节

小结和自测

带走一句话 读这段库存程序，要看清值的类型、赋值改的是谁，以及分支从哪里结束。int 不会自动当条件，给循环变量赋值不会改到数组，continue 和 break 也会算出不同的合计。
遇到的写法本篇可以核对的事实
int count;局部变量不能在明确赋值前读取。
'A'、"A"前者是 char，后者是 String。
5 / 2先做整数除法；赋给 double 后是 2.0。
if (stock)stock 是 int 时编译失败，要写出具体判断。
static String statusOf(int stock, int threshold)类方法，两个 int 参数，返回 String。
for (int stock : stocks)stock 是循环变量；给它赋 0 不会把 int 数组清零。
final int[] fixed不能再给变量赋另一个数组，仍能改当前数组的元素。

三个问题

1. 把完整程序的 threshold 从 5 改成 3，哪些输出会改变？
只有“文件夹：需补货”会变成“文件夹：正常”。它的库存是 3，判断用的是 stock < threshold，等于阈值不满足。总库存仍是 23，因为汇总方法不接收 threshold，也没有用它过滤数据。
2. 在 totalAvailable 中，把 continue 改成 break，总数会是多少？
按执行路径推导是 8：第一个库存 8 加进去，遇到第二个库存 0 时离开整个循环，后面的 -2、3、12 都不再检查。原来的 continue 只跳过本轮，后面的 3 和 12 仍会累计。
3. 只想输出“有货”或“无货”，请把 statusOf 的规则改成 stock > 0 时“有货”，其余“无货”。返回类型需要改吗？
仍是 String。可以把方法体改成 return stock > 0 ? "有货" : "无货";。调用处依然接收一个字符串；threshold 参数不再使用，可以连同调用时的第二个实参一起删除。仅改方法声明或仅改调用的一边，会产生参数不匹配的编译错误。
