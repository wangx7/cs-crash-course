语法速览

Syntax you already know, the way Java writes it

0.2 把一个只有一行有效代码的程序从源码跟到了 JVM。这一篇换一个真正做计算的程序：统计一组数量。判断、循环、方法你已经会，所以这篇只讲 Java 多出来的限制——每一条限制都让 JDK 8 的编译器实际拦一次，错误信息原样贴出。最后有一个 19 行的找错练习，把整篇的检查点混在一起。

你们的服务跑在 Java 8 上，所以正文一律按 Java 8 实测。每一节后面附一段新版补充，说清新的版本在这条上加了什么写法。方向可以放心：新版加的是更省事的写法，你学到的 Java 8 规则并没有被废掉。

第 1 节

先读，不先讲

下面是一个完整的 Java 程序，统计一批数量：正数累加，零跳过，遇到负数停止。先通读一遍，猜它打印什么。

public class OrderStats {
    public static void main(String[] args) {
        int[] quantities = {2, 0, 3, -1, 6};
        int total = sumBeforeStop(quantities);
        String label = total >= 5 ? "可发货" : "待凑单";
        System.out.println("件数=" + total);
        System.out.println(label);
    }

    static int sumBeforeStop(int[] quantities) {
        int total = 0;
        for (int i = 0; i < quantities.length; i++) {
            int quantity = quantities[i];
            if (quantity < 0) {
                break;
            }
            if (quantity == 0) {
                continue;
            }
            total += quantity;
        }
        return total;
    }
}

这个程序的每一行你大概都读得懂。会读和会写之间的差距不在思路，在编译器：Java 运行任何东西之前先过编译器，很多写法问题在这一步就被拦下，根本等不到运行。接下来四节，每一节挑一处最容易凭直觉写错的地方，让 JDK 8 的 javac 实际拦给你看。

第 2 节

声明：类型写在前面，先给值再读

本篇用到的声明都在这里。类型名写在变量名前面，等号右边给初值：

int quantity = 3;
long orderId = 3000000000L;
double ratio = 0.5;
float progress = 0.5F;
boolean paid = false;
char grade = 'A';
String status = "PAID";
  • int 是 32 位整数，long 是 64 位。这个订单号超出了 int 的范围，字面量末尾要加 L。小数默认是 double，float 的字面量加 F。
  • boolean 只有两个值：true 和 false。
  • 单引号是 char（一个 UTF-16 代码单元），双引号是 String。String 不是基本类型，是引用类型。基本类型一共八种：上面六种加 byte、short。
  • var total = 0; 在 Java 8 上编译不过：错误: 找不到符号 … 类 var——编译器把 var 当成一个类名去找（实测）。它后来才出现，见本节的「新版补充」。
新版补充：var（Java 10） 从 Java 10 起，局部变量可以写 var，类型由编译器按等号右边推断：var list = new ArrayList<String>(); 推断为 ArrayList<String>。它只能用于带初值的局部变量（包括 for 循环里的），字段、方法参数和返回类型都不行。var 不是关键字，是一个保留的类型名，所以老代码里叫 var 的变量不受影响。你们的项目是 Java 8，用不上它；读新代码见到时，知道它只是省写类型、类型检查一步不少就行。（依据 JEP 286，本机只有 JDK 8，这段没有实测。）

声明还有一条运行前就生效的规则，先猜：

和局部变量对照着记的是数组元素：new int[3] 造出来的三个元素自动是 0，引用类型数组的元素自动是 null。这两个输出是实际跑出来的：

System.out.println(Arrays.toString(new int[3]));
System.out.println(Arrays.toString(new String[2]));

[0, 0, 0]
[null, null]

规则的分界线是声明的位置：字段和数组元素在创建时带默认值，局部变量不带——任何读取局部变量的位置，编译器都要能确定它之前被赋过值。字段是直接写在类里的变量，1.4 篇再写。把“Java 的变量默认是零”记成一条统一规则，会在局部变量上撞墙。

实测：local/examples/0-3/Checks.java（数组默认值）、fail/Unassigned.java、fail/VarKeyword.java。

第 3 节

分支：条件得算出个布尔

第 2 节的 quantity 是 3。把下面这行交给 javac，先猜结果：

条件得写成一个能算出布尔值的表达式：

if (quantity > 0 && "PAID".equals(status)) {
    System.out.println("可处理");
} else {
    System.out.println("暂不处理");
}

字符串比内容用 equals（逐个字符相同才算等）。== 用在字符串上比的不是内容，是两边是否指向同一个对象——为什么有时“碰巧也对”，1.3 篇讲常量池时看，现在先记住：内容比较写 equals。

&& 和 || 会短路：左边已经能定出结果，右边就不执行。所以下面这行不会访问空引用的 length，输出 false：

int[] missing = null;
System.out.println(missing != null && missing.length > 0);

false

if 的括号也接受包装类型 Boolean，但它会被拆箱；对 null 拆箱会在运行时抛 NullPointerException（实测，Checks.java 最后一行）。本篇只用 boolean。

几个固定状态：Java 8 的 switch

switch (status) {
    case "PAID":
        System.out.println("已付款");
        break;
    case "CLOSED":
        System.out.println("已关闭");
        break;
    default:
        System.out.println("未知状态");
}

输出“已付款”。Java 8 的 switch 能匹配字符串（还能匹配 int、char、枚举等）。一点注意：

  • 冒号写法里，匹配上以后如果没有 break 之类的结束语句，会顺着往下执行，default 也拦不住。实测：把上面三个 break 都删掉，三行“已付款”“已关闭”“未知状态”会全部打印。
新版补充：箭头写法和 switch 表达式（Java 14、21） Java 14 给 switch 加了箭头写法，匹配后只执行箭头右侧，不贯穿，break 不再需要；switch 还可以整体当表达式，直接把结果赋给变量： 
String label = switch (status) {
    case "PAID" -> "已付款";
    case "CLOSED" -> "已关闭";
    default -> "未知状态";
};
冒号旧写法没有被废弃：JEP 361 的原话是传统的 case ... : 和新的 case ... -> 两种标签都可用。Java 21 又让 switch 能按类型匹配（模式匹配，JEP 441）。这些在 Java 8 的项目里见不到，但读新代码会碰到。（示意：这段没有在 Java 14+ 的编译器上跑过，写法依据 JEP 361。）

两个值里选一个时可以用条件表达式，第 1 节第 5 行就是：total >= 5 ? "可发货" : "待凑单"。

实测：fail/Truthiness.java、Checks.java（短路）、FallThrough.java（switch 贯穿）。

第 4 节

数组和循环

int[] 读作“元素类型为 int 的数组”。{2, 0, 3} 在声明时给出初值，也定下了长度。数组创建以后长度不再变；想要能增删的容器，第 2 部分的 List 是干这个的。

取长度写 quantities.length，不带括号——它是数组对象上一个 public final 字段。String 的长度是方法 length()，带括号。两个写法都存在，写混了编译器会拦。

下标的合法范围是 0 到 length - 1。越界这件事编译器不查，它在运行时抛 ArrayIndexOutOfBoundsException——下面这个文件编译顺利通过，运行才炸：

int[] a = new int[2];
System.out.println(a[5]);

Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: 5
	at Bounds.main(Bounds.java:4)

所以遍历条件写 i < quantities.length，不是小于等于。

增强 for：循环变量是个副本

增强 for 每一轮把当前元素的值赋给循环变量。给这个 int 变量重新赋值，不会写回数组。要改元素，用下标：

for (int i = 0; i < quantities.length; i++) {
    quantities[i] *= 2;
}
System.out.println(Arrays.toString(quantities));

[4, 0, 6]

这条结论的边界要说清：它针对的是“给循环变量赋值”。如果数组里放的是对象引用，通过引用调用方法改对象内部，是另一回事，1.2 篇讲引用时再看。

三个出口

第 1 节的循环里 break、continue、return 都有，正好是三个不同的出口：continue 跳过本轮剩下的部分（接着执行 for 的更新语句 i++ 再判断条件）；break 退出整个循环，所以最后的 6 没有被加进去；return 退出的就是整个方法，写在哪一层都一样。

while 和 do-while 的写法和你习惯的一样，条件同样必须是布尔值，这篇不单独演示。

新版补充：这一节没有新版要补 数组是这门语言最早的一批特性，它的规则在新版里没有变化——“数组对象创建后长度不再改变”“所有数组访问都在运行时检查”这两句，在 Java SE 25 的规范里原文还在（参考资料里有链接）。遍历的新写法没有发生在数组上，发生在集合那边：forEach、Stream 是第 2 部分的内容。

实测：fail/Bounds.java（越界）、Checks.java（增强 for 副本、下标写回）。

第 5 节

方法

第 1 节把统计收进了 sumBeforeStop。拿它的第一行拆一遍方法声明：

写法含义
static类方法，这里为了能从同为 static 的 main 里直接调用。static 的适用场景 1.5 篇讲，不要据此把业务方法都加上 static。
int返回类型。不返回值就写 void。
sumBeforeStop方法名。
int[] quantities参数：类型 + 名字。传进来的值必须和声明的类型对得上。
return total;交回结果并结束本次调用。

方法写在类体里，和 main 并列。Java 8 不能把方法定义塞进另一个方法的内部——这条你先记着，下一节的练习里会亲手撞到它。

每条正常路径都得有结果

声明了返回类型的方法，不允许“从末尾掉出去”。下面这个 fee 只在 paid 为真时返回，另一条路径正常走完方法体——编译不过：

static int fee(boolean paid) {
    if (paid) {
        return 0;
    }
}

MissingReturn.java:6: 错误: 缺少返回语句
    }
    ^
1 个错误

注意这条规则管的是“正常走完”的路径：抛出异常的路径不算正常结束，不受这条限制。

同名方法靠什么区分

Java 允许同名方法并存，靠参数列表区分（重载）。但方法的签名只有名字和参数类型，不含返回类型。所以只靠返回类型不同的两个同名方法，会被当成重复定义：

static int count(int n) { return n; }
static long count(int n) { return n; }

1 个错误
新版补充：变化的重心在方法旁边 这一节没有新版写法要记。和方法相关的写法变化，最大的一次就是 Java 8 自己：lambda 表达式和方法引用把“一段行为”变成了可以当值传递的东西（2.5 篇展开）；接口从 Java 8 起可以有带实现的方法（默认方法，1.7 篇讲）。

实测：fail/MissingReturn.java、fail/DuplicateMethod.java。

练习：编译器会拦哪几行

这一篇见过的检查点都在下面这个 19 行的文件里了，另外还混进了一条没讲过的。任务：点出所有会被 javac 拦下的行（编译错误），可以多点，然后提交。其中有一行 javac 永远不管——它属于另一类问题。

    四轮输出连起来看，能看出 javac 是分阶段干活的：先把源码读成结构（第 1 轮只报了第 14 行），再核对类型（第 2 轮报第 4、13 行），再检查赋值路径（第 3 轮报第 12 行）。前一阶段有错，后面的检查就不做。所以改完一拨错误再编译，可能冒出新的错误——不是你改坏了，是编译器终于走到了下一步。

    第 7 行从头到尾没出现在任何一轮的编译输出里。下标越界的检查本来就被规定在运行时，编译期查的是语法结构、类型、赋值路径这些不看运行数据就能定的事。

    第 8 节

    小结和自测

    带走一句话 读得懂和写得对之间隔着编译器的检查：局部变量先赋值再读，条件必须算出布尔，声明了返回类型的方法每条正常路径都要给结果，同名方法靠参数列表区分。这些过不去，程序根本不会被运行。而数组越界、null 拆箱这类问题编译器不查，它们在运行时等着。每节末尾的「新版补充」是全课的固定栏目：正文按你们项目的 Java 8 实测，新版本加的写法单列。

    三个问题

    1. 字段、局部变量、数组元素——哪些不赋值就能读？读出来是什么？
    字段和数组元素：创建时带默认值，int 是 0，引用类型是 null，boolean 是 false。局部变量：没有默认值，读取之前编译器必须能确定它被赋过值，否则编译错误。实测见第 2 节。
    2. double average = 5 / 2; 打印 average 得到 2.5 吗？
    得到 2.0。等号右边先算整数除法，5 / 2 得 2（整数除法向零取整），然后才把 2 转成 double。写 5 / 2.0 才得到 2.5。两种输出都在 Checks.java 里实测过。除法、溢出、小数精度这些数值的坑，是下一篇 1.1 的内容。
    3. 同事写了 if ("PAID" == status)。能编译吗？行为对不对？
    能编译——== 用在引用类型上是合法的。但它比的是两边是否指向同一个对象，不是内容是否相同。内容比较要写 "PAID".equals(status)。为什么 == 有时“碰巧”也对，1.3 篇讲字符串常量池时会拆开看。

    参考资料

    每一条后面写了它支撑的是哪句话。规范正文在本地留有副本，链接和原文在 2026-11-13 逐条核对过；未特别标注版本的语言规范均为 Java SE 8 版。

    语言规范（JLS）

    • JLS §4.2 Primitive Types and Values支撑：第 2 节——八种基本类型；int 32 位、long 64 位；char 是 UTF-16 代码单元；boolean 只有 true 和 false
    • JLS §3.10.1 Integer Literals支撑：第 2 节——long 字面量末尾写 L
    • JLS §3.10.2 Floating-Point Literals支撑：第 2 节——小数字面量默认是 double，写 F 才是 float
    • JLS §4.12.5 Initial Values of Variables支撑：第 2 节——字段和数组元素创建时带默认值（int 为 0，引用类型为 null）
    • JLS §16 Definite Assignment支撑：第 2 节——局部变量在每次读取前必须已被赋值，否则编译错误
    • JLS §14.9 The if Statement支撑：第 3 节——条件必须是 boolean 或 Boolean（Boolean 会拆箱）
    • JLS §5.1.8 Unboxing Conversion支撑：第 3 节——对 null 拆箱抛 NullPointerException
    • JLS §15.23 / §15.24 Conditional-And / Conditional-Or支撑：第 3 节——&& 和 || 的短路
    • JLS §15.21.3 Reference Equality Operators支撑：第 3 节和自测第 3 题——== 为真当且仅当两边指向同一个对象（或都为 null）
    • JLS §14.11 The switch Statement支撑：第 3 节——switch 可匹配 String；冒号写法匹配后顺序往下执行（贯穿）
    • JLS §10.2 Array Variables支撑：第 4 节——数组对象创建后长度不再改变
    • JLS §10.4 Array Access支撑：第 4、6 节——所有数组访问在运行时检查，越界抛 ArrayIndexOutOfBoundsException
    • JLS §10.7 Array Members支撑：第 4 节——length 是数组的 public final 字段（所以不带括号）
    • JLS §14.14.2 The enhanced for Statement支撑：第 4 节——增强 for 每轮把元素赋给循环变量（等价于一个带下标的普通 for）
    • JLS §8.4.2 Method Signature支撑：第 5 节——签名只含名字和参数类型，不含返回类型
    • JLS §8.4.7 Method Body支撑：第 5 节——有返回类型的方法，方法体若能正常走完就是编译错误
    • JLS §15.17.2 Division Operator支撑：自测第 2 题——整数除法向零取整
    • JLS（Java SE 25）§10.2、§10.4支撑：第 4 节「新版补充」——“创建后长度不再改变”“所有数组访问在运行时检查”两句原文到 Java 25 未变

    JEP（新特性的来处）

    • JEP 286：Local-Variable Type Inference（Java 10）支撑：第 2 节「新版补充」——var 的推断方式、适用范围、“var 不是关键字而是保留类型名”
    • JEP 361：Switch Expressions（Java 14）支撑：第 3 节「新版补充」——箭头写法不贯穿、switch 可当表达式、传统冒号写法继续可用
    • JEP 441：Pattern Matching for switch（Java 21）支撑：第 3 节「新版补充」——Java 21 起 switch 能按类型匹配

    官方 API 文档（Java 8）

    • String.equals(Object)支撑：第 3 节——equals 按“相同的字符序列”比较内容
    • Arrays.toString(int[])支撑：第 2、4 节——输出格式是方括号加逗号分隔，如 [2, 0, 3]
