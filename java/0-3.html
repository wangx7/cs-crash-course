01 / 先预测

它会打印 0 吗？

把下面两行放在上一节的 main 方法里。先选一个结果，再展开答案：打印 0、运行时报错，还是根本编译不过？

int total;
System.out.println(total);
看 JDK 8 的编译结果
fail/Unassigned.java:4: error: variable total might not have been initialized
        System.out.println(total);
                           ^
1 error

编译不过。total 是方法里的局部变量，读取之前必须有确定的赋值。要从零累加，就明确写 int total = 0;。Java 对数组元素的规则又不一样，下一节马上对照。

实测文件：Unassigned.java，第 3–4 行。错误输出使用英文诊断，便于对照错误名。

02 / 声明

类型写在名字前面

本篇用到的声明如下。在 Java 8 里，局部变量不能用 var 推断类型；这里直接写出类型名。

int quantity = 3;
long orderId = 3000000000L;
double ratio = 0.5;
float progress = 0.5F;
boolean paid = false;
char grade = 'A';
String status = "PAID";

int 和 long 都是整数类型，分别为 32 位和 64 位；这个订单号超出了 int 的正数范围，所以字面量末尾写 L。小数默认按 double 写，float 的字面量加 F。范围、转换和计算误差在 1.1 篇展开。

boolean 只有 true 和 false。单引号用于 char，双引号用于 String；char 存一个 UTF-16 代码单元，不保证能装下一个完整的 Unicode 字符，例如某些 emoji。String 是引用类型，前面的六种是基本类型；另外两种基本类型是 byte 和 short。

局部变量和数组元素，别混在一起

int[] counts = new int[3];
String[] names = new String[2];
System.out.println(Arrays.toString(counts));
System.out.println(Arrays.toString(names));
[0, 0, 0]
[null, null]

new int[3] 创建三个元素，元素自动初始化为 0；引用类型数组的元素默认是 null。这里的局部变量 counts、names 都已经由等号右边赋过值。Arrays.toString 用于把数组内容转成便于阅读的字符串，文件顶部要写 import java.util.Arrays;。

区分声明的位置。字段和数组元素有默认值；局部变量必须在读取前赋值。字段是直接声明在类里的变量，1.4 篇再写。把“Java 变量默认是零”记成统一规则，会在本篇开头就碰壁。

本节及后面的零散片段摘自 SyntaxChecks.java；它是可下载、可编译的完整文件。

03 / 分支

不把数量当作真假

if (quantity) 在 Java 中编译不过，即使它的值是 3。条件要写成能得到布尔值的表达式：

if (quantity > 0 && "PAID".equals(status)) {
    System.out.println("可处理");
} else {
    System.out.println("暂不处理");
}

这里用 quantity > 0 判断数量，用 "PAID".equals(status) 判断字符串内容。不要把字符串的 == 当成内容比较：它比较的是引用是否相同。字符串比较为什么这样写，1.3 篇细讲；这次先用 equals。

&&、||、! 分别是逻辑与、逻辑或、逻辑非。前两个会短路，因此这个判断不会访问空引用的 length：

int[] missing = null;
System.out.println(missing != null && missing.length > 0);

输出是 false。左边已经为假，&& 右边不执行。if 也接受包装类型 Boolean，但它会被拆箱；若值是 null，会抛出异常。本篇只用基本类型 boolean。

几个固定状态：Java 8 的 switch

switch (status) {
    case "PAID":
        System.out.println("已付款");
        break;
    case "CLOSED":
        System.out.println("已关闭");
        break;
    default:
        System.out.println("未知状态");
}

输出是“已付款”。Java 8 的 switch 可以匹配字符串；使用 case ...: 的写法，若匹配后没有 break、return 等结束控制流，就会继续执行后面的语句，甚至走进 default。这里的 break 退出这个 switch。

只需要在两个值里选一个时，可以写 String label = total >= 5 ? "可发货" : "待凑单";。后面的完整程序会用到它。Java 8 没有新版教程里的 case ... -> 写法。

04 / 数组与循环

先看遍历到底改了谁

预测：数组里的数量翻倍了吗？

int[] quantities = {2, 0, 3};
for (int quantityCopy : quantities) {
    quantityCopy *= 2;
}
System.out.println(Arrays.toString(quantities));
展开实际输出和原因
[2, 0, 3]

没有翻倍。for (int quantityCopy : quantities) 是增强 for，每轮把当前元素的值赋给局部变量 quantityCopy。给这个 int 变量重新赋值，不会写回数组。要更新元素，用下标：

for (int i = 0; i < quantities.length; i++) {
    quantities[i] *= 2;
}
System.out.println(Arrays.toString(quantities));
[4, 0, 6]

这个结论针对给循环变量赋值。如果数组里装的是对象引用，通过引用调用方法修改对象，是另一回事，留到 1.2 篇。

int[] 是“元素类型为 int 的数组”。{2, 0, 3} 在声明时给出初值，也确定了长度。数组创建以后长度固定，取长度写 quantities.length，没有括号。想要能增删元素的容器，第 2 部分用 List。

下标从 0 到 length - 1；越界会在运行时抛 ArrayIndexOutOfBoundsException。所以遍历条件是 i < quantities.length，不是小于等于。越界示例已在 Bounds.java 实测。

把 continue 和 break 放进一次统计

为观察控制流程，约定一批演示数据 {2, 0, 3, -1, 6}：正数累加，零跳过，遇到负数就停止。负数是本例人为约定的停止标记，不是订单系统的通用规则。

int total = 0;
for (int i = 0; i < quantities.length; i++) {
    int quantity = quantities[i];
    if (quantity < 0) {
        break;
    }
    if (quantity == 0) {
        continue;
    }
    total += quantity;
}

先猜总数，再逐轮追踪

示意：浏览器按上面的固定数据展示步骤，不在网页中执行 JVM。最终结果已与 JDK 8 输出核对。

[0]2
[1]0
[2]3
[3]-1
[4]6
total = 0

还没进入循环。最后的 6 会被加进去吗？

这里的 continue 跳过本轮剩余部分，接着执行 for 的更新语句 i++，再判断条件。break 则直接退出这个循环，不会再走到最后的 6。如果把 return total; 写进循环里，退出的就是整个方法。

while 和 do-while 的写法速查 
int i = 0;
while (i < quantities.length) {
    System.out.println(quantities[i]);
    i++;
}
int attempts = 0;
do {
    attempts++;
} while (attempts < 1);
System.out.println(attempts);

while 的条件同样要是布尔值。上面的数组已经翻倍，依次打印 4、0、6。do-while 先执行再判断，本例最后打印 1；注意结尾有分号。若在 while 里写 continue，它会直接回到条件判断，不会替你执行后面手写的 i++。

05 / 方法

把统计收进一个有返回值的方法

将下面完整代码保存为 OrderStats.java。main 准备输入、调用统计方法，再打印结果；计算逻辑放进同一个类里的 sumBeforeStop。

public class OrderStats {
    public static void main(String[] args) {
        int[] quantities = {2, 0, 3, -1, 6};
        int total = sumBeforeStop(quantities);
        String label = total >= 5 ? "可发货" : "待凑单";
        System.out.println("件数=" + total);
        System.out.println(label);
    }

    static int sumBeforeStop(int[] quantities) {
        int total = 0;
        for (int i = 0; i < quantities.length; i++) {
            int quantity = quantities[i];
            if (quantity < 0) {
                break;
            }
            if (quantity == 0) {
                continue;
            }
            total += quantity;
        }
        return total;
    }
}
方法声明中的部分这里的含义
static这是类方法；此处可从同类的 static main 直接调用，无需先创建对象。
int返回结果的类型。若不返回值，写 void。
sumBeforeStop方法名，调用时在后面加括号。
int[] quantities参数的类型与名字；传入值必须与参数类型兼容。
return total;返回结果并结束本次调用。

方法写在类体内，和 main 并列，不能把普通方法声明塞进另一个方法体。这里先用 static 把程序跑通；对象方法、访问修饰符和 static 的适用场景会在 1.4、1.5 篇展开，不要据此把业务方法全部加上 static。

返回类型为 int 的方法不能走到末尾却没给出结果。例如只在 if (paid) 分支里返回，另一个分支走到结尾，就会报 missing return statement。这不意味着每条路径必须写 return：抛出异常的路径也不会正常走到结尾。

Java 允许同名方法用不同的参数列表重载，但不能只靠返回类型区分。同时声明 int count(int n) 和 long count(int n)，会被当成重复方法。两种编译错误都保留在本篇的 实验目录。

看改动后的输出
件数=11
可发货

负数不再结束循环，只跳过这一个元素，因此最后的 6 也计入总数。这个改动也用 JDK 8 实测过，验证脚本会在临时目录里生成修改版。

三道自测

1. new int[0] 能创建吗？访问它的第一个元素呢？
能创建长度为零的数组，遍历它不会进入循环。但它没有合法下标，访问 [0] 会在运行时抛出 ArrayIndexOutOfBoundsException。
2. 想在数组里把每个数加 1，用增强 for 给循环变量赋值行吗？
对本篇的 int[] 不行，修改局部变量不会写回数组。用普通 for 和下标写 quantities[i] += 1;。
3. double average = 5 / 2; 得到 2.5 吗？
得到 2.0。右侧先做整数除法，得到 2，然后才转成 double。写 5 / 2.0 得到 2.5。这两种输出都在 SyntaxChecks.java 中实测过；下一篇从这里展开数值类型。
现在你可以写出并运行一个 Java 方法：声明参数和返回类型，用布尔表达式控制分支，用下标或增强 for 读取数组，并明确决定是跳过一轮、退出循环，还是结束方法。

每条规则对应到哪里

2026-11-13 打开原文核对。以下是 Java SE 8 规范与官方 API 文档；示例是为本课编写的实验，没有引用业务项目源码。

语言规范

  • JLS §4.2 · 基本类型支撑：int / long 的位宽、八种基本类型、char 是 UTF-16 代码单元。
  • JLS §4.12.5 · 变量的初值支撑：字段与数组元素有默认值；局部变量在读取前必须明确赋值。
  • JLS §14.4 · 局部变量声明支撑：Java 8 的局部变量声明语法需要写类型。
  • JLS §14.9 · if 语句支撑：条件必须是 boolean 或 Boolean，后者会拆箱。
  • JLS §14.11 · switch 语句支撑：Java 8 的冒号语法、字符串匹配与匹配后的顺序执行。
  • JLS §15.23 · 条件与运算符 &&支撑：左侧为 false 时不计算右侧；相邻 §15.24 说明 || 的短路。
  • JLS §15.21.3 · 引用相等运算符支撑：字符串用 == 比较的是引用，不是内容。
  • JLS §10.2 · 数组变量支撑：数组对象创建后长度不变；§10.4 说明下标检查；§10.7 规定 length 字段。
  • JLS §14.14.2 · 增强 for支撑：数组遍历时每轮把元素赋给循环变量，而不是把变量赋值写回元素。
  • JLS §14.14.1.3 · 普通 for 的控制转移支撑：continue 后执行更新表达式；§14.12–14.17 规定 while、do、break、continue 和 return。
  • JLS §8.4 · 方法声明支撑：参数、static 方法、返回类型、方法体；§8.4.2 / §8.4.9 规定签名与重载，不能只靠返回类型区分。
  • JLS §15.17.2 · 除法运算符支撑：整数除法向零截断；5 / 2 先得到整数 2。

官方 API 与本篇实验

  • Java 8 Arrays.toString(int[])支撑：把 int 数组按方括号、逗号分隔的形式转成字符串；同页有 Object[] 重载。
  • Java 8 String.equals(Object)支撑：按字符串的字符序列比较内容。
  • 本篇可复现实验含完整源码、实际输出和验证脚本；正常示例、预期编译失败、数组越界、练习修改版都用 Amazon Corretto 1.8.0_512 检查。

示例边界：订单状态、负数停止标记和满 5 件的标签都是教学约定，不代表 BladeX 的业务规则。交互中的逐轮状态是按源码制作的示意；JVM 的实际最终输出单独保存。本文不推断实际项目的实现方式。
