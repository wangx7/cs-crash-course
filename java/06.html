第 1 节 · P6

先说学习方法：先求广度，再求深度

零基础刚开始学，不要追求知识点的深度，要追求广度。一个知识点先学会怎么用，别往深里钻；把尽可能多的知识点综合用起来、锻炼思维，才是第一位的。深入的内容放到第二阶段再学。这也符合我们平时学东西的顺序，整门课就是按这个思路设计的。

第一阶段（基础）分几大块：Java 基础语法、Java 最核心的面向对象、API、字符串、集合，最后用学过的所有知识写一个综合案例拼图小游戏。写游戏不是目的，目的是练逻辑思维和综合运用的能力。

基础语法一共 7 个模块：前 6 个学基础内容，第 7 个结合斯坦福大学的练习题做大量综合练习。现在是第一个模块，顺序是：Java 是什么 → 写第一个小案例 → Java 的发展历史 → 为什么这么火 → JRE 和 JDK。

Java 是什么？想让计算机按我们的指令做事，就得说它听得懂的语言，Java 就是一门非常火的计算机语言。视频给了几组截至 2021 年上半年的数据：全球编程语言排行榜上，没有哪门语言能一直霸榜，起起伏伏很正常，但 Java 基本一直在前三；国内市场占有率约 28%，排第一；BOSS 直聘、前程无忧、智联招聘的热门职位里也都有 Java。

排行榜看个大概就好 常见的排行榜（TIOBE、PYPL 等）算法各不相同，只能反映"讨论和搜索热度"，名次每年都在变，比如这几年 Python 的排名普遍在 Java 前面。但 Java 在企业后端、安卓和大数据领域的岗位一直很多，这一点没变。
第 2 节 · P7

下载并安装 JDK

就像玩游戏得先下载安装，写 Java 代码也要先装一个软件：JDK。去官网 www.oracle.com 下载，一定要选和自己操作系统对应的安装包。安装是"傻瓜式"的，一路下一步，最多改一下安装路径。改路径时有两条建议：

  1. 路径里不要有中文、空格和特殊符号。这些软件是外国人写的，对中文支持不完美，路径带中文以后容易出问题。用英文单词加数字就好。
  2. 所有开发工具放在同一个文件夹里，方便统一管理。老师把开发相关的软件都装在 E:\develop 下面，JDK 就装在 E:\develop\jdk。

官网下载的路线：Products → Java → 右上角 Download Java。页面默认是最新版，当时是 2021 年 9 月刚发布的 Java 17，后面带 LTS，意思是"长期支持版"（后面的视频再细讲）。往下选 Windows，会看到三个下载项，老师选中间那个 .exe 安装包，说它最"干净"；第一个 zip 他说是"压缩包里装着安装包和一些说明文件"，其实不是。官网速度慢，课程资料里直接提供了安装包（资料里的是 JDK 11）。

更正：三个下载项分别是什么 Windows 下的三项一般是：x64 Compressed Archive（.zip）、x64 Installer（.exe）、x64 MSI Installer（.msi）。zip 里装的就是 JDK 本身，解压到哪儿就"装"在哪儿，不需要安装，也不会自动配置环境变量；exe 和 msi 都是安装程序，msi 更适合公司里批量部署。初学用 exe 最省事，老师的选择没问题。另外，Oracle 官网下载 JDK 17 及之后的版本一般不用登录；JDK 8、11 这些旧版才要求登录 Oracle 账号。

装完打开 E:\develop\jdk，里面有一堆文件夹。点一点看它们是干什么的：

点一点：JDK 安装目录里有什么

    六个文件夹里，真正要记住的只有 bin：各种工具都在里面，其中最重要的是 javac 和 java，下一节马上用到。以后要用哪个工具，就去 bin 里找。

    版本选哪个 LTS（Long-Term Support）版本会得到很多年的更新和安全补丁，公司里基本只用 LTS。Java 从 2018 年起每半年发一个新版本；LTS 有 8、11、17、21（2023）、25（2025），从 17 起每两年出一个。这门课用 17 讲，用 21 或 25 学完全没问题，课里的代码都能跑。
    用 Mac 的话 下载页选 macOS，Apple 芯片（M 系列）选 ARM64，Intel 芯片选 x64，下载 .dmg 双击安装，不用选路径。装好后在 /Library/Java/JavaVirtualMachines/jdk-17.jdk/Contents/Home，同样有 bin、conf、lib 这些文件夹。打开终端输入 java -version，能看到版本号就说明装好了。免费的 OpenJDK 发行版（比如 Eclipse Temurin）也可以，用法一样。
    第 3 节 · P8

    第一个程序：HelloWorld

    不管学哪种语言（Java、C、Python……），写的第一个程序都是 HelloWorld，这是程序员圈约定俗成的规矩。老师开了个玩笑：程序员退休后练毛笔字，第一个字下意识写的也是 HelloWorld。步骤只有三步：

    1. 用记事本编写程序。代码只有三行，作用是把第三行双引号里的内容打印出来。
    2. 编译文件。
    3. 运行程序，就能看到 HelloWorld。

    双引号里写 ABC 就打印 ABC，写 123 就打印 123。只要先别写中文（会乱码，第 6 节讲怎么解决）。

    "编译"是什么意思？Java 代码不能直接在操作系统里运行，因为操作系统不认识它。只能先把代码翻译成操作系统看得懂的东西再执行。所以"编译"就理解成"翻译"：翻译完会生成一个新文件，第三步运行的是这个新文件。

    第 1 步：写代码。在代码文件夹里右键新建文本文档，起名 HelloWorld，后缀名改成 .java。系统会提示"更改扩展名可能导致文件不可用"，选"是"：Java 代码所在的文件后缀必须是 java。看不到后缀名的话，打开"此电脑"→ 查看 → 勾上"文件扩展名"。然后右键 → 编辑，用 Windows 自带的记事本写：

    public class HelloWorld { public static void main(String[] args) { System.out.println("HelloWorld"); } }

    写的时候有个好习惯：括号成对写。很多人先写左括号，写完中间的代码再补右括号，这样很容易忘。应该左右括号一起敲出来，再把光标挪到中间回车，补中间的代码。写完 Ctrl+S 保存。怎么看有没有保存？记事本标题最前面有个 * 就是没保存，保存后它就消失了。

    第 2、3 步：编译和运行。用的工具就是上一节说的 bin 里的 javac 和 java，它们要在 CMD 里用：

    F: ← 切换盘符：代码在 F 盘 cd JavaSE\day01\代码 ← 进入代码所在的文件夹 javac HelloWorld.java ← 编译：带后缀 java HelloWorld ← 运行：不带后缀
    • 切换盘符、进文件夹：CMD 默认在 C:\Users\用户名，可代码不在那儿。先找到代码。
    • javac 是 JDK 提供的编译工具，把当前路径下的 HelloWorld.java 编译成 HelloWorld.class。没报错就说明语法没问题；写错了会列出一堆错误。生成的 class 文件也叫字节码文件，用记事本打开是一堆看不懂的东西，正常，它本来就不是给人看的。
    • java 是 JDK 提供的运行工具，运行当前路径下的 HelloWorld.class，但不写后缀。口诀：有 c 有后缀，没 c 没后缀。

    动手：记事本 + CMD，跑通 HelloWorld

    左边是记事本，右边是"代码"文件夹。改完代码记得 保存（标题前的 * 会消失），再在下面的 CMD 里编译、运行。试着改一下双引号里的内容，不保存直接编译，或者改完只运行不编译，看看会怎样。

    有基础的同学可能会问：老师，你还没配环境变量，怎么就能直接用 javac 了？那是老版本教程的做法，新版 JDK 不太一样，第 5 节揭晓。

    更正：class 文件是给谁看的 操作系统真正能直接执行的是 CPU 的机器码，而 javac 生成的 class 文件里是字节码，操作系统也不认识它。读懂字节码的是 JVM（Java 虚拟机）：java HelloWorld 这条命令先启动 JVM，再由 JVM 去读 class 文件，翻译成当前系统的机器码来执行。正因为中间多了 JVM 这一层，同一个 class 文件才能拿到 Windows、Mac、Linux 上都能跑，这就是后面 P15 要讲的"跨平台"。
    用记事本打开 class 文件，最前面 4 个字节永远是 CA FE BA BE（"咖啡宝贝"），JVM 靠它认出这是 class 文件。在上面的模拟器里编译后点一下 class 文件可以看到。
    这三行大概在说什么（先混个脸熟） 第 1 行定义了一个叫 HelloWorld 的类，Java 代码都写在类里；第 2 行是 main 方法，程序从这里开始执行，这一行目前照抄就行；第 3 行把括号里的内容打印出来并换行（println = print line）。后面讲到类和方法时会逐个解释。还有一条规则视频这里没提：public class 后面的类名必须和文件名一模一样（包括大小写），否则编译报错。
    新版本的小捷径 从 JDK 11 开始，可以跳过 javac，直接 java HelloWorld.java：JVM 会在内存里先编译再运行，不会生成 class 文件。适合试一小段代码，但正经项目还是要先编译。模拟器里也能试。
    用 Mac 的话 Mac 自带的"文本编辑"默认存成富文本，写代码前要在菜单"格式"里选"制作纯文本"，否则 javac 读不了。更省心的是装一个代码编辑器（比如 VS Code）。编译运行在终端里进行，命令完全一样：cd 到代码文件夹，javac HelloWorld.java，java HelloWorld。
    第 4 节 · P9

    常见小问题：bug 从哪来，怎么改

    初学时出各种问题很正常，别慌、别怂，心态稳住慢慢解决，这是每个程序员的必经之路。代码出了问题，程序员一般说"出了个 bug"。bug 原意是小甲虫，为什么和程序出错扯上关系？传说早期计算机体积很大，有一天一只虫子钻了进去，导致计算机不能正常运行，工作人员排查时被问"出了什么问题"，回答就是"bug"。从此 bug 就表示程序里的问题。

    面对 bug，要慢慢培养三种能力，都需要时间沉淀：

    • 识别 bug：多看老师写的代码，也多看自己写的代码；
    • 分析 bug：多思考，多查资料；
    • 独立解决 bug：每次解决完多总结，下次再遇到就能很快搞定。
    补充：真实的 bug 故事 1947 年 9 月 9 日，哈佛大学的 Mark II 计算机出故障，操作员在一个继电器里找到一只飞蛾，把它用胶带贴在工作日志上，旁边写着"First actual case of bug being found"（第一次真的找到了虫子）。这个故事因计算机先驱格蕾丝·霍珀（Grace Hopper）常讲而出名。不过"bug"指机器故障的说法更早就有了，19 世纪爱迪生就这么用过，所以日志里才会写"真的"找到了虫子。这页日志连同飞蛾现在保存在美国国家历史博物馆。

    HelloWorld 里最常见的两个问题：

    1. 标点符号用了中文的。代码里所有标点必须是英文状态的。中文分号 ； 比英文分号 ; 胖一圈，老师说"天朝的伙食好，标点符号也胖一点"。编译时会报"非法字符"，下面还有个 ^ 箭头指着出错的位置。
    2. 单词拼写/大小写错了。该大写的地方一定要大写，比如 System 的 S。写成小写，报错会说第 3 行有问题，箭头指的地方附近就是错误所在。

    两个顺手的小技巧：

    • 输入法设置"中文时使用英文标点"：老师用的搜狗输入法，右键 → 属性设置 → 常用 → 勾上它。以后在中文输入状态下打出来的也是英文标点，从根上避免第一个问题。
    • 在文件夹地址栏输入 cmd 回车：打开的 CMD 直接就在这个文件夹里，不用再切盘符、cd 一层层进去。

    动手：埋个 bug，看 javac 怎么说

    点一个按钮，代码会被改成对应的错误写法并自动保存。然后点 javac HelloWorld.java，读读报错：第几行、箭头指在哪、说的是什么。最后两个比较特别：一个编译能过、运行才报错；另一个是类名和文件名对不上。

    埋 bug：

    报错信息仿照 JDK 17 中文版的 javac，做了简化；模拟器只认识 HelloWorld 这种结构的代码

    读报错的小经验 javac 报错的格式是 文件名:行号: 错误: 描述，下面一行是出错的代码，再下面的 ^ 指着它发现问题的位置。先看第一条：后面的错误常常是第一条引起的连锁反应，改掉第一条，其余的可能一起消失。另外，println 里那个字母是小写的 L（line），不是大写的 i，这是新手非常高频的一个错。
    第 5 节 · P10

    环境变量：JAVA_HOME 的专业配法

    上一篇讲过，配置 Path 环境变量是为了在任意目录下都能打开指定的软件。回想写 HelloWorld 的过程，有点怪：我们在 F:\JavaSE\day01\代码 里用了 javac 和 java，可这两个工具在 JDK 安装目录的 bin 里，代码文件夹里根本没有，为什么能用？

    猜一下：是不是安装时 Java 帮我们把路径配进环境变量了？打开 Path 一看，在之前加的 QQ 路径上面，果然多了一条。把它复制到"此电脑"地址栏打开看看：Java 安装时把 java、javac 这几个命令做了一份"快捷方式"放进这个文件夹，再把这个文件夹配进了 Path。所以在任意目录都能用。

    但是要注意：自动配置的只有 4 个工具：java、javac、javaw、jshell。要用 bin 里的其他工具还是不行，所以需要自己手动配。

    手动配的最简单方式，是把 bin 的完整路径直接粘贴到 Path 的编辑框里，再上移到最上面。老师不推荐这样配 Java：Path 里有很多别的变量，直接在里面改，一不小心碰到别人的，系统里其他软件可能就打不开了。专业的做法分两步：

    1. 在系统变量里新建一个变量，名字叫 JAVA_HOME，值是 JDK 的安装目录，比如 E:\develop\jdk，注意不带 bin。（这是老师的路径，你要写自己电脑上的真实路径。）
    2. 编辑 Path → 新建，写 %JAVA_HOME%\bin，再上移到最上面。两个百分号中间写变量名，意思是"引用 JAVA_HOME 的值"，和后面的 \bin 拼起来，就是完整的 E:\develop\jdk\bin。

    为什么要多此一举建一个 JAVA_HOME？因为以后要学的其他开发软件也会依赖 JAVA_HOME，现在一次配到位，以后就不用再配了。

    动手：配 JAVA_HOME，看 Path 怎么展开

    开始时的 Path 和安装完 JDK 一样，第一条是 Java 自动配的。先试试 jar --version（bin 里的另一个工具），然后按老师的步骤：删掉自动配的那条 → 新建 JAVA_HOME → Path 里新建 %JAVA_HOME%\bin，再试一次。也可以故意把 JAVA_HOME 写成带 \bin 的，看看会发生什么。

      第 6 节 · P11

      高级记事本：Notepad++

      用 Windows 记事本写代码有点累：所有单词都是黑色的；报错说第 3 行出问题，还得一行一行数。现在代码少还好，要是 100 多行、告诉你第 78 行错了，难道也一行行数？能不能让有特殊含义的单词换个颜色、前面再显示行号？

      可以，换个高级记事本就行。它的特点是：前面有行号，Java 里的关键单词会高亮。市面上有很多种：Java 程序员常用的 EditPlus、Notepad++，前端程序员常用的 Sublime。用法都差不多，学会一个就行，这里以 Notepad++ 为例（课程资料里提供了安装包）。

      1. 安装：第一步选语言，选"中文（简体）"；之后一路下一步，只改安装路径。建议别装 C 盘，所有东西都装 C 盘电脑会变卡，统一放进开发软件的文件夹，老师装在 E:\develop\notepad。
      2. 设置（一定要做）：设置 → 首选项 → 左边选"新建"，中间格式选 Windows，语言选 Java，右边编码选 ANSI（使用本地默认编码），关闭。不设置的话，代码里就不能写中文；设置完之后新建的文件才生效，以前建的不行。
      3. 用它写代码：新建 HelloWorld.java，右键 → Edit with Notepad++。敲 public、class 时颜色马上就变了。这次双引号里可以写中文："你好老铁"。
      4. 更快打开 CMD：在 Notepad++ 顶部这个文件的标签上右键 → "打开所在文件夹（命令行）"，弹出的 CMD 已经在这个文件所在的路径。这是目前最快的方式。然后照常 javac、java，屏幕上就是"你好老铁"。

      动手：换成 Notepad++ 再写一遍

      这次编辑器带行号和高亮，代码里已经写好了中文。也可以点标题栏的"记事本 / Notepad++"来回切换对比。故意写错一处再编译，出错的行号会在左边标红，不用再数了。

      那为什么要设成 ANSI？这关系到编码，视频说后面会细讲。下面这个补充先把原理讲清楚：

      文件里存的其实是字节。编辑器按某种编码把"你好老铁"存成字节，javac 再按某种编码把字节读回文字。两边用的编码一样才对得上。

      编辑器把文件存成
      javac 读文件时按
      为什么是 ANSI，以及什么时候不该选它 "ANSI"在简体中文 Windows 上指的就是 GBK 编码。JDK 17 及以前的 javac 在中文 Windows 上默认按 GBK 读源文件，而 Notepad++ 和新版 Windows 记事本默认存成 UTF-8，两边对不上就会乱码甚至编译失败，所以老师让 Notepad++ 改成 ANSI，和 javac 保持一致。
      但从 JDK 18 开始，Java 的默认编码统一改成了 UTF-8。如果你装的是 21、25 这些新版本，反而应该保持 UTF-8，选 ANSI 会让中文报错。不管哪个版本，都可以在编译时明确告诉 javac 文件的编码：javac -encoding UTF-8 HelloWorld.java。以后用 IDEA 写代码，它会帮你处理好这件事。
      用 Mac 的话 Notepad++ 只有 Windows 版。Mac 上可以用 VS Code、Sublime Text 或 CotEditor，都有行号和高亮。Mac 系统默认编码就是 UTF-8，编辑器也默认存 UTF-8，两边天然一致，不会遇到上面的乱码问题。
      第 7 节

      小结

      JDK写 Java 要装的软件。路径不要有中文、空格、特殊符号；开发工具放同一个文件夹。工具都在 bin 里
      HelloWorld记事本写代码（后缀 .java）→ javac HelloWorld.java 编译出 .class → java HelloWorld 运行。有 c 有后缀，没 c 没后缀
      常见 bug中文标点（报"非法字符"）、大小写写错（如 system）。看报错的行号和 ^
      环境变量安装时只自动配了 java、javac、javaw、jshell。专业配法：新建 JAVA_HOME（不带 bin），Path 里加 %JAVA_HOME%\bin
      Notepad++有行号、有高亮。新建文件的编码设为 ANSI，才能在代码里写中文（JDK 17 + 中文 Windows 的情况）
      一句话 Java 程序要先用 javac 把 .java 翻译成 .class，再用 java 运行 class；这两个工具都在 JDK 的 bin 里，能在任意目录使用，是因为 bin 被配进了 Path。

      自测

      1. 编译和运行 HelloWorld 分别用什么命令？哪个要写后缀，哪个不写？
      编译 javac HelloWorld.java（带 .java 后缀），运行 java HelloWorld（不带后缀）。口诀：有 c 有后缀，没 c 没后缀。写成 java HelloWorld.class 会报"找不到或无法加载主类"。
      2. 改了双引号里的内容、也保存了，直接 java HelloWorld，打印出来的是新内容还是旧内容？
      旧内容。java 运行的是 class 文件，而 class 文件是上次 javac 时生成的。改了代码要先重新编译。（同理，没保存就编译，编译的也是硬盘上的旧版本。）
      3. 编译时报 错误: 非法字符: '\uff1b'，最可能是哪里错了？
      代码里用了中文分号 ；（它的 Unicode 编码就是 FF1B）。把它改成英文分号 ;。可以把输入法设为"中文时使用英文标点"来避免。
      4. JAVA_HOME 的值应该写到哪一层？Path 里该写什么？
      JAVA_HOME 写 JDK 的安装目录，不带 bin，例如 E:\develop\jdk；Path 里新建 %JAVA_HOME%\bin。如果 JAVA_HOME 带了 bin，展开后就成了 …\bin\bin，找不到工具。
      5. 装完 JDK 什么都没配，javac 就能用了，为什么还要手动配环境变量？
      安装程序只自动配了 java、javac、javaw、jshell 四个工具的路径，bin 里其他工具（如 jar、javadoc）用不了；另外以后的很多开发软件要靠 JAVA_HOME 找到 JDK。
