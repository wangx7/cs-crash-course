第 1 节 · P71

最基本的内存图

为了更好地理解方法的运行过程，讲三种内存：① 方法调用的基本内存原理；② 方法传递基本数据类型的内存原理；③ 方法传递引用数据类型的内存原理。中间还会从内存的角度讲一讲什么是基本数据类型、什么是引用数据类型，这一点很多同学会懵。

先回顾 Java 的内存结构：每款软件运行时都要占用一块内存，JVM 把自己这块空间分成了五个部分。目前只要知道前两个：

栈和方法有关：方法运行时要进栈；方法里所有代码运行完毕，就从栈里出去
堆和 new 关键字有关：只要看到 new，一定是在堆里开辟了一个新的小空间

先看最简单的一段代码：main 方法里定义一个变量 int number = 100;，再打印它。这块内存和堆有没有关系？没有，代码里没有 new，暂时用不到堆，只关注栈就行。

  • 程序刚开始运行，main 方法进栈，从上往下执行；
  • 第一行定义变量：main 方法里有了一块小空间，名字叫 number，类型限定为 int（以后只能存 int 类型的整数），100 就是真实存在这块小空间里的值；
  • 输出 number：找到这个变量，里面记录多少就打印多少；
  • main 方法里所有代码执行完毕，方法出栈。出栈之后变量还在吗？不在了，变量随之消失。
第 2 节 · P71

方法进栈与出栈：先进后出

把代码变复杂：main 调用了 eat，eat 里先调用 study，再打印"吃饭"，再调用 sleep。一共四个方法在运行，内存里是怎么回事？

先看一个图：子弹的弹夹。弹夹有个规则：先压进去的子弹最后打出，叫先进后出。栈里方法的运行和子弹类似：先调用方法一，方法一进栈；再调用方法二，方法二进去，压在方法一身上；再调用方法三，压在最上面，此时方法一身上压了两个人。出去的规则是在上面的先出去：方法三先出，然后方法二，这时方法一身上没人压着了，它才能出去。

过程和上一篇的"两个核心"完全对得上：看到方法就进入方法，就是进栈；方法执行完回到调用处，就是出栈后轮到它下面的那个方法继续执行。main 最先进栈、最后出栈。

栈是有限的 每调用一次方法，栈里就多一层；每层都要占一点内存，而栈的总大小是有限的（HotSpot 虚拟机每个线程默认约 512 KB ~ 1 MB）。如果方法一直调用下去不返回，比如 eat() 的方法体里又写了一句 eat();，栈很快被压满，程序抛出 StackOverflowError（栈溢出）。那个著名的程序员问答网站 Stack Overflow，名字就是这么来的。方法自己调用自己叫递归，课程后面讲算法时会学怎么正确地用它。
第 3 节 · P72

什么是基本数据类型和引用数据类型

看参数传递的内存之前，必须先弄明白这件事，否则下面的内存没法学。以前说过：基本数据类型就是四类八种，除此之外的其他所有类型都是引用数据类型。这属于强行记忆，没有抓到本质。说到本质，还是要看内存图。

基本数据类型：int a = 10; 就是在内存中给变量 a 开辟一块空间，名字叫 a，能存 int 类型的整数，而 10 就是真实存在这块小空间里的数据。再定义 double b = 20.0; 也一样：再开辟一块空间叫 b，20.0 真实地存在里面。所以：基本数据类型的变量里，存储的是真实的数据。

引用数据类型：记住一句话，只要是 new 出来的，都是引用数据类型。目前对我们来说只有一个：数组。比如 int[] arr = {1, 2, 3};，这是静态初始化的简写，看着没有 new，但完整格式里有。它在内存里是这样的：

  • main 方法先进栈；等号左边，在栈里定义了一个变量 arr；
  • 等号右边有 new，在堆里开辟一块空间。堆里的空间都有地址值，假设是 0x0011。因为是 int 类型的数组，有 0、1、2 三个索引，默认初始化值三个 0；用的是静态初始化，默认值立马被 1、2、3 替代；
  • 重点：变量 arr 里记录的并不是数组里真实的数据 1、2、3，而是那块空间的地址值。想获取数组里的数据，只能先通过 arr 找到堆里的数组，再通过索引拿数据。

当一个变量里存储的不是真实的数据，而是其他空间的地址值时，这个变量就称为引用数据类型。这里的"引用"，可以理解成使用其他空间中的数据。还不理解？讲个小故事：你和你的好基友经常在一起。你用自己的钱，这是基本操作；你用了好基友的钱，这就叫引用。引用，就是拿别人的去用。

基本数据类型

  • 数据值存储在自己的空间中，不和其他空间产生关系；
  • 赋值给其他变量，赋的也是真实的值。int a = 10; int b = a; 交给 b 的就是 10，之后修改 b，不会影响 a。

引用数据类型

  • 数据值存储在其他空间中，自己空间里存的是地址值；
  • 赋值给其他变量，赋的是地址值。int[] arr2 = arr1; 之后两个变量指向同一个小空间，谁改了里面的数据，另一个再访问就是修改之后的结果。

"new 出来的"之外还有一个熟面孔 String 也是引用数据类型，虽然平时写 String s = "abc"; 时看不到 new。四类八种（byte、short、int、long、float、double、char、boolean）之外的全是引用类型，这句"强行记忆"的话本身没错；内存图只是告诉你它们为什么不一样。地址值 0x0011 是示意，真实程序里打印数组看到的是 [I@ 加一串十六进制数。
第 4 节 · P73

传递基本数据类型

验证一下是不是真听懂了。看这段代码，结果是什么？

public static void main(String[] args) { int number = 100; System.out.println("调用change方法前：" + number); change(number); System.out.println("调用change方法后：" + number); } public static void change(int number) { number = 200; }

第一次打印想都不用想，是 100。然后把 number 记录的数据作为实际参数交给 change，方法里把 number 改成 200。注意这个 number 是 change 方法里的 number，和上面 main 里的 number 没关系。change 执行完回到调用处，再打印 main 里的 number：是 100 还是 200？运行一下：两次都是 100。

画内存图解释。代码里没有 new，只看栈：

  • main 进栈，定义变量 number 记录 100，打印 100；
  • 调用 change，change 方法进栈。change 里也有一个变量 number（形参），记录的是传递过来的 100；
  • number = 200; 是把 200 赋给 change 方法里的 number。会影响 main 里的 number 吗？不会，变量是有作用范围的，只在所属的方法里有效；
  • change 执行完出栈，回到调用处继续往下，再打印 main 里的 number，还是 100。
结论一 传递基本数据类型时，传递的是真实的数据，形参的改变，不影响实际参数的值。

就是想让 main 里的 number 变成 200，有办法吗？有。把 change 里修改之后的 number 返回给调用处：调用处那一行方法的结果就是 200，还要再把 200 赋值给 number，原来的 100 才会被覆盖：

public static void main(String[] args) { int number = 100; System.out.println("调用change方法前：" + number); // 100 number = change(number); System.out.println("调用change方法后：" + number); // 200 } public static int change(int number) { number = 200; return number; }

第 5 节 · P73

传递引用数据类型

如果传递的不是基本数据类型，而是引用数据类型呢？

public static void main(String[] args) { int[] arr = {10, 20, 30}; System.out.println("调用change方法前：" + arr[1]); change(arr); System.out.println("调用change方法后：" + arr[1]); } public static void change(int[] arr) { arr[1] = 200; }

调用前打印 1 索引，肯定是 20。调用 change 之后再打印，是 20 还是 200？这次内存和堆有关系了（数组有 new），栈和堆都要看：

  • main 进栈。等号左边定义变量 arr；右边在堆里开辟空间，存 10、20、30，假设地址值是 0x0011，通过赋值运算符交给 arr；
  • 打印 arr[1]：通过 arr 找到堆里的空间，1 索引是 20；
  • 调用 change，change 进栈。调用时把 arr 记录的值传过去，而 arr 记录的是地址值 0x0011，所以 change 的形参里也是 0x0011。此时形成了两个变量指向同一个空间；
  • arr[1] = 200; 可以理解成：把 200 赋给 0x0011 的 1 索引。堆里那块空间的 1 索引变成了 200；
  • change 出栈，回到调用处。用 main 里的 arr 再获取 1 索引，拿到的就是修改之后的结果：200。
结论二 传递引用数据类型时，传递的是地址值，形参的改变，影响实际参数的值。

两个结论合起来：基本数据类型的空间里存的是真实的数据，所以传递的是真实的数据值，把 10 赋过去，对原来的变量没有任何影响；引用数据类型传递的不是真实的数据，而是地址值，把 0x0011 赋过去，相当于两个变量指向了同一个空间，使用的是同一个东西，不管谁对那块空间做了改变，另一个再访问，都是修改之后的结果。这个过程稍微有点复杂，可以多听两遍加深理解。

动手：把数组传给方法

更正："形参的改变影响实参"说得不够准 结论二里真正被改的，是形参指向的那个数组里的数据，不是形参这个变量本身。区别在上面演示的第二段程序里：如果 change 里写的是 arr = new int[]{7, 8, 9};，这才是"改变形参"，让它记录了一个新的地址值。结果呢？main 里的 arr 一点没变，还是指向原来的 {10, 20, 30}。

所以更准确的说法是：Java 只有值传递。不管什么类型，传给方法的都是实参变量里存的那个值的一份拷贝：基本类型拷贝的是数据，引用类型拷贝的是地址值。方法拿着拷贝来的地址能找到同一个数组、改里面的数据（结论二）；但它把自己手里的拷贝换成别的地址，外面的变量并不知道。和结论一其实是同一条规则。
第 6 节

小结

栈方法被调用就进栈，执行完出栈；先进后出，最上面的是正在执行的方法
变量在所属方法的栈空间里，只在这个方法里有效；方法出栈，变量随之消失
堆new 出来的都在堆里，有地址值
基本数据类型变量里存真实的数据；赋值、传参给的都是数据值，互不影响
引用数据类型变量里存其他空间的地址值；赋值、传参给的是地址值，两个变量指向同一个空间
传 int方法里改形参，外面不变；想要结果就 return 回来再赋值
传数组方法里通过形参改数组里的数据，外面再访问是修改之后的结果
一句话 传参就是把实参变量里存的东西抄一份给形参：抄的是数据，各改各的；抄的是地址，改的就是同一个数组。

自测

1. main 调用 a()，a 里调用 b()，b 里调用 c()。c 正在执行时，栈里从下到上依次是什么？谁最先出栈？
从下到上：main、a、b、c。c 最先出栈，然后 b、a，main 最后。先进后出。
2. 从内存的角度说，基本数据类型和引用数据类型的区别是什么？
基本数据类型的变量里存的是真实的数据；引用数据类型的变量里存的是其他空间的地址值，真实的数据在那块空间（堆）里。
3. int a = 10; int b = a; b = 20; 之后 a 是多少？int[] x = {10}; int[] y = x; y[0] = 20; 之后 x[0] 是多少？
a 还是 10：赋给 b 的是真实的值 10，之后各改各的。x[0] 是 20：赋给 y 的是地址值，x、y 指向同一个数组。
4. 方法 public static void add(int n) { n = n + 1; }，main 里 int n = 5; add(n); System.out.println(n); 打印几？怎么改才能打印 6？
打印 5。add 里的 n 是 add 自己的变量，改它不影响 main 里的 n。改法：add 返回结果 return n;（返回值类型改成 int），main 里写 n = add(n);。
5. 方法 public static void clear(int[] arr) { arr[0] = 0; }，main 里 int[] arr = {9, 9}; clear(arr); 之后 arr[0] 是多少？为什么不需要返回值？
0。传过去的是地址值，clear 里的 arr 和 main 里的 arr 指向堆里同一个数组，方法直接改了那块空间里的数据，main 再访问就是修改之后的结果。
