第 1 节 · P30

运算符和表达式

第三天的内容很"快乐"：很多东西小学、初中数学里都见过，主要看它们在代码里有什么不一样。先看两个概念：

  • 运算符：对字面量或者变量进行操作的符号；
  • 表达式：用运算符把字面量或变量连接起来、符合 Java 语法的式子。不同运算符连接的表达式，是不同类型的表达式。
int a = 10; int b = 20; int c = a + b; // + 是运算符（算术运算符）；a + b 是表达式（算术表达式） // 变量 c 记录了右边这个表达式的最终结果

一共要学六种运算符：算术运算符、自增自减运算符、赋值运算符、关系运算符、逻辑运算符、三元运算符。最后还会学运算符的优先级，看谁先算。

第 2 节 · P30

加减乘除和取模

算术运算符有 + - * / %，基本用法参见小学数学。在 day03-code 模块里建包 com.itheima.arithmeticoperator，新建类 ArithmeticDemo1 来试。

  • 乘号不是 ×，是 *（Shift+8）；除号是 /（右边 Shift 左边的那个键）。运算符前后一般加个空格，读起来更清楚。
  • 3 + 2 = 5，5 - 1 = 4，7 * 9 = 63，和小学一模一样。

细节一：有小数参与计算，结果有可能不精确。1.1 + 1.01 本该是 2.11，运行结果却是 2.1100000000000003。不只是加法，加减乘除都可能这样。但只是"有可能"：1.1 + 1.1 就正好是 2.2。原因涉及小数在计算机里的存储方式，比较难，放到进阶再讲，现在先记住结论。

细节二：整数参与计算，结果只能得到整数。10 / 2 是 5，10 / 3 按小学应该是 3.333…，运行结果却是 3。想要小数，必须有小数参与计算：10.0 / 3 得 3.3333333333333335，最后一位的 5 又是"不精确"在作怪。需要精确计算要用后面的知识。

取模 %，也叫取余：做的也是除法，只不过得到的是余数。10 % 2 商 5 余 0，结果 0；10 % 3 商 3 余 1，结果 1。取模的应用场景：

  1. 判断 A 能不能被 B 整除：A % B 是不是 0；
  2. 判断 A 是不是偶数：A % 2 为 0 是偶数，为 1 是奇数；
  3. 斗地主发牌：给每张牌编个序号，序号 % 3 为 1 发给第一个玩家，为 2 发给第二个，为 0 发给第三个（以后有这个练习）。

动手：Java 计算器（会按 Java 的规矩算）

选两个数的类型、填值、选运算符。下面会显示 Java 算出来的结果，以及类型是怎么提升的（第 4 节会讲）。先点几个例子。

补充：负数取模、除以 0 Java 里 % 的结果符号跟着被除数走：-10 % 3 是 -1，10 % -3 是 1。所以判断奇数最好写 a % 2 != 0，而不是 a % 2 == 1（负奇数取模得 −1）。
整数除以 0 会让程序崩溃（ArithmeticException: / by zero）；小数除以 0 不会崩，得到 Infinity（无穷大），0.0 / 0 得到 NaN（不是一个数）。上面的计算器都能试。
第 3 节 · P30

练习：数值拆分

需求键盘录入一个三位数，拆分出它的个位、十位、百位，打印在控制台。比如输入 123：个位 3，十位 2，百位 1。

分析：键盘录入用 Scanner。怎么拆？提示：整数相除只能得到整数，这个结果就是商；% 做的也是除法，得到的是余数。

  • 个位：123 % 10，123÷10 商 12 余 3，取余数 3。
  • 十位：先除 10 再模 10。123 / 10 得商 12，12 % 10 得 2。
  • 百位：先除 100 再模 10。123 / 100 已经是 1 了，最后的 % 10 可以不写，但建议补上：这样就是一个完整的公式，千位、万位都能往下推。
个位：数字 % 10 十位：数字 / 10 % 10 百位：数字 / 100 % 10 千位：数字 / 1000 % 10 ……

练习放在新包 com.itheima.test 里（包名用来区分演示和练习）。用 IDEA 写 Scanner 不用自己导包，它会自动加上。

public class Test1 { public static void main(String[] args) { // 键盘录入一个三位数，获取其中的个位、十位、百位 Scanner sc = new Scanner(System.in); System.out.println("请输入一个三位数"); int number = sc.nextInt(); int ge = number % 10; int shi = number / 10 % 10; int bai = number / 100 % 10; System.out.println(ge); System.out.println(shi); System.out.println(bai); } }

第 4 节 · P31

隐式转换：小的自动变大

算术运算符的高级用法有三种情况：数字相加、字符串相加、字符相加。这一节先说数字相加。"1+1=2 就这？"来看看代码里加法的险恶：

  • int a = 10; double b = 12.3;，a + b 的结果是什么类型？22.3 是小数，所以是 double，没问题。
  • int a = 10; double b = 20.0;，a + b 呢？结果 30.0，说是 int 和 double 好像都解释得通。所以要学规则。

规则：数字运算时，数据类型不一样不能直接运算，需要先转成一样的类型。转换有两种：

  • 隐式转换（也叫自动类型提升）：取值范围小的 → 取值范围大的。不需要我们写代码，程序自动完成。
  • 强制转换：取值范围大的 → 取值范围小的。下一节讲。

取值范围从小到大：

byte<short<int<long<float<double

比如 int a = 10; double b = a;，以前看这行肯定有问题（类型不一样怎么赋值），现在能解释了：a 的取值范围小，赋值给范围大的 b 时，a 里记录的 10 自动提升为 10.0，b 里就是 10.0。就像把 1 升水倒进 8 升的盆里，最多盆没装满，水不会洒。

有了隐式转换，不同类型的数据才能一起计算。计算时有两条提升规则：

  1. 取值范围小的和取值范围大的一起算，小的先提升为大的，再计算。int a + double b：a 先变成 double，相当于两个 double 相加，结果 double。
  2. byte、short、char 三种类型在运算时，都会先直接提升为 int，再计算。所以 byte a = 10; byte b = 20;，a + b 的结果是 int，不是 byte！（char 怎么提升，下一篇讲字符相加时说。）

第 5 节 · P31

强制转换：大的硬塞进小的

把取值范围大的数据赋值给取值范围小的变量，不允许直接赋值。一定要这么做，就加上强制转换，需要自己手动写：

目标数据类型 变量名 = (目标数据类型) 被强转的数据; double a = 12.3; int b = (int) a; // 想转成什么类型，括号里就写什么类型

注意：强制转换有可能导致数据发生错误。用 8 升的盆往 1 升的杯子里倒水，盆里超过 1 升，水就洒了。比如 int a = 300; 强转成 byte：byte 最大只到 127，数据就错了。具体原理视频说放到第二阶段讲，本站的 P38 原码反码补码那篇已经讲了，下面的演示也能直接看到。

练习：

byte b1 = 10; byte b2 = 20; int result = b1 + b2; // 没问题：b1、b2 先提升为 int，结果是 int byte result = (byte) b1 + b2; // 红色波浪线！只强转了 b1，加完还是 int byte result = (byte) (b1 + b2); // 正确：先算括号里的，再把整体结果强转成 byte

把 result 改成 byte 类型时，等号右边要转的是 b1 + b2 的整体结果，所以要用括号把它们括起来。运行结果 30 没问题；把 b1、b2 都改成 100，结果不是 200，而是 -56：200 超出了 byte 的范围，数据过大，强转后就错了。

动手：强转到底丢了什么

整数强转成更小的类型时，Java 只是把多出来的高位字节直接砍掉，留下的那几个字节重新解读成新类型。小数转整数则是直接丢掉小数部分。

()
补充：为什么 200 变成了 −56 200 的 int 是 32 位：00000000 00000000 00000000 11001000。强转成 byte 只留最后 8 位 11001000。byte 的最高位是符号位，1 表示负数，按补码解读，11001000 就是 −56（200 − 256 = −56）。同理 300 留下 00101100，变成 44。
小数强转整数是直接截掉小数部分，不是四舍五入：(int) 12.7 是 12，(int) -12.7 是 −12。想四舍五入要用 Math.round，P155 会学。
第 6 节

小结

算术运算符+ - * / %。有小数参与，结果可能不精确；整数相除只得整数（商）；% 取余数
取模用途判断整除（余数为 0）、判断奇偶（% 2）、按序号分组发牌
数值拆分个位 % 10，十位 / 10 % 10，百位 / 100 % 10
隐式转换小 → 大，自动。范围 byte < short < int < long < float < double。小的和大的算，小的先提升；byte、short、char 运算时先提升为 int
强制转换大 → 小，手动：(目标类型) 数据。转整体结果要加括号；数据过大会出错
一句话 不同类型先统一再计算：小的自动往大的提升（byte、short、char 直接到 int）；大的往小的塞要自己写强转，装不下就会出错。

自测

1. System.out.println(10 / 3); 和 System.out.println(10.0 / 3); 分别打印什么？
3 和 3.3333333333333335。整数相除只得整数；有小数参与才有小数，而且小数的结果可能不精确。
2. 怎么拿到 4567 的十位和千位？
十位 4567 / 10 % 10 = 6；千位 4567 / 1000 % 10 = 4。
3. byte b1 = 10; byte b2 = 20; byte r = b1 + b2; 为什么报错？
byte 参与运算时会先提升为 int，b1 + b2 的结果是 int，不能直接赋值给 byte。要写 byte r = (byte) (b1 + b2);
4. int i = 10; long n = 100; double d = 20.0;，i + n + d 是什么类型？说出提升过程。
从左到右：i + n，int 提升为 long，结果 long；long + d，long 提升为 double，结果 double。
5. (byte) (100 + 100) 是多少？为什么不是 200？
−56。byte 的范围是 −128 ~ 127，200 装不下；强转时只保留最低 8 位 11001000，按补码解读是 −56。
