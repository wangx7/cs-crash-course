第 1 节 · P63

什么是方法

这一章学四块：什么是方法、方法的格式、方法的重载，最后额外扩展方法的内存。先说第一块。

方法（method）是程序中最小的执行单元。之前写 HelloWorld 时，public static void main(String[] args) { … } 这一整个就叫 main 方法，也叫主方法。想一想：程序运行后，main 方法里的两条输出语句，能不能只让它运行其中一条？不行，它们是一起执行的，不能拆开。我们自己定义的方法也一样，里面的代码要么全都执行，要么全都不执行。

方法有什么用？举个例子：用输出语句描述打一局游戏：选人物、准备开局、对线、崩盘、骂队友、送人头、GG，一共七行打印（老师强调这都是他朋友干的事）。如果要打两局呢？把七行打印再写一遍当然可以，但代码重复了，太麻烦。改进的办法是：把重复的代码打包，给这个整体起个名字，比如 playGame。想打一局，调用一次 playGame；想打两局，调用两次。右边打包起来的这个整体，就是方法。

不用方法：打两局要写 14 行

System.out.println("选人物");
System.out.println("准备开局");
……（共 7 行）
System.out.println("选人物");
System.out.println("准备开局");
……（又是 7 行，重复）

用方法：打包一次，调用两次

playGame
System.out.println("选人物");
System.out.println("准备开局");
……（共 7 行，只写一遍）
playGame();
playGame();

实际开发中什么时候用？再举个例子：植物大战僵尸里很多植物都能发射子弹。豌豆射手发射子弹的代码写了 20 行，寒冰射手又写 20 行，第三个植物还要 20 行……只要植物有发射功能，就得把这 20 行再写一遍，重复度太高。所以把发射炮弹的 20 行代码打包成方法：有发射功能的植物直接调用；来了第四个会发射的植物，再调用一次；第五个植物不能发射，那就不调用。

小结三个问题：

  • 什么是方法？程序中最小的执行单元。
  • 什么时候用？把重复的代码，或者具有独立功能的代码抽取到方法中，以后要用不需要再写，直接调用。
  • 有什么好处？① 提高代码的复用性；② 提高代码的可维护性：以后代码有问题，只改方法里面，调用方法的地方不用动。
第 2 节 · P64

最简单的方法定义和调用

方法就是把一些代码打包在一起，用到时调用。所以格式只要学两点：

  • 怎么把代码打包：方法的定义；
  • 打包好之后怎么用：方法的调用。方法定义之后不会主动运行（它比较害羞），需要手动调用才会执行里面的代码。

方法的定义格式其实只有一种，但比较复杂，所以拆成三部分由浅入深：最简单的 → 带参数的 → 带返回值的，学完再三者合一。先看最简单的：

// 定义 public static void 方法名() { 方法体（就是打包起来的代码）; } // 调用 方法名();

小括号里什么都不写；大括号里打包起来的代码，专业的叫法是方法体。方法名要见名知意、驼峰命名（讲标识符时说过）：一个单词全部小写，多个单词从第二个单词开始首字母大写。

到 IDEA 里写一遍，注意两件事：

  • 位置：方法要定义在 main 方法的外面、类的里面。
  • public static void 记不住？它和 main 方法前面的三个单词一模一样，选中复制下来就行。
public class MethodDemo1 { public static void main(String[] args) { // 目标：掌握最简单的方法定义和调用的格式 playGame(); // 调用方法 playGame(); // 想打两局，就再调用一次 } // 定义一个方法 public static void playGame() { System.out.println("选人物"); System.out.println("准备开局"); System.out.println("对线"); System.out.println("崩盘"); System.out.println("骂队友"); System.out.println("送人头"); System.out.println("GG"); } }

如果只定义、不调用，运行后控制台什么都没有。因为程序运行时先找 main 方法（程序的主入口），而 main 方法里一行代码都没写。在 main 里写上 playGame();，七个打印语句就全部执行；再复制一行，就是两局。还要注意：方法必须先定义才能调用，调用一个不存在的方法，程序会报错。

  1. 看到方法，就进入方法；

第 4 节 · P65

带参数的方法：形参与实参

还是一个小故事。小蔡说：我写了个方法可以求 10 和 20 的和，你要算可以直接调用。小黄说：我想算 20 和 30 的和，你这用不了。小蔡：别急，我给你改一下，把 num1、num2 改成 20 和 30。小黄：每算一组不同的数据就要改一次变量的值，你这代码不行，写得真低级。

为什么说它低级？如果有三个人同时要算，而且算的数都不一样，num1 和 num2 到底写多少？写多少都不合适。针对这种变量的值不确定的情况，一般这么办：把 num1、num2 这两个变量定义在小括号里，只定义、不给值。谁要调用这个方法，就必须给这两个变量赋值，赋多少就算多少：

// 定义：小括号里写参数，多个参数用逗号隔开 public static void getSum(int num1, int num2) { int result = num1 + num2; System.out.println(result); } // 调用：小括号里传值（或变量），多个之间也用逗号隔开 getSum(10, 20); // 相当于把 10 赋值给 num1，20 赋值给 num2 → 30 getSum(20, 30); // 50 getSum(30, 40); // 70

注意：小括号里有几个参数，调用时就必须传几个，多一个少一个都不行；数据类型也要对应，方法要两个 int，传小数过去也不行。在 IDEA 里试：getSum() 什么都不传，报错；getSum(10.1, 20.7)，类型不对应，也报错；getSum(10, 20)，打印 30。

两个专业名词

刚才把调用处写的值叫"参数"，方法定义时小括号里写的也叫"参数"，两个称呼重复了，要区分开：

  • 形参：全称形式参数，指方法定义中的参数（上面的 num1、num2）；
  • 实参：全称实际参数，指方法调用中的参数（上面的 10、20）。

于是刚才的规则可以简化成一句：方法调用时，形参和实参必须一一对应，否则程序报错。

"类型要对应"的准确范围 演示里你会发现：给 double 形参传整数 5 是可以的。这不是例外，而是 P30 讲过的隐式转换：int 可以自动提升成 double，所以 Java 允许。反过来把 10.1 传给 int 形参需要强制转换，会丢精度，Java 不会替你做，于是报错。"一一对应"更准确的说法是：个数相同，每个实参都能自动转换成对应形参的类型。

定义方法前先问自己两个问题

很多同学学到这里会问：以后定义方法，到底什么时候写参数、写几个？分享一个技巧，定义方法之前一定问自己：

  1. 我要干什么？答案一般从题目里找。它决定了方法体怎么写。
  2. 我干这件事需要什么才能完成？它决定了形参。

比如"描述玩一局游戏"：要干的事是打印几句话；需要什么？什么都不需要，所以定义成无参的。"求两个数的和"：要求和；需要什么？你得把这两个数给我，我才能求，所以要两个形参。

练习一：求长方形的周长，结果在方法中打印。我要干嘛？求周长。需要什么？长和宽，所以两个形参（写 int 或 double 都可以，这里用 double）：

public static void main(String[] args) { getLength(5.2, 1.3); // 13.0 } public static void getLength(double len, double width) { double result = (len + width) * 2; System.out.println(result); }

练习二：求圆的面积，结果在方法中打印。公式是半径的平方乘以 π。需要什么？有人说要两个：半径和 π。不对！每个圆的半径不一样，需要别人告诉我；但 π 不用别人告诉我也知道是 3.1415926…（不用那么精确，写 3.14 就行）。所以形参只要一个：

public static void main(String[] args) { getArea(1.5); // 7.065 } public static void getArea(double radius) { double result = radius * radius * 3.14; System.out.println(result); }
第 5 节 · P66

带返回值的方法：return

第三种，也是最完整的格式。先看场景：小美要算出公司每个季度的销售额，小呆要根据小美算的结果求全年销售总额。小呆说：老妹，算好的数据给我用一下，哥要算总和。可小美的方法是按前面学的写法，把季度总和直接打印在控制台的，于是她回答：这个结果我没法给你，你要用，自己运行一下到控制台里看。小呆火冒三丈。

小呆矫情吗？不是。实际开发中，方法都是一些相对独立的功能，我们希望调用方法之后，方法能把算出的结果交给我们，我们再根据这个结果做别的事。如果方法只是把结果打印到控制台，调用者就拿不到结果，也就没法接着往下做了。比如求季度营业额的方法调用四次，控制台上有四个数，可这不是我想要的，我想要的是拿到这四个结果，再求全年总额。

所以，方法的返回值就是方法运行的最终结果。要根据一个方法产出的结果去编写另一段代码逻辑，就必须定义带返回值的方法。格式在之前的基础上改两处：

public static 返回值类型 方法名(参数) { 方法体; return 返回值; }
  • 把 void 改成返回值类型：方法最终的结果是什么类型，这里就写什么数据类型；
  • 方法体最后多一个 return：表示返回，把后面的结果返回给方法的调用处。哪里调用方法，结果就返回给哪里。

调用方式也多了几种：

直接调用方法名(实参);对返回值不做任何处理。一般用在没有返回值的方法上
赋值调用数据类型 变量名 = 方法名(实参);把方法的结果赋值给左边的变量，后面想用结果直接用变量。最常用
输出调用System.out.println(方法名(实参));把方法调用写在输出语句里：先调用得到结果，再打印

案例：定义一个方法，求一家商场每个季度的营业额，再根据方法的结果计算全年总营业额。一个季度有三个月，所以方法有三个形参；结果是整数，返回值类型写 int（写 double 表示小数也行）：

public static void main(String[] args) { // 目标：掌握带返回值方法的定义和调用格式 int sum1 = getSum(10, 20, 30); // 第一个季度 int sum2 = getSum(20, 30, 40); // 第二个季度 int sum3 = getSum(20, 30, 40); // 第三个季度 int sum4 = getSum(20, 30, 40); // 第四个季度 int sum = sum1 + sum2 + sum3 + sum4; System.out.println(sum); // 330 } public static int getSum(int num1, int num2, int num3) { int result = num1 + num2 + num3; return result; // 返回给方法的调用处 }

字幕里只念出了第一个季度的实参 10、20、30，后三个季度的数字是这里随手填的。

参数和返回值的运行过程：调用 getSum(10, 20, 30)，相当于把 10 赋给 num1、20 赋给 num2、30 赋给 num3；三个形参有值了，方法体里算出 60；记住一句话：方法的返回值是返回给调用处的，所以 60 回到上面，再赋值给左边的变量 sum1。

第 6 节 · P66

练习：比较长方形面积，和第三个问题

需求：定义方法，比较两个长方形的面积。

很多同学刚拿到题目是这么想的（先说结论：这个思路是错的）：我要干嘛？比较两个长方形的面积。需要什么？两个长方形，那就是两个长、两个宽。于是：

// 不推荐的写法 public static void compare(double len1, double width1, double len2, double width2) { double area1 = len1 * width1; double area2 = len2 * width2; if (area1 > area2) { System.out.println("第一个长方形更大"); } else { System.out.println("第二个长方形更大"); } }

问题在哪？回忆刚学方法时说的：把重复的代码或具有独立功能的代码抽取到方法中。用这个思想再看上面的方法：

  • 里面有重复：求 area1 和求 area2 的两行，都是在求面积；
  • 需求一变就不行了：要比较三个、四个长方形呢？参数到底写多少个都满足不了。

正确的思路：只定义一个方法求长方形的面积，在调用处调用它拿到面积，再比较。也就是说，比较的代码不写在方法里，写在调用处。

这里要多问自己第三个问题：方法的调用处是否需要继续使用方法的结果？要用，方法必须有返回值；不用，可以写返回值，也可以不写（不写就在方法里直接打印）。这道题调用处拿到两个面积后还要比较，所以必须有返回值。至此，定义方法时完整的三个问题是：

① 我要干什么？决定方法体
② 我干这件事需要什么才能完成？决定形参
③ 调用处是否需要继续使用方法的结果？决定返回值
public static void main(String[] args) { double area1 = getArea(5.3, 1.7); // 9.01 double area2 = getArea(2.4, 2.7); // 6.48 if (area1 > area2) { System.out.println("第一个长方形更大"); } else { System.out.println("第二个长方形更大"); } } // 我要干嘛？求长方形的面积。需要什么？长和宽。调用处要不要用结果？要。 public static double getArea(double len, double width) { double area = len * width; return area; }

写的过程中有个小插曲：返回值类型一开始不知道写什么，先写了 void，结果 return area; 那行报错。void 表示方法没有返回值，return 后面却真的返回了一个结果，两边冲突了；把 void 改成真正的返回类型 double 就好。运行结果：第一个长方形更大。

第 7 节 · P67

完整格式与注意事项

方法其实只有一种格式，前面是为了好吸收才按情况分成三种。最完整的写法就是第三种：

public static固定格式 返回值类型没有返回值写 void 方法名见名知意，驼峰命名 (参数)没有参数就空着 { 方法体;打包起来的代码 return 返回值; }没有返回值可省略

定义方法的注意点：

  1. 方法不调用就不执行。字面意思：playGame 没被调用，里面的代码就不会执行。
  2. 方法与方法之间是平级关系，不能互相嵌套定义。平级：方法定义时没有上下顺序，自己写的方法甚至可以放在 main 方法上面；只是为了好读，一般第一个写 main（程序的主入口），下面才是自己的方法。不能嵌套：把一个方法定义在另一个方法的里面，语法错误。
  3. 方法的编写顺序和执行顺序无关。先定义 playGame1 再定义 playGame2，运行时不一定先执行 playGame1，要看调用顺序：谁先被调用，谁先执行。
  4. 返回值类型为 void 表示没有返回值，可以省略 return 不写。一定要写也可以，但后面不能跟具体的数据，只写 return;，此时表示结束方法（不写的话方法执行完自己也会结束，所以可以省略）。
  5. return 语句下面不能编写代码。return 表示结束方法，方法都结束了，下面的代码永远执行不到，属于无效代码，会报错。

关于 return 关键字再归纳一下：它不能单独存在，一定写在方法里。

  • 方法没有返回值：可以省略不写；写了就表示结束方法，后面不能跟数据。
  • 方法有返回值：必须写，有两层含义：结束方法，并返回结果。

用这些注意事项判断下面四段代码对不对（视频每题留五秒，让大家把答案打在弹幕里）：

public static void method() { System.out.println("方法执行了"); }
正确。最普通的、没有返回值的方法。
public static void method() { System.out.println("方法执行了"); return; }
正确。方法没有返回值时 return 也可以出现，后面不跟数据，表示结束方法。
public static void method() { return 100; }
错误。void 表示方法没有返回值，方法体里却真的把 100 返回了，两处冲突。
public static int method() { return 100; System.out.println("方法执行了"); }
错误。return 表示结束方法，它下面的代码永远执行不到，不能写。

四段代码在幻灯片上，字幕里没有念出来，这里按老师的讲解还原。

编译器到底会报什么 第三段的报错是 不兼容的类型: 意外的返回值（incompatible types: unexpected return value）；第四段是 无法访问的语句（unreachable statement）。还有一个常见的第五种错：返回值类型写了 int，却有某条执行路径走不到 return，比如只在 if 里 return、else 里什么都没写，报 缺少返回语句（missing return statement）。有返回值的方法，必须保证每条路最后都 return。
第 8 节

小结

方法程序中最小的执行单元；把重复的、或有独立功能的代码打包，提高复用性和可维护性
位置main 方法的外面、类的里面；方法之间平级，不能嵌套定义
最简单public static void 方法名() { … }，调用 方法名();；不调用不执行
执行过程看到方法进入方法；执行完回到调用处继续往下
带参数形参：定义中的参数；实参：调用中的参数；个数、类型一一对应
带返回值void 换成返回值类型，return 结果; 返回给调用处；直接 / 赋值 / 输出三种调用
三个问题我要干什么（方法体）→ 需要什么（形参）→ 调用处要不要用结果（返回值）
returnvoid 方法里可省略，写就是 return; 结束方法；有返回值必须写；return 下面不能有代码
一句话 方法就是起了名字的一包代码：形参是它要的东西，返回值是它交回来的东西，调用一次就完整执行一遍。

自测

1. 定义了方法 playGame，但 main 方法里一行代码都没写，运行后控制台有什么？
什么都没有。方法不调用就不执行；程序从 main 开始，main 里没有代码。
2. main 里依次是：打印 1、调用 m()、打印 2；m 里依次是：打印 3、打印 4。控制台输出的顺序？
1 3 4 2。看到方法进入方法，方法执行完回到调用处继续往下。
3. getSum(int num1, int num2)，下面哪些调用会报错：getSum()、getSum(10, 20)、getSum(10.1, 20.7)？num1 和 10 分别叫什么？
第一个（个数不对应）和第三个（类型不对应）报错。num1 是形参，10 是实参。
4. 定义"求圆的面积"的方法，为什么形参只要半径，不要 π？
形参是"我干这件事需要别人给我的东西"。每个圆半径不同，要别人告诉我；π 是固定的，不用别人给，直接写在方法体里。
5. "比较两个长方形的面积"，为什么不定义成四个参数的 compare，而是定义 getArea？
compare 里求面积的代码重复了两遍，而且换成比较三个、四个长方形就得改参数。getArea 只做"求一个长方形的面积"这一件独立的事并返回结果，比较放在调用处，几个长方形都能用。
6. 什么时候必须定义带返回值的方法？最常用哪种调用方式？
调用处需要根据方法的结果继续写别的代码时。最常用赋值调用：int sum = getSum(10, 20, 30);。
