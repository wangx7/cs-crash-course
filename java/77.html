第 1 节 · P77

练习六：数字加密

需求：某系统的数字密码是一个大于 0 的整数（可能是 123，可能是 1234，比如 1983），传输时采用加密方式。规则：先得到每一位数字，然后每位数都加上 5，再对 10 求余，最后将所有数字反转，得到一串新数。以 1983 为例：

原始数据1   9   8   3
每位加 56   14  13  8
对 10 取余6   4   3   8
反转8   3   4   6 → 加密结果 8346

很多同学会想：既然是加 5、对 10 取余、反转，那就对整数里的每一位分别操作。加 5 能做，取余能做，但反转怎么做？把它当成一个整数、一位位取出来操作的话，反转就不好办了。所以遇到要对一些数字批量操作的情况，一般都先把每一位放到数组里，再对数组里的每个元素操作。放进数组，反转就简单了，数组那章专门讲过。

"把整数的每一位放进数组"这一步非常难，放到最后写。先假设已经放好了，把最基本的逻辑规则写完：

// 1. 把整数里的每一位放到数组当中（先直接写出放好之后的结果） int[] arr = {1, 9, 8, 3}; // 2. 加密：一个循环只干一件事 for (int i = 0; i < arr.length; i++) { // 每一位加 5 arr[i] = arr[i] + 5; } for (int i = 0; i < arr.length; i++) { // 每一位对 10 取余 arr[i] = arr[i] % 10; } for (int i = 0, j = arr.length - 1; i < j; i++, j--) { // 反转 int temp = arr[i]; arr[i] = arr[j]; arr[j] = temp; } // 3. 把数组里的每一个数字拼接起来，变成加密之后的结果 int number = 0; for (int i = 0; i < arr.length; i++) { number = number * 10 + arr[i]; } System.out.println(number); // 8346

能不能一个循环把所有事做完？别忘了之前的建议：为了思路清晰，一个循环只干一件事，所以写三个循环。每写完一个就遍历打印验证一下：6 14 13 8 → 6 4 3 8 → 8 3 4 6。反转用的是两个指针：i 从 0 索引、j 从最大索引出发，交换后 i++、j--，i 小于 j 时才继续。

拼接怎么做？循环肯定逃不掉。在外面定义 number 记录最终结果，循环里 number = number * 10 + arr[i]。推导一下：一开始 number 是 0，0 × 10 + 8 = 8；第二次 8 × 10 + 3 = 83；第三次 83 × 10 + 4 = 834；最后 834 × 10 + 6 = 8346。

动手：加密、解密流水线

试试：加密 1983 · 解密 8346 · 加密 1985
这套规则有个漏洞：末位是 5 的密码解不回来 在上面试试"加密 1985"：末位 5 加 5 得 10，对 10 取余是 0，反转之后这个 0 跑到了最前面，数组是 0 3 4 6。可拼成整数时 0 × 10 + 3 = 3，开头的 0 没了，结果是 346，少了一位。再把 346 解密，得到的是 198，不是 1985。原因是整数没法记住开头的 0。真要用这套规则，加密结果得用数组或字符串保存（"0346"），不能拼回 int。题目的例子 1983 恰好避开了这种情况。
第 2 节 · P77

难点：把整数上的每一位都添加到数组

这是整道题最难的部分，单独新建一个类来写。先分享一个诀窍：比较难的题没有思路时，可以反向推导，从后往前想：

  • 最终要达到什么效果？把整数上的每一位都添加到数组当中；
  • 要完成这个效果需要什么？得先有一个数组，才能往里添加；
  • 数组怎么创建？静态初始化要知道所有元素，动态初始化要知道有几个元素。这个整数只知道大于 0，可能是 123，也可能是 12345，只能用动态初始化；
  • 动态初始化要写长度，长度不知道。再往前推一步：得先计算出数组的长度。

于是步骤就出来了：① 计算出数组的长度；② 定义数组；③ 把整数上的每一位都添加到数组。实际开发中很多复杂的问题都是用这种思想解决的：先确定最后一步要什么，再一步一步往前推。

第一步：数字有几位？定义计数器 count，写一个 while：判断条件先不管，先写循环体。每循环一次就去掉右边的一位：number = number / 10;（12345 → 1234 → 123 → 12 → 1 → 0），每去掉一位 count++。什么时候停？所有数字都去掉、number 变成 0 的时候，所以条件是 number != 0。12345 数出来是 5，123 是 3，一位数也能数对。（不要写 0，题目要求密码大于 0。）

第三步：添加。要先得到每一位，也可以用上面那样的循环。但这时还能从 number 身上取吗？不行，第一步的循环结束后 number 已经是 0 了。所以在第一步之前要再定义一个临时变量 int temp = number; 记录原来的值，让第一步去消耗 temp，第三步再用 number。

循环体：number % 10 得到个位，再 number / 10 去掉个位。得到的个位往数组里放，但没有变量能表示索引，那就定义一个 index（又是伪造索引）。一开始写 index 从 0 开始、每次 ++，遍历数组一看：5 4 3 2 1，反了！因为最先取出来的是最右边的 5，却被放到了最左边的 0 索引。所以不能正着添加，要倒着添加：index 的初始值是 arr.length - 1，每次添加完 index--。先取到 5 放在最大索引，再取到 4 放在倒数第二个……

int number = 12345; // 1. 计算出数组的长度 int temp = number; // 临时记录 number 的值，让下面的循环去消耗 temp int count = 0; while (temp != 0) { temp = temp / 10; // 每次循环去掉右边的一位 count++; // 去掉一位，计数器自增一次 } // 2. 定义数组（动态初始化） int[] arr = new int[count]; // 3. 把整数上的每一位都添加到数组当中 int index = arr.length - 1; // 倒着添加 while (number != 0) { int ge = number % 10; // 获取个位 number = number / 10; // 再去掉个位 arr[index] = ge; // 把个位添加到数组 index--; }

视频里是第一步消耗 number、第三步用 temp，这里把两个变量的角色对调了一下，效果相同，读起来更顺。

动手：一位一位拆

这部分加上上一节，就是完整的加密。课后先把两段分别写熟，再试试能不能自己独立地把它们合成一个完整的程序。如果听得懂、自己写却差点意思，说明思路还不够明确，回去再走一遍反向推导。

第 3 节 · P77

练习七：数字解密

需求：把上一题加密之后的数据解密出来。思路没错：把加密的过程反过来再做一遍。加密是 加 5 → 对 10 取余 → 反转，解密就是 反转 → 还原取余 → 减 5。

8346 先反转成 6 4 3 8；最后一步也简单，加密时加 5，解密时减 5。难的是中间：6 4 3 8 是"对 10 取余"得到的，怎么推回去？以 6 为例，什么数字对 10 取余是 6？6 可以，16、26、36、46 也都可以。到底是哪个？

要结合第一步"加 5"一起分析。取余之前的那一排数字都是某一位加 5 得来的。一位数字最大是 9，加 5 最大是 14；最小是 0，加 5 最小是 5。所以那一排数字一定在 5 ~ 14 之间，这样特点就清楚了：

  • 5、6、7、8、9 对 10 取余，还是它本身；
  • 10 ~ 14 对 10 取余，是去掉前面的 1，只留个位：0、1、2、3、4。

所以解密时判断一下：是 5 ~ 9，数字不变；是 0 ~ 4，加 10。

int[] arr = {8, 3, 4, 6}; // 1. 定义数组记录加密之后的结果 for (int i = 0, j = arr.length - 1; i < j; i++, j--) { // 2. 反转 → 6 4 3 8 int temp = arr[i]; arr[i] = arr[j]; arr[j] = temp; } // 3. 加密是对 10 取余得到的，解密时要判断：0 ~ 4 之间加 10，5 ~ 9 之间不变 for (int i = 0; i < arr.length; i++) { if (arr[i] >= 0 && arr[i] <= 4) { arr[i] = arr[i] + 10; // → 6 14 13 8 } } for (int i = 0; i < arr.length; i++) { // 4. 每一位减 5 → 1 9 8 3 arr[i] = arr[i] - 5; } int number = 0; // 5. 拼接成最终的结果 for (int i = 0; i < arr.length; i++) { number = number * 10 + arr[i]; } System.out.println(number); // 1983

在第 1 节的演示里切到"解密"，输入 8346，可以一步步看到 6 14 13 8 是怎么还原出来的。

第 3、4 两步可以合成一个式子 "0 ~ 4 先加 10，然后统一减 5"和"每一位加 5 再对 10 取余"是同一回事：arr[i] = (arr[i] + 5) % 10;。验证：6 → 11 % 10 = 1；4 → 9；3 → 8；8 → 13 % 10 = 3。也就是说，这套规则里加密和解密中间那步是同一个运算：一位数字加两次 5 等于加 10，对 10 取余后回到原地。课上分两步写，是为了练"根据取值范围倒推"的分析过程。
第 4 节 · P78

练习八：抽奖（抽到重复的就重抽）

需求：一个大 V 直播抽奖，奖品是现金红包，分别有 {2, 588, 888, 1000, 10000} 五个奖金。用代码模拟抽奖，打印出每个奖项，奖项的出现顺序要随机且不重复。比如：888、588、10000、1000、2（每次运行的结果可以不一样）。

说到抽取，第一反应是 Random。但它有个小弊端：这次随机到 1 索引抽出 588，下一次有可能还是 588。怎么屏蔽这个弊端？再定义一个新数组，一开始什么都不装。抽到 588，拿着它到新数组里判断有没有：没有，就添加进去；第二次又抽到 588，再去新数组里一查，已经存在了，这次就是无效的奖项，重新抽一次就是了。

  1. 定义数组表示奖池；
  2. 定义新数组，用于存储抽奖的结果（长度和奖池一样）；
  3. 抽奖：随机索引 → 拿到奖项 → 判断在新数组中是否存在：存在就重新抽取，不存在才是有效奖项，存进新数组；
  4. 遍历新数组。

"判断是否存在"先写成一个方法，就是 之前写过的 contains。第三步里有效奖项要做两件事：存进 newArr[i]，然后 i++。和评委打分一样，i++ 要从 for 的小括号里挪到 if 里面：抽到已存在的奖项时不会走进 if，i 不变，下一圈重新抽；只有抽到有效奖项，索引才移动。

public static void main(String[] args) { int[] arr = {2, 588, 888, 1000, 10000}; // 1. 奖池 int[] newArr = new int[arr.length]; // 2. 存储抽奖的结果 Random r = new Random(); // 3. 抽奖 for (int i = 0; i < 5; ) { // 有 5 个奖项，要存满 5 个 int randomIndex = r.nextInt(arr.length); // 随机索引 int prize = arr[randomIndex]; // 获取奖项 boolean flag = contains(newArr, prize); // 判断当前的奖项是否存在 if (!flag) { // 不存在：有效奖项 newArr[i] = prize; // 添加到 newArr i++; // 添加完毕，移动索引 } } for (int i = 0; i < newArr.length; i++) { // 4. 遍历 System.out.println(newArr[i]); } } // 判断 prize 在数组当中是否存在：存在 true，不存在 false public static boolean contains(int[] arr, int prize) { for (int i = 0; i < arr.length; i++) { if (arr[i] == prize) { return true; } } return false; }

对方法的结果做判断时，如果直接把方法调用写在 if 的小括号里看着眼晕，可以像上面这样先用变量 flag 接住，再判断变量。存在的情况什么都不用做，所以对 flag 取反，只写不存在时的代码。多运行几次，每次的顺序都不一样。

视频里变量名写的是 price（价格），按它的意思"奖项"，这里写成 prize。

第 5 节 · P78

优化：把奖池打乱

刚才的代码能用，但效率比较低。分析一下：假设前四次已经抽走了 588、1000、888、10000，现在是第五次。第五次只有抽到 2 才算有效，抽到别的都要重抽，而每次抽到 2 的概率只有 20%。甚至想一想：第五次有没有可能永远抽不到那个 2？有可能。

现实生活中抽奖是怎么做的？把奖池里的顺序打乱。所以第二个思路更简单，效率也高：

  1. 把奖池里的所有奖项打乱顺序（数组那章写过：遍历数组，拿 i 和随机索引上的值交换）；
  2. 遍历奖池，从 0 索引开始一个个拿出来，同样是随机且不重复的效果。
int[] arr = {2, 588, 888, 1000, 10000}; Random r = new Random(); // 1. 打乱顺序 for (int i = 0; i < arr.length; i++) { int randomIndex = r.nextInt(arr.length); // 随机索引 int temp = arr[i]; // i 和随机索引上的值交换 arr[i] = arr[randomIndex]; arr[randomIndex] = temp; } for (int i = 0; i < arr.length; i++) { // 2. 遍历奖池 System.out.println(arr[i]); }

这样不会出现无效的抽取，代码也更好理解。

动手：两种抽法比一比

arr（奖池）
newArr（抽奖结果）
方法一平均要抽多少次 第 1 个奖项一抽就中；抽第 2 个时 5 个里有 4 个有效，平均要 5/4 次；第 3 个平均 5/3 次；第 4 个 5/2 次；最后一个 5/1 = 5 次。加起来是 5 × (1 + 1/2 + 1/3 + 1/4 + 1/5) ≈ 11.4 次，而方法二永远是 5 次。奖项越多差距越大：100 个奖项时方法一平均要抽 500 多次（这个问题在数学上叫"集卡问题"）。点上面的"各跑 10000 轮"可以看到实测的平均值和最倒霉的一轮。
另外方法一还藏着一个前提：newArr 的默认值是 0，查重是拿奖项和这些 0 比的，所以奖池里不能有 0 这个奖项，否则它永远被当成"已存在"，程序会停不下来。

练习九：双色球（一）生成中奖号码

最后一个练习：模拟双色球。先说规则：投注号码由 6 个红色球号码和 1 个蓝色球号码组成。红球从 1 ~ 33 中选择，蓝球从 1 ~ 16 中选择。根据中了几个红球、蓝球中没中来定奖：

一等奖
6 + 1

6 + 0
最高 500 万
三等奖
5 + 1
3000 元
四等奖
5 + 0、4 + 1
200 元
五等奖

要学会找它们之间的关系：以六等奖为例，三种情况满足其中一个就算中；而每种情况里，红球个数和蓝球个数要同时满足。红球中 4 个、蓝球没中是五等奖；红球中 4 个、蓝球也中了，那就是 4 + 1，变成四等奖了。

整体三步：① 随机生成中奖号码；② 让用户输入自己买的号码；③ 两者比较，看中了几个红球、蓝球中没中，判断奖项。写代码时把规则截图放在旁边对照。

第一步用一个方法 createNumber 来写。中奖号码是 6 个红球加 1 个蓝球，用长度为 7 的数组存，方法返回这个数组。特点：红球号码不能重复（第一个是 1，第二个就不能再是 1）；蓝球可以和红球重复。

  • 红球：循环 6 次，放在 0 ~ 5 索引。r.nextInt(33) + 1 生成 1 ~ 33；用 contains 方法（和上一题一样）判断在数组里是否已存在，不存在才添加，添加之后 i 才 ++；
  • 蓝球：只有一个，r.nextInt(16) + 1，直接放到最大索引 arr[arr.length - 1]（写 6 也行）。
public static int[] createNumber() { int[] arr = new int[7]; // 1. 创建数组用于添加中奖号码：6 个红球 1 个蓝球 Random r = new Random(); // 2. 随机生成号码并添加到数组 for (int i = 0; i < 6; ) { // 红球：不能重复 int redNumber = r.nextInt(33) + 1; boolean flag = contains(arr, redNumber); if (!flag) { arr[i] = redNumber; // 不存在，才添加 i++; // 成功添加，索引才变化 } } int blueNumber = r.nextInt(16) + 1; // 蓝球：可以和红球重复 arr[arr.length - 1] = blueNumber; return arr; } // 判断数字在数组中是否存在 public static boolean contains(int[] arr, int number) { for (int i = 0; i < arr.length; i++) { if (arr[i] == number) { return true; } } return false; }

在 main 里调用并遍历打印，多运行几次：前 6 个是红球，没有重复；最后一个是蓝球，和红球重不重复都无所谓。

第 7 节 · P79

双色球（二）用户输入彩票号码

规则和刚才一样，也是 6 红 1 蓝、长度为 7 的数组，只是数据来源从 Random 换成了键盘录入。方法叫 userInputNumber，返回 int[]。

  • 提示语是"请输入第 i + 1 个红球号码"：i 从 0 开始，提示时一定要先加 1；
  • 用户输入的红球要做两个判断，同时满足才能添加：① 在 1 ~ 33 的范围之内；② 唯一、不重复（再调用一次 contains）。不满足就给出提示，i 不变，让用户重新输入同一个位置；
  • 蓝球只有一个，只判断范围 1 ~ 16。超出范围要让用户再录，所以把这一段用 while (true) 包起来，录对了就 break。
public static int[] userInputNumber() { int[] arr = new int[7]; // 1. 创建数组，用于添加用户购买的彩票号码 Scanner sc = new Scanner(System.in); // 2. 键盘录入 for (int i = 0; i < 6; ) { // 红球 System.out.println("请输入第" + (i + 1) + "个红球号码"); int redNumber = sc.nextInt(); if (redNumber >= 1 && redNumber <= 33) { // 要求一：在 1 ~ 33 之内 boolean flag = contains(arr, redNumber); if (!flag) { // 要求二：唯一不重复 arr[i] = redNumber; // 有效，添加到数组 i++; } else { System.out.println("当前红球号码已经存在，请重新输入"); } } else { System.out.println("当前红球号码超出范围"); } } System.out.println("请输入蓝球号码"); // 蓝球 while (true) { int blueNumber = sc.nextInt(); if (blueNumber >= 1 && blueNumber <= 16) { arr[arr.length - 1] = blueNumber; break; // 录对了，跳出循环 } else { System.out.println("当前蓝球号码超出范围"); } } return arr; }

嵌套一深，就容易不知道某个循环到哪结束。两个办法：用鼠标点一下左大括号，对应的右大括号会高亮；或者点循环左边的小箭头，把整个循环折叠起来，再接着往下写。包 while 循环的快捷键是选中代码后按 Ctrl + Alt + T。

测试：第一个红球输 100，提示超出范围，还是让你输第一个；输 1 之后第二个再输 1，提示已存在，继续输第二个；依次输 2、3、4、5、6，蓝球 6，数组里就是 1 2 3 4 5 6 6。

Mac 快捷键，以及一个更省事的生成办法 用语句包裹选中的代码 Ctrl+Alt+T → ⌥⌘T。
另外，生成红球可以用上一题"打乱"的思路：先做一个装着 1 ~ 33 的数组，打乱，取前 6 个，就是 6 个不重复的红球，不会有无效的随机。课上沿用查重的写法，是因为 33 个里抽 6 个很少撞上重复（平均只多抽 0.5 次左右），而且用户输入那一步本来就必须查重，两个方法的结构正好一样。
第 8 节 · P79

双色球（三）判断中奖情况

中奖情况分两部分分开判断：红球中了几个，蓝球中没中。先定义两个统计变量 redCount、blueCount，默认是 0，表示默认没有中。

  • 红球：遍历用户的红球（注意只到 length - 1，最后一个是蓝球），拿着每一个到中奖号码的红球里去找。有个细节：中奖号码是 1 2 3 4 5 6，用户买的是 6 5 4 3 2 1，这也算中。号码只要存在就算，不需要位置一样。所以要写循环嵌套：内循环遍历中奖号码的红球（同样到 length - 1），找到一样的就 redCount++，然后 break，后面的没必要再比，接着判断下一个红球。
  • 蓝球：直接比两个数组最大索引上的数字，相等 blueCount++。

测试时不知道中奖号码没法测，所以生成中奖号码之后先把它打印出来（上下打两行华丽的分隔线），对着号码去"买"。现实里要是也能这样该多美。测试要把所有情况都考虑到：全都不中（0 和 0）；全中但顺序不一样（6 和 1）；中一半（比如红球中 3 个，蓝球中 1 个）。

知道了两个个数，剩下的就是体力活：照着规则表写六个判断，最后 else 谢谢参与。一个奖项有多种情况时，每种情况用小括号括起来，中间用 ||。

public static void main(String[] args) { int[] arr = createNumber(); // 1. 生成中奖号码 System.out.println("============================"); // 测试用：先把中奖号码打印出来 for (int i = 0; i < arr.length; i++) { System.out.print(arr[i] + " "); } System.out.println("\n============================"); int[] userInputArr = userInputNumber(); // 2. 用户输入彩票号码 int redCount = 0; // 3. 判断中奖情况 int blueCount = 0; for (int i = 0; i < userInputArr.length - 1; i++) { // 红球：只看前 6 个 int redNumber = userInputArr[i]; for (int j = 0; j < arr.length - 1; j++) { if (redNumber == arr[j]) { redCount++; break; // 找到了，后面的没必要比了，跳出内循环，判断下一个红球 } } } int blueNumber = userInputArr[userInputArr.length - 1]; // 蓝球 if (blueNumber == arr[arr.length - 1]) { blueCount++; } if (redCount == 6 && blueCount == 1) { System.out.println("恭喜你，中奖1000万"); } else if (redCount == 6 && blueCount == 0) { System.out.println("恭喜你，中奖500万"); } else if (redCount == 5 && blueCount == 1) { System.out.println("恭喜你，中奖3000"); } else if ((redCount == 5 && blueCount == 0) || (redCount == 4 && blueCount == 1)) { System.out.println("恭喜你，中奖200"); } else if ((redCount == 4 && blueCount == 0) || (redCount == 3 && blueCount == 1)) { System.out.println("恭喜你，中奖10"); } else if ((redCount == 2 && blueCount == 1) || (redCount == 1 && blueCount == 1) || (redCount == 0 && blueCount == 1)) { System.out.println("恭喜你，中奖5"); } else { System.out.println("谢谢参与，谢谢惠顾"); } }

这一题代码量大，加起来大约 150 行。真写出来了，说明前六天的东西一点问题都没有。

第 9 节

小结

批量操作数字先把每一位放进数组，再对数组操作；一个循环只干一件事
拼成整数number = number * 10 + arr[i]
拆成数组先用 / 10 数出位数 → 动态初始化 → % 10 取个位，从最大索引倒着放
反向推导没思路时从最终效果往前推：要什么 → 为此先要什么
解密反转 → 0 ~ 4 的加 10（因为取余前一定在 5 ~ 14）→ 减 5
随机且不重复方法一：存进新数组前先 contains 查重，有效才 i++；方法二：打乱数组再遍历，效率高
双色球生成（红球查重）→ 输入（范围 + 查重，蓝球 while + break）→ 分开数红、蓝中奖个数 → 六个判断
红球比对不要求位置一样：循环嵌套，找到就 count++ 并 break
一句话 大程序都是小步骤拼起来的：先把每一步写成注释，难的那步单独拎出来，一个方法、一个循环只干一件事。

自测

1. 数组是 {8, 3, 4, 6}，循环执行 number = number * 10 + arr[i]，number 依次是多少？
8、83、834、8346。每次把已有的数字整体左移一位（乘 10），再把新的一位加在个位上。
2. 把 12345 的每一位放进数组时，为什么 index 要从 arr.length - 1 开始、每次 index--？
用 % 10 最先取到的是个位 5，它应该在数组的最右边（最大索引）。如果从 0 索引开始正着放，数组里会是 5 4 3 2 1，反了。
3. 解密时，反转之后数组里某一位是 2，取余之前它是多少？原始数字是多少？为什么能确定？
取余之前是 12，原始数字是 7。取余之前的数是"一位数字加 5"，只可能在 5 ~ 14 之间；个位是 2 的只有 12。所以 0 ~ 4 要加 10，再减 5。
4. 抽奖的方法一为什么效率低？方法二怎么做的？
方法一越到后面越容易抽到已经抽过的奖项，要反复重抽（最后一个奖项每次只有 20% 的概率抽中）。方法二直接把奖池数组打乱，再从 0 索引依次取，没有无效的抽取。
5. 判断红球中了几个时，为什么要写循环嵌套，而不是直接比较 userInputArr[i] == arr[i]？
中奖不要求位置相同：中奖号码 1 2 3 4 5 6，买的是 6 5 4 3 2 1 也算全中。所以要拿用户的每个红球到中奖号码的 6 个红球里挨个找，找到就 redCount++ 并 break。
6. 红球中 4 个、蓝球也中了，是几等奖？红球中 2 个、蓝球没中呢？
4 + 1 是四等奖（200 元）。2 + 0 不在任何奖项里：谢谢参与。六等奖的三种情况都要求蓝球中。
