第 1 节 · P12

Java 的前世今生：差点凉凉

Java 的诞生很有戏剧性，几次差点凉凉。

1990 年，Sun 公司（Stanford University Network 的首字母缩写，"斯坦福大学网络公司"）成立了 Green 计划，打算给下一代智能家电（电视机、微波炉、电话等）写一套通用的控制系统。负责人是 James Gosling（詹姆斯·高斯林），一位慈祥的白胡子老头，后来被称为"Java 之父"。

团队一开始想用 C++，但 C++ 在很多方面用着不方便，项目进展很慢。大神不愧是大神：语言不好用，就自己造一个。新语言叫 Oak（橡树），因为项目组门口长着一棵橡树。

1992 年，Green 计划已经做出了新平台的一部分：Green 操作系统、Oak 语言、类库等。Sun 看这个团队这么厉害，11 月专门成立了全资子公司 FirstPerson。可公司里大多是程序员，不太会管理，FirstPerson 因经营不善几乎凉凉，Oak 也差点跟着凉。

转机在 1994 年：互联网进入快速发展期，Gosling 很有商业眼光，立刻改写了 Oak，同年秋天做出了第一个用 Oak 写的网页浏览器 WebRunner，在当时是跨时代的产品。Sun 准备给 Oak 注册商标，却发现这个名字已经被一家投资公司注册了，只好改名。程序员爱喝咖啡，而盛产咖啡豆的地方叫爪哇岛（Java），于是就叫 Java。

1995 年 Java 正式推出，随后是 1.0、1.1、1.2、1.3、1.4。Sun 觉得每次只改小数点后一位太小家子气，从 5 开始改成大版本号，叫 Java 5.0；之后 6.0……2009 年 Sun 被 Oracle（甲骨文）收购。Oracle 当时是全球仅次于微软的软件公司，Java 在它手里市场份额越来越大，版本也一直在更新，到录课时最新是 Java 17。

点一点：Java 版本时间线

橙色 LTS = 长期支持版；虚线框是录课之后才出现、补充进来的版本

看这些版本的时间会发现：从 Java 9 开始，基本每 6 个月出一个版本。更新这么快是为了紧贴市场、不被淘汰，可对开发者来说学不过来。所以版本被分成两种：

  • 普通版，也叫过渡版本；
  • 长期支持版（LTS，Long-Term Support），可以理解成"正式版本"。上一篇下载时看到 17 后面带着 LTS，就是这个意思。Java 8、11、17 都是 LTS。

其中有三个版本特别重要：

  1. Java 5：第一个大版本号更新。
  2. Java 8：当时市场上绝大多数公司在用的版本，是 LTS，而且最稳定。
  3. Java 17：这门课学的版本。

也就是说，课里学的比很多公司正在用的还要新。后面会讲到不少新版本的特性，工作中可能暂时用不到，但它们代表趋势，以后一定会用到，到时候你就不慌了。

几处时间和细节 1995 年 5 月 23 日 Sun 在 SunWorld 大会上正式发布 Java，第一个正式的开发包 JDK 1.0 是 1996 年 1 月发的。WebRunner 后来改名叫 HotJava。Oak 不能用，一般的说法是这个商标已经属于一家叫 Oak Technology 的公司。Oracle 收购 Sun 是 2009 年 4 月宣布、2010 年 1 月完成的。严格说"半年一版"从 Java 10（2018 年 3 月）开始：9 和 8 之间隔了三年多。
录课之后：现在公司用哪个版本 2021 年之后又出了两个 LTS：Java 21（2023 年 9 月）和 Java 25（2025 年 9 月），LTS 也从"每三年一个"改成了"每两年一个"。Java 8 老项目还很多，但新项目基本都在 17 以上了：主流框架 Spring Boot 从 3.0（2022 年底）起最低要求 Java 17。所以学 17 一点都不亏。

Java 能干什么：三大平台

Java 从 1995 年问世到现在二十多年，可能比部分同学年纪还大。它能干什么？先说它的三大平台，也就是三个分类：

平台是什么现状
Java SE
标准版		可以开发桌面应用（像电脑上的计算器、小游戏这类双击就能用的软件）；是另外两个版本的基础桌面应用能做但不占优势：复杂动画加载可能很慢，这个领域最合适的是 C 和 C++
Java ME
小型版		开发嵌入式消费类电子设备（电视机、微波炉、数码相机里的系统）和小型移动设备（手机）诺基亚塞班时代，打开软件会弹出一个小咖啡杯，那就是 Java ME 写的。随塞班没落已经凉了，招聘网站上搜不到岗位，被安卓和 iOS 取代
Java EE
企业版		用于 Web 方向的网站开发，确切地说是服务器开发当之无愧的第一。从问世到现在，服务器领域没有一门语言能撼动它

既然 SE 做桌面应用不占优势，还要学吗？必须学：它是另外两个版本的基础。我们现在学 SE，目的不是写桌面应用，而是锻炼逻辑思维，为以后做 Java EE 开发打基础。

具体到应用领域，视频列了六个：

  1. 桌面应用：各种开发工具，比如 Java 程序员用的 IDEA、C/C++ 程序员用的 CLion、Python 程序员用的 PyCharm。Java 语言规范、漏洞少，写出来的工具很健壮。国内很多办公系统、税务管理系统也是 Java 写的。
  2. 企业级应用：说简单点就是开发服务器，后面课程里的微服务、Spring Cloud 都属于这个。服务器可能要扛每秒几十万甚至几百万的访问，比如春节 12306 抢票的高峰期。
  3. 移动端和嵌入式：安卓、鸿蒙可以用 Java 开发；医院里做 CT、B 超的机器界面也有用 Java 的。
  4. 科学计算：Java 很严谨。数学建模、机器人动态仿真会用到的 MATLAB，也是用 Java 开发的。
  5. 大数据：大数据框架 Hadoop（logo 是一头大象）就是 Java 写的。
  6. 游戏：很火的像素游戏《我的世界》（Minecraft）是 Java 写的。

天猫、淘宝、阿里云、京东的服务器，WebStorm、IDEA 这些开发工具，机械臂里的控制程序……Java 能干的事情很多。

第 3 节 · P14

Java 为什么这么火

一门语言火不火、能不能长久活下去，主要看四个方面：

  1. 用户量：用的程序员多不多。还记得上一篇的排行榜吗？国内国外用 Java 的都很多。
  2. 适用面：用的地方多不多。上一节的六大领域就是答案。
  3. 是否与时俱进：一门语言跟不上时代，再厉害也会被淘汰。Java 从 9 开始半年一更，别的语言有什么好东西、市场出了什么新技术，都能融进来变成自己的。
  4. 语言本身的特点：下面细说。

Java 自身的特点有六个，不用背，了解一下就行：

面向对象不是"面相这个对象"。学完面向对象以后，你可以把对一样东西的要求（比如名字、年龄、身高等属性，还有它会做的事）告诉 Java，Java 就按这个"模板"把它造出来。根据你想的模板，把东西创建出来，这就是面向对象。造车子、房子都行。怎么写代码、造出来干嘛，后面再学。这是 Java 里最难理解的部分
安全性字面意思：Java 写出来的代码很安全，漏洞少
多线程四个用户同时在 12306 上买票，服务器同时给四个人服务。简单理解就是同时做多件事情
简单易用学起来简单，用起来也容易
开源手机上下载 QQ，下的只是安装包，腾讯不会把代码给你，这叫不开源。而下载 Java 开发工具时，Oracle 会把 Java 的源代码一起给你，告诉你 Java 是怎么工作的。开源之后全世界的开发者都能维护 Java，即使有缺点也会被修好
跨平台最重要的特点。"平台"指操作系统（Windows、Mac、Linux），跨平台就是 Java 程序在任意操作系统上都能运行

动手：一个服务员 vs 四个服务员

四个用户同时来 12306 买票，每人的"查余票 → 下单 → 支付"要 3 秒。比较一下：服务器一次只服务一个人，和同时服务四个人。

用时：0.0 秒

跨平台对公司特别有用。假如一家公司用不能跨平台的语言做了项目，只能在 Windows 上跑；想在别的系统上跑，就得重新写代码，额外增加成本。换成 Java，写一次，所有操作系统都能运行。如果你是老板，你选哪个？就算不差钱，省下来的钱用在别处不香吗？Java 1995 年刚出来时，就是凭这个特性迅速占领了市场，当时的口号是 Write once, run anywhere，视频译作"一次编译，到处运行"。

开源的源代码就在你电脑上 打开上一篇装好的 JDK，lib 文件夹里有个 src.zip，解压出来就是 Java 核心类库的源代码，比如 HelloWorld 里用到的 System 就在 java.base/java/lang/System.java。以后用 IDEA 按住 Ctrl 点一个类名，看到的就是这里面的代码。Java 的开源实现叫 OpenJDK（2006–2007 年起以 GPL 协议开源），Oracle JDK 和 Temurin 等免费发行版都是在它的基础上构建的。
多线程的"同时"是怎么做到的 现在的 CPU 有好几个核心，可以真的同时跑几个线程；就算只有一个核心，系统也会在几个线程之间飞快地来回切换，看起来像同时。上面的演示里每个人的大部分时间其实在"等"（等数据库、等支付结果），多线程的好处就是：一个人在等的时候，服务器可以先去服务别人。多线程在课程下部会细讲。

跨平台的原理

这个原理相对难，简单了解就行，最后有一张图需要看懂。先说高级语言（C、Java、Python 等）是怎么跑起来的，大体都分三步：

  1. 编程：新建文件、写代码、保存。Java 程序员写 .java 文件，C 程序员写 .c，Python 程序员写 .py。
  2. 编译：不管哪种高级语言，操作系统本身都不认识，计算机只认识 0101 这样的机器语言，所以要把代码翻译成机器认识的语言。
  3. 运行：让机器执行翻译之后的代码。

写 HelloWorld 时就是这么做的。而"翻译"这一步，有三种方式：

  • 编译型（代表：C）：根据不同的操作系统，把代码整体翻译成二进制，再交给机器运行。会多出一个后缀为 .obj 或 .o 之类的文件。问题是，不同设备的硬件不一样（手机用 ARM 平台，电脑用 x86 平台），翻译出的指令也可能不一样，存在兼容性问题，每换一个操作系统都要重新编译一次。更夸张的是，编写代码的电脑和运行代码的电脑硬件差别太大，即使是同一个操作系统也可能跑不起来。所以 C 不是跨平台的。
  • 解释型（代表：Python）：不整体翻译，而是读一行、解释一行：读到一行代码，解释成 0101 运行，再读下一行。编译型是"整体翻译"，解释型是"按行翻译"。而且 Python 不产生新文件，直接拿着源代码逐行解释，所以视频说 Python 程序员"天生开源"：不把代码交给别人，别人就没法运行。
  • 混合型（Java）：网上有的说 Java 是编译型，有的说是解释型，都不对，它两样都有。先把 .java 整体编译成 .class（字节码文件），再按行交给设备运行。而且运行时不是直接跑在计算机上，而是跑在虚拟机里。

虚拟机是什么？想让手机游戏在电脑上运行，直接肯定不行。但可以在电脑上装一个安卓手机模拟器，相当于在操作系统里模拟出一部手机，在这部虚拟的手机里就能玩手机游戏了。这部虚拟出来的手机，就可以理解成虚拟机。

Java 也是同一个道理：程序不直接运行在操作系统里，而是运行在虚拟机里。只要针对不同的操作系统，提供不同的虚拟机就行。虚拟机不用我们写，Java 已经提供好了，程序员只要装一个适合自己系统的就可以。

说了这么多原理，脑子可能有点懵，没关系。需要掌握的就一句：Java 的跨平台是通过虚拟机实现的。Java 程序不直接运行在操作系统里，而是运行在虚拟机里；程序员只要针对不同的操作系统，安装不同的虚拟机就行。

补充：三种方式的几个细节 C 的 .o 文件只是半成品，还要经过"链接"，和库拼在一起，才变成能双击运行的 .exe（Windows）或可执行文件（Mac / Linux）。
Python 其实也会先把 .py 编译成字节码（就是你可能见过的 __pycache__ 文件夹里的 .pyc），再交给 Python 虚拟机执行，和 Java 的思路很像，只是这一步是自动、悄悄完成的。想不交源码，也可以只发 .pyc 或用工具打包成 exe（不过这些都比较容易被还原）。
Java 也不全是"按行解释"：JVM 一开始确实是逐条解释字节码，但它会发现哪些代码被反复执行，把这些"热点代码"直接编译成当前 CPU 的机器码存起来，下次就不用再解释了。这叫 JIT（即时编译），是 Java 跑得快的关键，也是"混合型"更准确的含义：先编译成字节码，运行时解释 + 即时编译。
第 5 节 · P16

JDK 和 JRE

程序员写代码需要一套环境。想想刚才写 HelloWorld，要正常编写并运行，需要哪些东西？

  1. JVM（Java Virtual Machine，Java 虚拟机）：真正运行 Java 程序的地方。没有它，代码都没地方跑。
  2. 核心类库：Java 已经写好的东西，直接拿来用。比如 HelloWorld 里的 System、out、println，每个单词都有特定含义，组合起来就能把括号里的内容打印出来。这些 Java 事先定义好的东西，统称核心类库。
  3. 开发工具：javac 编译工具（把 .java 变成 .class）、java 运行工具；还有很多，比如 jdb 调试工具（代码多的时候看程序怎么一步一步运行）、内存分析工具（监控程序运行时的内存）等等。

这三样组成的整体就叫 JDK（Java Development Kit，Java 开发工具包）。程序员想写代码并成功运行，装一个 JDK 就行。

还有一种情况：代码写完、编译好了，把 class 文件交给别人运行。别人只需要运行，不用开发，还需要装完整的 JDK 吗？硬装也没问题，但里面有些东西用不到，白占硬盘。只运行需要什么？

  • JVM 必须要：代码真正运行的地方；
  • 核心类库也要：运行时要用到 Java 写好的那些东西；
  • 开发工具只要一部分：class 文件已经有了，不需要 javac；代码已经没问题了，也不用调试，jdb 用不到。但运行代码的 java 工具得有。

Java 就把 JVM、核心类库和运行时用到的工具单独抽出来，组成了 JRE（Java Runtime Environment，Java 运行环境）。只运行、不开发，装个 JRE 就行，它比较小，不占太多硬盘。很多课程会忽略 JRE 里的运行工具，但它是存在的。

点一点：JDK ⊃ JRE ⊃ JVM

JDKJava 开发工具包
javacjdbjconsolejavadocjar…
JREJava 运行环境
java核心类库
JVMJava 虚拟机
真正运行程序的地方

三个问题要知道：

  1. JDK 是什么，由什么组成？Java 开发工具包，写代码就要装它。包含 JVM、核心类库和开发工具（javac、java、jdb、jhat 等）。
  2. JRE 是什么，由什么组成？Java 运行环境，包含 JVM、核心类库和运行工具（比如 java）。
  3. 三者的包含关系：JDK 包含 JRE，JRE 包含 JVM。

到这里，第一个模块"Java 入门"就学完了。这个模块主要是概念，代码不多；从下一个模块开始，代码量就会逐渐增加了。

补充：现在找不到 JRE 了 上一篇看过 JDK 17 的安装目录：bin、conf、include、jmods、legal、lib，没有 jre 文件夹。从 JDK 11 开始，Oracle 不再单独提供 JRE 下载，JDK 里也不再套一个 jre 目录，不过"JDK 包含运行所需的一切"这个关系没变。现在想给用户一个小巧的运行环境，一般用 JDK 自带的 jlink 工具，只挑程序用到的模块，打包出一个专属的精简运行时。一些发行版（比如 Eclipse Temurin）也还提供 JRE 安装包。
另外，视频提到的内存分析工具 jhat 在 JDK 9 已经被移除了，现在常用 jconsole、jcmd 或 VisualVM。
第 6 节

小结

发展1990 Sun 的 Green 计划 → Oak → 改名 Java，1995 推出 → 2009 Oracle 收购。从 9 起半年一版；LTS：8、11、17。重要版本：5、8、17
三大平台SE 标准版（桌面，是基础）、ME 小型版（嵌入式/移动，已凉）、EE 企业版（服务器，第一）
为什么火用户多、适用面广、与时俱进；特点：面向对象、安全、多线程、简单易用、开源、跨平台
跨平台编译型（C，整体翻译，换平台要重新编译）、解释型（Python，按行翻译）、混合型（Java）。Java 编译成 class，跑在虚拟机里，不同系统装不同的 JVM
JDK / JRE / JVMJDK = JVM + 核心类库 + 开发工具；JRE = JVM + 核心类库 + 运行工具。JDK ⊃ JRE ⊃ JVM
一句话 javac 把代码编译成和系统无关的 class 文件，每个系统各装一个 JVM 来运行它，这就是"写一次，到处运行"。

自测

1. Java 最早叫什么名字？为什么改名叫 Java？
叫 Oak（橡树，项目组门口有棵橡树）。注册商标时发现 Oak 已被别人注册，因为程序员爱喝咖啡，而盛产咖啡的地方叫爪哇岛（Java），就改名 Java。
2. Java SE、ME、EE 分别是什么？我们学 SE 的目的是什么？
SE 标准版（桌面应用，另外两个的基础）、ME 小型版（嵌入式和小型移动设备，已经没落）、EE 企业版（Web 服务器开发）。学 SE 不是为了写桌面应用，而是锻炼逻辑思维、为以后做 EE 开发打基础。
3. 一个 C 程序在 Windows 上编译好了，能直接拿到 Mac 上运行吗？Java 的 class 文件呢？
C 不行：编译出来的是针对 Windows 和那种 CPU 的机器码，要在 Mac 上重新编译一次。Java 的 class 文件可以：它运行在 JVM 里，Mac 上装一个 Mac 版的 JVM 就能运行同一个 class 文件。
4. 为什么说 Java 是"混合型"语言？
它既有编译又有解释：先用 javac 把 .java 整体编译成 .class 字节码，运行时再由 JVM 解释执行（补充：JVM 还会把热点代码即时编译成机器码）。
5. 只想运行别人给的 class 文件，最少需要什么？JDK、JRE、JVM 是什么关系？
需要 JRE：JVM + 核心类库 + 运行工具（java）。关系是 JDK 包含 JRE，JRE 包含 JVM。
