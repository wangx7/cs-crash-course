引用和内存

What a variable actually holds

Java 的变量分两种：一种直接装值，一种装指向对象的引用。赋值和传参，拷的都是变量里装的东西——所以 swap 换不动两个 int，而 service 里的一个 set 能打在 controller 传来的那个对象上。这一篇先用六行代码的步进演示看清这个差别，再往下走一层：变量和对象各住在哪里、栈什么时候满、null 到底是个什么值。

第 2 节

变量两种：装值的、装箭头的

Java 的变量分两大类。基本类型的变量直接装值：int a = 5; 之后，a 这个格子里就是 5。引用类型的变量装的是指向对象的引用——语言规范的原话是 "The values of a reference type are references to objects"（§4.1）。0.3 说过数组是对象，所以数组变量也是装引用的。

赋值只有一条规则：把右边变量里装的东西拷一份。基本类型拷的是值，引用类型拷的是引用。六行代码，点「下一步」逐行执行，盯着右边两栏看：

揭晓第 1 节：== 比的是箭头，不是值

  
两个引用变量之间写 ==，比的是两边装的引用——是不是指向同一个对象。那么 Integer x = 127; 这类写法发生了什么？int 被自动装箱成了一个 Integer 对象，而规范 §5.1.7 有条专门的规则：-128 到 127 之间的整数（还有 true、false 和一部分字符）装箱后保证是同一个对象——"It is always the case that a == b"，实现可以缓存这些值。127 的 == 是 true，靠的就是这个缓存。

  
128 为什么 false？规范对范围外的值的原话是 "disallows any assumptions about the identity"：不做任何承诺。这台 Corretto 8 的默认实现只缓存到 127，所以 128 每次装箱都是新对象——换成别的 JVM、或者给 JVM 加参数扩大缓存范围，结果可能不同。规范没承诺的事，不能当规则用。

  
工程结论：包装类型判等，用 equals 或拆箱后比。两种写法在 BoxCache.java 里实测都是 true。这条不是学究：SpringBlade 的实体类里有 27 个 Integer 字段（1.1 篇统计过），对它们写 == 就是在赌值不超过 127。

  

    新版补充：到 Java 25 没变化
    "引用类型的值是指向对象的引用"（§4.1）和装箱缓存规则（§5.1.7：-128 到 127 保证 ==），在 Java SE 25 的规范里原文都还在，已逐句核对。
  

  
实测：local/examples/1-2/CopyVsShare.java、BoxCache.java。






  
第 3 节

  
参数传递：只有按值传递

  
调用方法时发生了什么？规范 §15.12.4.2 的说法：把实参的值赋给"新创建的参数变量"（freshly created parameter variables）。参数是一个新变量，装着实参的拷贝——拷贝规则和上一节的赋值完全一样：基本类型拷值，引用类型拷引用。

  
三行对照，全部实测：

  
static void swap(int x, int y) { int t = x; x = y; y = t; }
static void zeroFirst(int[] arr) { arr[0] = 0; }
static void reassign(int[] arr) { arr = new int[]{9, 9}; }

int a = 1, b = 2;
swap(a, b);
System.out.println(a + ", " + b);
int[] xs = {1, 2};
zeroFirst(xs);
System.out.println(Arrays.toString(xs));
reassign(xs);
System.out.println(Arrays.toString(xs));

1, 2
[0, 2]
[0, 2]

  
    
    
  • swap 换不动：x、y 是 a、b 的值的副本，交换发生在副本上，方法返回就消失了。
    • 
    
  • zeroFirst 改得动：arr 是 xs 的引用的副本——两支箭头指同一个数组，顺着哪支改都行。
    • 
    
  • reassign 换不动：给 arr 这支副本换一支新箭头，xs 那支还指原来的数组。
    • 
  

  
所以"Java 有没有引用传递"的答案是：没有，只有按值传递。方法能改对象的内部，换不掉调用者手里的引用。JS 在这一点上完全一样——对象共享、swap 同样无效——这套直觉可以直接搬过来。

  
工程里每天的样子

  
SpringBlade 的部门维护就是这条链：controller 把请求体 JSON 转成的 Dept 直接传给 service，service 往里填字段：

  
// DeptController.java 第 98–99 行
public R submit(@Valid @RequestBody Dept dept) {
    return R.status(deptService.submit(dept));
}

// DeptServiceImpl.java 第 70–88 行（节选）
public boolean submit(Dept dept) {
    ...
    if (Func.isEmpty(dept.getParentId())) {
        dept.setTenantId(SecureUtil.getTenantId());
        dept.setParentId(BladeConstant.TOP_PARENT_ID);
        ...
    }
    ...
    dept.setIsDeleted(BladeConstant.DB_NOT_DELETED);
    return saveOrUpdate(dept);
}

  
submit 手里的 dept 是 controller 那个 dept 的引用副本，指向同一个对象：四个 set 全打在调用者的对象上，填完直接 saveOrUpdate(dept) 入库。整个流程能成立，靠的就是"传的是引用副本"这一条。

  

    新版补充：到 Java 25 没变化
    "assign the argument values to corresponding freshly created parameter variables" 在 Java SE 25 的规范里原文还在（§15.12.4.2，已核对）。Java 没有、也没有加过引用传递。

第 4 节

  
栈和堆：谁住哪

  
第 2 节的步进器其实已经把它们画出来了，现在给两栏对上名字。虚拟机规范 §2.5 规定了 JVM 的运行时数据区，和这一篇有关的是两个：

  
    
    
  • JVM 栈（§2.5.2）：每个线程各有一个。栈里压的是帧（frame），一次方法调用一帧，帧里放这个方法的局部变量——步进器左边那栏"变量表"就是当前帧的局部变量。方法返回，帧弹出，里面的变量随之消失。
    • 
    
  • 堆（§2.5.3）：所有线程共享一个堆，规范的原话是 "memory for all class instances and arrays is allocated"——所有类的实例和所有数组都在这里分配。步进器右边那栏就是。
    • 
  

  
所以对得上：局部变量（不管装值还是装引用）在栈帧里，对象和数组本体在堆里。堆里没人指的对象由 GC 回收，3.8 篇展开；类的字节码和元数据住在另一个区（方法区，§2.5.4），3.9 篇讲类加载时再看。

  
一个诚实的注脚：规范还说了一句 "frames may be heap allocated"——栈是逻辑结构（只压入弹出帧），规范并不规定帧物理上必须存在哪。"栈上分配、堆上分配"是实现层面的说法，HotSpot 的实现确实把帧放在连续栈上；但你学到的规则应该是：变量的归属跟作用域走，对象的归属跟引用走，这一条和物理布局无关。

  

    新版补充：虚拟线程把栈帧放进了堆里（Java 21）
    数据区的划分到 Java 25 没变化（JVMS §2.5 原文核对过）。真正的新事在 Java 21：虚拟线程（JEP 444）的栈帧存在堆里——JEP 的原话是 "The stacks of virtual threads are stored in Java's garbage-collected heap as stack chunk objects"，所以一台机器能撑起百万级的并发任务。你们的 Tomcat 项目暂时还是平台线程、一个请求一个栈；第 3 部分讲线程时回来。（依据 JEP 444 原文，本机没有 21，未实测。）
  






  
第 5 节

  
栈的边界：StackOverflowError

  
栈不是无限的。规范 §2.5.2：线程需要的栈超过允许的值，JVM 抛 StackOverflowError。最常见的踩法是不小心写出的无限递归。真的炸一次看：

  
static long depth = 0;

static void go() {
    depth++;
    go();
}

public static void main(String[] args) {
    try { go(); }
    catch (StackOverflowError e) {
        System.out.println("StackOverflowError，深度停在 " + depth);
    }
}

  
连跑三次的输出：

  
StackOverflowError，深度停在 30630
StackOverflowError，深度停在 30622
StackOverflowError，深度停在 30545

  
三万左右，而且每次不一样。深度不是定值这件事本身值得记住：规范允许 JVM 栈固定大小或动态扩展（§2.5.2），不同 JVM、不同启动参数（如 -Xss）下数字都会变。工程里能依赖的只有"太深会抛"，不能依赖"多深才抛"。

第 6 节

  
null：空箭头

  
null 是可以赋给任何引用类型的值。规范里它的类型叫 "null type"（§4.1），没有名字——所以不能声明一个"null 类型"的变量，null 只是这个类型唯一的值。用第 2 节的画面说：装了 null 的变量是一支空箭头，不指任何对象。

  
顺着空箭头走，就抛 NullPointerException：

  
String s = null;
try {
    System.out.println(s.length());
} catch (NullPointerException e) {
    System.out.println("s.length() 抛出: " + e);
}
Integer n = null;
try {
    int m = n;
    System.out.println(m);
} catch (NullPointerException e) {
    System.out.println("int m = n 抛出: " + e);
}
System.out.println(s == null);

s.length() 抛出: java.lang.NullPointerException
int m = n 抛出: java.lang.NullPointerException
true

  
两处都在"顺着箭头走"：s.length() 要顺着引用找到对象才能调方法；int m = n 是拆箱，要顺着引用找到那个 Integer 才能取出里面的 int（0.3 见过 Boolean 版）。判断空不空用 == null，这是引用之间比"指不指对象"，合法且不会抛。

  
注意上面两条异常消息是空的——异常名后面什么都没有。这是 Java 8 的 NPE 的样子：它告诉你错了，不告诉你谁错了。

  

    新版补充：NPE 开始说话了（Java 14）
    从 Java 14 起（JEP 358），NPE 自带详情，同样这段代码会打印 Cannot invoke "String.length()" because "s" is null 这样的消息，直接点名是哪个变量、哪个操作。null 本身没有任何变化：还是能赋给任何引用类型、顺空箭头还是抛。另外 Java 8 自己引入了 Optional 作为"可能没有值"的显式写法，2.7 篇展开。（JEP 358 依据原文，本机只有 JDK 8，未实测。）

第 7 节

  
小结和自测

  

    带走四句话
    变量两种：基本类型装值，引用类型装引用；赋值和传参拷的都是变量里装的东西。方法能改传入对象的内部，换不掉调用者手里的引用。局部变量住在栈帧里、随方法返回消失，对象和数组住在堆里、没人指了由 GC 收；栈太深抛 StackOverflowError。null 是空箭头，顺着它走就抛 NullPointerException；包装类型判等用 equals，不用 ==。
  


  

    
四个问题

    

      
1. Integer a = 127, b = 127; 和 Integer c = 128, d = 128;，两组各自写 ==，结果是什么？判等应该用什么？

      
      
本机 JDK 8 实测：127 那组 true，128 那组 false（BoxCache.java）。规范只承诺 -128 到 127 装箱后是同一个对象（§5.1.7），范围外不做承诺。判等用 equals 或拆箱后 ==，两种写法实测都得 true。

    

    

      
2. 能写出一个 swap(int a, int b)，让调用者的两个 int 真的交换吗？

      
      
不能。参数是新变量，装着实参值的副本，交换发生在副本上，方法返回就没了。要交换得换思路，比如返回一个数组 new int[]{b, a}，或把两个值装进一个对象里改。实测见 Swap.java。

    

    

      
3. DeptController 把 dept 传给 submit，submit 里执行了 dept.setTenantId(...)。submit 返回后，controller 手里那个 dept 变没变？

      
      
变了。两个变量装的是同一个对象的引用（传参拷的是引用），submit 的 set 打在堆里的同一个对象上，controller 手里的 dept 顺着同一支箭头看，字段已经是新值。真实代码见 DeptServiceImpl.java 第 70–88 行。

    

    

      
4. String s = null; s.length() 和 Integer n = null; int m = n; 各自会怎样？报的错说了什么？

      
      
都抛 NullPointerException：前者顺着引用找对象，后者拆箱要取出对象里的值。Java 8 的异常消息是空的（只有异常名）；Java 14 起会带"哪个变量是 null"的详情（JEP 358）。实测见 NullDemo.java。
