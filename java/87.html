第 1 节 · P87

先回顾：栈、堆，再加一个方法区

以前讲过：每款软件运行时都要占用一块内存，Java 也不例外。虚拟机为了更好地利用这块内存，把它分成了五个部分，各有各的作用。现在要知道其中三块：

栈方法被调用时进栈执行，方法里定义的变量也在这里；方法执行完毕就出栈
堆只要是 new 出来的，就是在堆里开辟了一个小空间；堆里的空间都有自己的地址值
方法区运行一个类的时候，这个类的字节码文件（.class）会加载到这里临时存储

方法区要单独说一下。它有很多功能，其中一个是：要运行一个类时，把这个类的字节码文件加载进来临时存储，比如 HelloWorld.class、Test.class。在 JDK 7 以前，方法区和堆是连在一起的，在真实的物理空间里也是一片连续的空间。这种设计不好，到 JDK 8 改进了：取消了方法区，新增了一块叫元空间的区域，把它和堆分开，原来方法区要做的很多事情做了拆分，有的归到堆里，有的归到元空间；加载字节码文件这个功能，JDK 8 以后归属元空间。不过它叫什么名字不重要，重要的是加载完之后代码怎么运行，所以下面还是把这块区域叫方法区。（为什么老设计不好，课程后面有一篇单独的虚拟机内存讲解。）

更正：JDK 8 取消的是"永久代"，不是"方法区" 方法区是《Java 虚拟机规范》里规定的一块逻辑区域（存类的信息、方法的字节码等），任何版本的 JVM 都有它，JDK 8 也没有取消。变的是 HotSpot 虚拟机实现它的方式：JDK 7 及以前用的是和堆挨在一起、大小要提前定好的永久代（PermGen），类加载得多了容易报 OutOfMemoryError: PermGen space；JDK 8 把永久代去掉，改用元空间（Metaspace）来实现方法区，元空间用的是本地内存，不占堆。所以"还是把它叫方法区"不只是图方便，这个叫法本来就是对的。
第 2 节 · P87

一个对象的内存图

创建一个对象，比如 Student s = new Student();，内存里至少做了七件事：

  1. 加载 class 文件：把 Student 这个类的字节码文件加载到内存
  2. 声明局部变量：等号左边的 s
  3. 在堆内存中开辟一个空间：等号右边有 new。这个小空间就是平时说的对象
  4. 默认初始化
  5. 显式初始化
  6. 构造方法初始化
  7. 把堆内存中的地址值赋值给左边的局部变量

第 4、5、6 三步都是给第 3 步那个空间里的变量赋值。要画图的代码：Student 类有 name、age 两个属性和一个 study 方法；测试类里创建对象，打印 s，打印属性，赋值，再打印，最后调用 study。

代码在幻灯片上，字幕只描述了每一行做什么；下面演示里的代码是按讲解还原的（打印属性那两行中间的 "..." 是还原时加的分隔）。图里的地址值 001、002 是课上的假设。

动手：一步一步创建一个对象

过程里几个要点：

  • 程序从 main 方法开始，所以先把测试类的字节码文件加载到方法区，虚拟机自动调用 main，main 进栈；
  • 堆里的小空间会把 Student 类里所有的成员变量拷贝一份放进来，另外还有所有成员方法的地址，为的是以后用对象调方法时能找到对应的方法；
  • 默认初始化：name 是 null，age 是 0。显式初始化：如果定义成员变量时直接给了值，比如 String name = "张三"; int age = 23;，这一步 null 和 0 就被张三和 23 覆盖；这段代码里没这么写，可以忽略。构造方法初始化：小括号里什么都没写，调用的是空参构造，里面也没有代码，也可以忽略；如果用的是有参构造，这一步 name、age 就有值了。可见构造方法只是创建对象中的一步；
  • 最后一步，地址值 001 通过等号（赋值运算符）交给左边的变量 s。到这里一个对象才算创建完毕。这些不用背，简单了解即可；
  • 直接打印 s，打印的是变量 s 里记录的地址值。s.name 可以理解成"001 的 name"：通过 s 里的 001 找到堆里的空间，再拿里面的 name；
  • s.study()：先通过 s 找到 001 这个空间，再通过里面成员方法的地址找到 study，study 进栈，执行完出栈；
  • main 执行完也出栈，变量 s 随之消失，指向对象的那根线也就没了。没有变量指向这个空间，这个空间也会消失，变成垃圾。
两处简化：打印对象看到的东西、对象里的"方法地址" ① 打印 s 看到的不是 001。实际运行 System.out.println(s);，输出类似 Student@2a139a55（本机 JDK 8 实测；每次运行、每台机器都可能不同，类在包里时前面还带包名）。@ 后面是对象哈希码的十六进制，由虚拟机生成，可以把它当成地址值来理解，但它并不是真实的内存地址。

② 对象里并没有逐个存"每个成员方法的地址"。HotSpot 里每个对象只在对象头里放一个指针，指向方法区里这个类的信息；调方法时先顺着这个指针找到类，再在类里找到方法。所以不管 new 多少个 Student 对象，study 的代码在内存里只有一份。课上的画法是为了直观；演示里那一行写成了"→ 方法区的 Student.class"。
第 3 节 · P87

两个对象的内存图

代码里创建两个对象会怎样？很简单，就是把刚才一个对象的过程重复两次。学生类不变；测试类创建第一个对象 s1，打印、赋值阿强和 23、获取、调用 study；再创建第二个对象 s2，赋值阿珍和 24，做同样的事。

画图之前先想一个问题：创建第二个对象时，Student.class 还要再加载一次吗？

动手：两个对象

  • 答案是不需要。创建第一个对象时 class 文件已经加载过了，第二次直接用；
  • 等号右边又有一个 new，所以堆里又开辟了一个空间，地址是 002，里面同样有 name、age 和成员方法的地址；
  • s2.name = "阿珍"; 是把阿珍赋给 002 的 name，对 001 这个空间里的值没有任何影响。
结论 只要看见 new，就是在堆里开辟了一个新的小空间。看到两个 new，就是两个小空间，它们互相独立，互不影响。
第 4 节 · P87

两个引用指向同一个对象

学生类还是一样。测试类第一个对象正常创建：Student stu1 = new Student();。第二个变量不一样，等号右边不是 new：

Student stu2 = stu1;

它是把 stu1 这个变量里记录的东西赋给 stu2。stu1 里记录的是什么？是地址值 001。所以赋完之后，stu2 里记录的也是 001，它也能通过 001 找到堆里那个空间：两个变量指向了同一个对象。这会带来什么影响？

动手：stu2 = stu1 之后

  • stu2.name = "阿珍"; 就是把阿珍赋给 001 的 name，原来的阿强被覆盖。之后 stu1.name 和 stu2.name 都是在获取 001 的 name，等于把它获取了两次，打印阿珍、阿珍；
  • stu1 = null;：null 表示一个不存在的空间。这是把 stu1 里的 001 覆盖掉了，stu1 到对象的那根线断开。再用 stu1.name 就找不到 001 了，程序出现 NullPointerException（空指针异常）；
  • 把出错的那行注释掉往下看：stu2 没有被任何东西覆盖，里面还是 001，照样能找到对象、拿到阿珍；
  • 最后 stu2 = null;，stu2 的线也断了。对象没有人用了，变成垃圾。
结论 两个变量指向同一个空间时，只要其中一个变量改了这个空间里的值，其他变量再次访问，就是改变之后的结果。
空指针异常长什么样 本机 JDK 8 实测，控制台是：Exception in thread "main" java.lang.NullPointerException，下一行 at TestStudent.main(TestStudent.java:行号)。它是运行时才出现的，编译能通过；出现之后程序停在那一行，后面的代码不再执行。看到它就找"点"前面的那个变量：它里面是 null，却还想通过它去访问属性或调用方法。
第 5 节 · P88

基本数据类型和引用数据类型

有了对象的内存图，就能把两种类型最本质的区别讲明白。以前学的是：基本数据类型是四类八种，除此之外的其他所有类型都是引用数据类型。这属于强行记忆，没抓到本质。（这一段和方法那一章讲过的是同一个道理，当时的例子只有数组，现在多了对象。）

基本数据类型：int a = 10; 在内存里开辟一个小空间，名字叫 a，int 表示它能存 int 类型的整数，10 就是真实存在这个小空间里的数据，和其他空间没有任何关系。再定义 double b = 20.0;，就开辟第二个空间 b，20.0 存在里面。变量里存的是真实的数据值，自己玩自己的。

引用数据类型：代码里创建的任意对象、数组都是。Student s = new Student(); 等号左边定义了变量 s，Student 表示它能存 Student 这个类对象的地址值。对象里的数据 name、age 是存在 s 里的吗？不是，是存在堆里开辟的那个小空间里的；s 记录的仅仅是那个小空间的地址值。数组也一样：int[] arr = {1, 2, 3, 4};，arr 里记录的不是 1、2、3、4，而是堆里那块空间的地址值，要拿数据只能先通过 arr 找到那块空间，再通过索引获取。

这里的"引用"，可以理解成使用其他空间中的数据：引用引用，就是拿别人的东西过来用。

基本数据类型

  • 数据值存储在自己的空间中；
  • 赋值给其他变量，赋的也是真实的值：int b = a; 给 b 的就是 10，之后改 b 不影响 a。

引用数据类型

  • 数据值存储在其他空间中，自己的空间里存的是地址值；
  • 赋值给其他变量，赋的是地址值：Student s2 = s1; 之后两个变量指向同一个空间，一个改了，另一个再访问就是修改之后的结果（上一节的演示）。
第 6 节 · P89

this 的内存原理

上一篇学过 this 的作用：区分重名的局部变量和成员变量。直接打印 age 触发就近原则，打印局部变量的 10；写 this.age 就用成员变量，打印 0。可是为什么 this 能区分？它在内存里是什么？这要说到 this 的本质：

this 的本质 this 代表所在方法调用者的地址值。

这句话有点拗口，看内存图。第一段程序：Student 里只有一个成员变量 age，method 方法里定义局部变量 age = 10，先打印 age，再打印 this.age。第二段程序回答另一个问题：set 方法里的 this 是怎么给对象赋值的？用空参构造创建两个学生对象，分别调用 setName，两个名字怎么就各自赋给了各自的对象？

第二段程序里的两个名字是按语音转写的读音写的（朱小林、乔小九），用字可能和幻灯片不一样。

动手：方法里的 this 记录的是什么

  • method 是被 s 调用的，s 里是 001，所以方法里记录的调用者地址值就是 001，this 记录的也是 001；
  • this.age 可以看成"获取 001 里的 age"，拿到的是堆里对象的 0；不带 this 的 age 就近用方法里的 10；
  • setName 方法的形参 name 在内存里就是一个变量，接收传过来的实际参数。this.name = name; 等号右边没有 this，就近是形参；左边 this 是调用者的地址值。第一次是 s1 调的，this 是 001，整句话就是把名字赋给 001 的 name；第二次是 s2 调的，this 变成了 002，赋给的是 002 的 name，对第一个空间没有任何影响。

所以学 this 时要知道两层：最基本的作用很简单，区分局部变量和成员变量；之所以能区分，是因为它的本质是所在方法调用者的地址值。

第 7 节 · P90

成员变量和局部变量的区别

区别有好几条，不需要记，学完只要知道什么是成员变量、什么是局部变量就可以了。成员变量是类中、方法外的变量，没有上下顺序的规定，只是为了方便阅读，一般都写在最上面；局部变量是方法里面的变量。

public class Student { String name; // 成员变量 int age; // 成员变量 public void study() { int i = 0; // 局部变量 System.out.println("好好学习"); } }

幻灯片上的代码字幕没有念全，方法里的内容是示意。

区别成员变量局部变量
类中位置类中、方法外方法内，或方法声明上（形参也是局部变量）
初始化值有默认初始化值没有，使用之前必须先赋值
内存位置堆内存（准确说：堆里的对象里）栈内存（准确说：栈里的方法里）
生命周期跟对象有关：对象创建它就存在，对象消失它就消失跟方法有关：方法进栈它就存在，方法出栈它就消失
作用范围整个类中有效只在当前方法中有效

再用一个内存图解释。测试类里先定义变量 int a = 10;，它在方法里，是局部变量；再创建一个 Student 对象，对象里有 name 和 age 两个成员变量。

动手：一个在栈里，一个在堆里

"没有默认值"是编译器在把关 局部变量不赋值就使用，连编译都过不了。int a; System.out.println(a); 在 JDK 8 下的报错是 错误: 可能尚未初始化变量a。成员变量之所以可以不赋值，是因为创建对象的第 4 步"默认初始化"替你赋过了。另外表里"作用范围：整个类中有效"说的是在本类的方法里都能直接用；别的类能不能通过对象访问它，要看有没有 private。
第 8 节

小结

三块内存栈：方法运行、局部变量；堆：new 出来的对象，有地址值；方法区：加载进来的字节码文件
创建对象七步加载 class 文件 → 声明局部变量 → 堆里开辟空间 → 默认初始化 → 显式初始化 → 构造方法初始化 → 地址值赋给变量
对象名.属性通过变量里的地址值找到堆里的空间，再找里面的属性
两个对象两个 new 两个空间，互相独立；class 文件只加载一次
两个引用stu2 = stu1 赋的是地址值；一个改了，另一个看到的是改变之后的结果
null不存在的空间；变量里是 null 还去访问属性，空指针异常；没有变量指向的对象变成垃圾
基本 / 引用类型基本类型变量里存真实的数据；引用类型变量里存其他空间的地址值
this所在方法调用者的地址值：谁调用方法，this 就是谁
成员 / 局部变量类中方法外、堆里、有默认值、随对象；方法里、栈里、无默认值、随方法
一句话 变量在栈里，new 出来的对象在堆里，变量里记的只是对象的地址值；顺着地址找过去，属性、方法、this、null、垃圾，全都说得通。

自测

1. Student s = new Student(); 这一行里，s 在哪块内存？对象在哪块内存？s 里存的是什么？
s 是局部变量，在栈里（main 方法的空间里）；对象是 new 出来的，在堆里；s 里存的是对象那块空间的地址值。Student.class 则加载在方法区。
2. 创建对象时给成员变量赋值的三步是什么顺序？类里写了 int age = 23;，又用有参构造传了 24，对象创建完 age 是多少？
默认初始化 → 显式初始化 → 构造方法初始化。age 先是 0，被 23 覆盖，再被构造方法赋成 24，最后是 24。
3. Student s1 = new Student(); Student s2 = new Student(); s2.name = "阿珍"; 之后 s1.name 是什么？如果第二句改成 Student s2 = s1; 呢？
两个 new 是两个独立的空间，s1.name 还是默认值 null。改成 s2 = s1 后，两个变量记的是同一个地址值，指向同一个对象，s1.name 也是"阿珍"。
4. stu1 = null; 之后执行 System.out.println(stu1.name); 会怎样？对象此时一定变成垃圾了吗？
运行时出现空指针异常 NullPointerException：stu1 里的地址值被 null 覆盖，找不到对象了。对象不一定是垃圾：如果还有别的变量（比如 stu2）指向它，它还能正常使用；所有指向它的变量都没了，才变成垃圾。
5. s1.setName("A"); s2.setName("B");，setName 里写的是 this.name = name;。两次调用时 this 分别是什么？
this 是所在方法调用者的地址值。第一次由 s1 调用，this 是 s1 记录的地址（比如 001），"A" 赋给 001 的 name；第二次由 s2 调用，this 是 002，"B" 赋给 002 的 name。
6. 说出成员变量和局部变量的三点区别。
任选三点：位置（类中方法外 / 方法内或形参）；初始化值（有默认值 / 没有，必须先赋值）；内存位置（堆里的对象里 / 栈里的方法里）；生命周期（随对象 / 随方法进栈出栈）；作用范围（整个类 / 当前方法）。
