The Central Processing Unit (CPU)

第 0 节

CPU 做什么

嗨，我是 Carrie Anne，欢迎收看计算机科学速成课！今天我们讲处理器。先提醒一下：这可能是整个系列里最复杂的一集。所以一旦你弄懂了，你就厉害了。

我们已经做了一个算术逻辑单元（ALU），输入二进制数，它会执行计算。我们还做了两种计算机内存：寄存器——很小的一块线性内存，适合存一个值；然后我们扩大规模，做出了 RAM——一大块内存，能在不同的地址上存很多数字。

现在是时候把这些拼在一起，造出任何一台计算机的心脏了——只不过它没有人类心脏那些情感包袱。计算机的心脏是中央处理单元，最常见的叫法是 CPU。

CPU 的工作是执行程序。程序，比如 Microsoft Office、Safari 浏览器，或者你心爱的《半条命 2》，是由一系列单独的操作组成的，这些操作叫指令（instruction），因为它们"指示"计算机该做什么。如果是数学指令，比如加或减，CPU 会让 ALU 去做这个数学运算；如果是内存指令，CPU 会和内存通信，读写数值。

CPU 里有很多部件，所以我们一块一块地搭，边搭边讲。我们关注功能模块，而不是画出每一根线。当我们用一条线连接两个组件时，这条线代表所有必要线路的一个抽象。这种高层次的视角叫微体系结构（microarchitecture）。

第 1 节

零件清单与指令

好，首先我们需要一些内存，把上一集做的 RAM 模块拿过来就行。为了简单，假设它只有 16 个位置，每个位置存 8 位。再给处理器 4 个 8 位的寄存器，叫 A、B、C、D，用来临时存储和操作数据。

我们已经知道，数据可以以二进制的形式存在内存里，程序也可以存在内存里。我们可以给 CPU 支持的每一条指令分配一个 ID。在这个假想的例子里，我们用前 4 位存"操作码"（operation code，简称 opcode），后 4 位说明这个操作的数据从哪里来——可以是寄存器，也可以是内存地址。

这台 CPU 认识的指令

指令描述4 位操作码后 4 位
LOAD_A把 RAM 里的值读进寄存器 A00104 位 RAM 地址
LOAD_B把 RAM 里的值读进寄存器 B00014 位 RAM 地址
STORE_A把寄存器 A 的值写进 RAM01004 位 RAM 地址
ADD把两个寄存器相加，结果存进第二个10002 位寄存器 + 2 位寄存器

要把 CPU 补全，还需要两个寄存器。第一，需要一个寄存器记录程序运行到哪里了，我们用指令地址寄存器，顾名思义，它存着当前指令的内存地址。第二，需要另一个寄存器存当前的指令，我们叫它指令寄存器。

计算机刚启动时，所有寄存器都从 0 开始。为了举例，我们已经在 RAM 里放好了一个简单的程序，今天就把它从头走一遍。

第 2 节

动手：一个阶段一个阶段地跑程序

先用下面的模拟器跟着走一遍，再读后面的文字——文字就是这台模拟器每一步在做的事。

① 取指令 fetch② 解码 decode③ 执行 execute

蓝色 = 数据从这里出来，橙色 = 数据写到这里；右边 RAM 里黑框是指令地址寄存器指着的那一格

取指令（fetch）

CPU 运行的第一个阶段叫取指令阶段，负责拿到第一条指令。首先，把指令地址寄存器连到 RAM。寄存器的值是 0，所以 RAM 返回地址 0 里存的值，这里是 0010 1110。然后这个值被复制进指令寄存器。

解码（decode）

现在指令已经从内存里取出来了，我们得弄清楚这是什么指令，才能执行（execute）它——是运行它，不是"处决"它。这叫解码阶段。这里操作码，也就是前 4 位，是 0010，对应 LOAD_A 指令：把 RAM 里的一个值读进寄存器 A。RAM 地址是这条指令的后 4 位，1110，也就是十进制的 14。

指令由控制单元（Control Unit）来解码和解释。和我们造过的其他所有东西一样，它也是由逻辑门构成的。比如为了识别 LOAD_A 指令，需要一个检查操作码是否等于 0010 的电路，用几个逻辑门就能做到。

动手：识别 LOAD_A 的电路

这个电路怎么来的 0010 的意思是"第 3 位是 0、第 2 位是 0、第 1 位是 1、第 0 位是 0"。把应该是 0 的位先过一个 NOT，于是"完全匹配"就变成了"四个信号全是 1"——这正是 AND 的工作。每条指令都有一个这样的小电路，它们合起来就是控制单元里的解码部分。

执行（execute）

知道了是哪条指令，就可以执行它了，这是执行阶段的开始！用"LOAD_A 检查电路"的输出，打开 RAM 的允许读取线，并把地址 14 送过去。RAM 取出这个地址上的值，00000011，也就是十进制的 3。因为这是 LOAD_A 指令，我们只想把这个值存进寄存器 A，其他寄存器都不受影响。所以，把 RAM 的数据线连到 4 个数据寄存器上，再用 LOAD_A 检查电路只打开寄存器 A 的允许写入线。这就成功了——我们把 RAM 地址 14 的值读进了寄存器 A。

这条指令完成了，可以关掉所有线路，准备去内存里取下一条指令。为此，把指令地址寄存器加 1，执行阶段到此结束。

LOAD_A 只是这台 CPU 能执行的几条指令之一。不同的指令由不同的逻辑电路解码，这些电路会配置 CPU 的各个部件去执行相应的操作。一个个去看这些解码电路细节太多了，既然已经看过一个例子，我们就把它们统统打包成一个控制单元，保持简洁。没错，又一层新抽象。控制单元就像管弦乐队的指挥，指挥着 CPU 的所有部件。

第二轮：LOAD_B

完成了一整轮"取指令 → 解码 → 执行"，就可以从取指令开始，再来一遍。指令地址寄存器现在是 1，所以 RAM 给出地址 1 里的值：0001 1111。到解码阶段！0001 是 LOAD_B 指令，把 RAM 里的一个值读进寄存器 B，这次的内存地址是 1111，也就是 15。到执行阶段！控制单元让 RAM 读地址 15，并让寄存器 B 接收数据。成功，我们把 00001110，也就是十进制的 14，存进了寄存器 B。最后把指令地址寄存器加 1，又完成了一轮。

第三轮：ADD

下一条指令有点不同，来取它：1000 0100。操作码 1000 是 ADD 指令。这次后 4 位不是一个 4 位 RAM 地址，而是两组 2 位。2 位能表示 4 个值，所以 2 位足够选出 4 个寄存器中的任意一个。第一组 2 位是 01，这里代表寄存器 B；第二组是 00，代表寄存器 A。所以 1000 01 00 这条指令的意思是：把寄存器 B 的值加到寄存器 A 里。

为了执行这条指令，我们需要把第 5 集做的 ALU 整合进 CPU。控制单元负责选出正确的寄存器作为输入，并配置 ALU 做正确的运算。对于这条 ADD 指令，控制单元启用寄存器 B，把它的值送进 ALU 的第一个输入；也启用寄存器 A，送进 ALU 的第二个输入。前面说过，ALU 本身能做好几种运算，所以控制单元必须把 ADD 的操作码传给它，让它做加法。

最后，结果应该存进寄存器 A。但不能直接写进去，因为新值会绕回 ALU，然后不停地和自己相加。所以控制单元用一个内部寄存器暂存输出，关掉 ALU，再把值写进正确的目标寄存器。这里输入是 3 和 14，所以和是 17，二进制 00010001，现在存进了寄存器 A。和之前一样，最后把指令地址加 1，又完成一轮。

第四轮：STORE_A

好，来取最后一条指令：0100 1101。解码后发现 0100 是 STORE_A 指令，RAM 地址是 13。和平常一样，把地址送给 RAM 模块，但这次不是允许读取，而是允许写入。同时，打开寄存器 A 的允许读取，这样就能用数据线把寄存器 A 里的值送进去。

恭喜，我们刚刚运行了第一个计算机程序！它从内存里读出两个值，把它们加起来，再把和存回内存。

第 3 节

控制单元：乐队的指挥

回顾一下控制单元在每一轮里做的事：它看指令寄存器里的操作码，决定这一轮该打开哪些线——RAM 是读还是写、哪个寄存器允许写入、ALU 做什么运算——最后让指令地址寄存器加 1。CPU 里的其他部件都不"知道"自己在执行什么程序，它们只是在控制单元打开的那几根线上传数据。

指令RAM寄存器ALU
LOAD_A 14读地址 14只允许 A 写入不用
LOAD_B 15读地址 15只允许 B 写入不用
ADD B, A不用读 B、读 A；结果经临时寄存器写回 A做加法
STORE_A 13写地址 13读 A，送上数据线不用

第 4 节

时钟

当然，刚才是我一步一步讲给你听的，我在手动地把 CPU 从取指令推进到解码、再到执行。但不是每台计算机里都住着一个迷你 Carrie Anne。所以让 CPU 一拍一拍走下去的责任，落在了一个叫时钟的部件上。

顾名思义，时钟以精确、规律的间隔触发电信号。控制单元用这个信号推进 CPU 的内部操作，让一切按步骤同步进行——就像罗马战船船头那个有节奏地击鼓的人，让所有划桨手保持同步……或者像一个节拍器。

当然，节奏不能太快，因为就连电，在导线里传过去、让信号稳定下来，也需要一点时间。CPU 执行"取指令 → 解码 → 执行"每一步的速度，叫时钟速度（clock speed），单位是赫兹——一个表示频率的单位，1 赫兹就是每秒 1 个周期。

我花了大约 6 分钟给你讲完 4 条指令——读取、读取、相加、存储——所以我的等效时钟速度大约是 0.03 赫兹。我承认我不是一台好计算机，但就算是心算很快的人，大概也只能一秒算一次，也就是 1 赫兹。

第一款单芯片 CPU 是英特尔 4004，一款 1971 年发布的 4 位 CPU。它的微体系结构其实和我们的示例 CPU 很像。虽然它是同类中的第一款处理器，但它的时钟速度已经达到了惊人的 740 千赫兹——每秒 74 万个周期。你可能觉得这很快了，但和我们今天用的处理器比起来不值一提。1 兆赫兹是每秒一百万个时钟周期，而你现在看视频用的电脑甚至手机，毫无疑问有好几吉赫兹——那可是每秒几十亿个 CPU 周期。

你可能还听说过有人给电脑超频。意思是修改时钟，加快 CPU 的节奏——就像罗马战船要去撞另一艘船时，鼓手会加快击鼓。芯片厂商在设计 CPU 时通常会留出足够的余量，能承受一点超频；但超得太多，要么让 CPU 过热，要么因为信号跟不上时钟而算出一堆乱七八糟的结果。

你很少听说降频，但它其实超级有用。有时候没必要让处理器全速运行，也许用户走开了，或者正在跑的程序要求不高。把 CPU 放慢，可以省很多电，这对靠电池供电的设备很重要，比如笔记本和智能手机。为了满足这种需求，很多现代处理器能根据需要提高或降低时钟速度，这叫动态频率调节（dynamic frequency scaling）。

第 5 节

打包成一个 CPU

加上时钟，我们的 CPU 就完整了。现在可以给它套个盒子，变成一个独立组件。没错，又一层新的抽象！

RAM 就像上一集给你看的那样，是 CPU 外面的一个独立组件，它们之间用地址线、数据线和允许读 / 写线通信。

虽然我们今天设计的 CPU 是一个简化的例子，但我们讲到的很多基本机制，现代处理器里依然存在。下一集，我们会加强这台 CPU，给它扩展更多指令，同时迈出走向软件的第一步。下周见！

第 6 节

本集小结

① 取指令：按指令地址寄存器去 RAM 取指令，放进指令寄存器→② 解码：控制单元看操作码→③ 执行：打开相应的线，最后指令地址 +1↺
一句话 程序就是存在 RAM 里的一串指令；CPU 在时钟的节拍下不停地"取指令 → 解码 → 执行"，控制单元像指挥一样决定每一拍打开哪些线。我们的 4 条指令程序：从地址 14、15 读出 3 和 14，相加得 17，写回地址 13。

合上页面，试着回答

1. 指令地址寄存器和指令寄存器分别存什么？
指令地址寄存器存当前指令在 RAM 里的地址（程序走到哪了）；指令寄存器存取回来的那条指令本身（8 位的操作码 + 操作对象）。每执行完一条，指令地址寄存器 +1。
2. 0001 1111 和 1000 0100 分别是什么意思？
0001 1111：操作码 0001 = LOAD_B，地址 1111 = 15，把 RAM 地址 15 的值读进寄存器 B。1000 0100：操作码 1000 = ADD，后 4 位拆成 01（B）和 00（A），把 B 加到 A 里。
3. ADD 的结果为什么不能直接写回寄存器 A？
A 同时是 ALU 的输入。如果结果直接写进 A，新值马上又流进 ALU，再和 B 相加，再写回……不停地自己加自己。所以控制单元先把结果存进内部的临时寄存器，关掉 ALU，再写回 A。
4. 时钟速度 3 GHz 是什么意思？超频和降频各有什么用？
每秒 30 亿个时钟周期，控制单元每个周期推进 CPU 一步。超频让节奏更快，但太快会过热或因信号跟不上而算错；降频让节奏变慢，省电，对笔记本和手机很重要。现代 CPU 会按需自动调节，叫动态频率调节。
