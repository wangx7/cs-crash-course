图形用户界面

Graphical User Interfaces

不用再背命令，屏幕上直接摆出你能做什么，"指一指、点一下"就行。这套界面不是 Macintosh 一夜发明的，而是从恩格尔巴特的鼠标、施乐的"桌面"一路演化来的；它背后的编程方式也变了——事件驱动。

第 0 节

从命令行到"指一指、点一下"

嗨，我是 Carrie Anne，欢迎收看计算机科学速成课！上集最后谈到了苹果在 1984 年发布的 Macintosh。这是普通人能买到的第一台带图形用户界面的计算机，还配了一个鼠标来操作。那个年代其他个人计算机用的全是命令行，图形界面是一次革命性的进化。

你不必记住或者猜出该输入的正确命令，图形界面直接把能做的事显示给你看，只要在屏幕上找到想做的那一项就行。这是一种"指一指、点一下"（point and click）的界面。突然间，计算机直观多了：不只是爱好者或计算机科学家，任何人都能自己摸索着用起来。

人们认为是 Macintosh 让图形用户界面（GUI）成了主流，但实际上图形界面是几十年研究的成果。前几集讲过一些早期的交互式图形程序，比如 1962 年的 Sketchpad 和《太空大战》（Spacewar!），但它们都是一次性的程序，不是一整套融为一体的使用体验。现代图形界面真正的先驱，可以说是道格拉斯·恩格尔巴特（Douglas Engelbart）。

第 1 节

恩格尔巴特：增强人类智力

思想泡泡

二战期间，恩格尔巴特驻扎在菲律宾当雷达操作员，读到了万尼瓦尔·布什关于 Memex 的文章（第 24 集讲过）。这些想法启发了他。海军服役结束后他回到学校，1955 年在加州大学伯克利分校拿到博士学位。他投身于新兴的计算机领域，在 1962 年一份开创性的报告里汇集了自己的想法，报告名叫《增强人类智力》（Augmenting Human Intellect）。

恩格尔巴特认为，人类面临的问题变复杂的速度，比我们解决问题能力增长的速度更快。因此，找到增强智力的方法，似乎既必要又值得追求。他看到计算机的用处不只是自动化，还可以成为未来知识工作者应对复杂问题必不可少的交互式工具。

伊凡·苏泽兰不久前演示的 Sketchpad 进一步启发了他。恩格尔巴特决定动手把愿景变成现实，招募团队来做 oN-Line System（NLS）。他意识到，对他想实现的那类程序来说，只有键盘是不够的。用他的话说：

"我们设想解决问题的人用计算机辅助工作站来增强他们的工作。他们需要和屏幕上显示的信息互动，用某种设备在屏幕上移动[光标]。"

1964 年，他和同事比尔·英格利希（Bill English）一起，造出了第一个计算机鼠标。线从设备的尾部伸出来，看起来很像一只老鼠，于是"鼠标"这个外号就沿用了下来。

演示之母

1968 年，恩格尔巴特在"秋季联合计算机会议"上展示了他的整个系统，这次演示常被称为"演示之母"（the mother of all demos）。演示长 90 分钟，展示了现代计算的很多功能：位图图形、视频会议、文字处理，以及多人实时协作编辑文档。还有现代图形界面的雏形，比如鼠标和多窗口——不过窗口还不能互相重叠。

它远远领先于那个时代，而且和很多贴着这个标签的产品一样，最终失败了，至少在商业上是这样。但它对当时的计算机研究者影响巨大。恩格尔巴特因为这个计算史上的分水岭时刻，获得了 1997 年的图灵奖。

你每天都在用它的后代 "多人实时协作编辑文档"——这就是今天的在线文档、Figma 一类工具。1968 年的演示里已经有了，只是又过了四十多年，网络和浏览器才让它普及。
第 2 节

施乐奥托：桌面隐喻与 WIMP

1970 年代初，政府资金开始减少，这在两集前（第 24 集）讲过。那时恩格尔巴特团队里的很多人，包括比尔·英格利希，去了施乐公司新成立的帕洛阿尔托研究中心，更常被叫作 Xerox PARC。第一台真正带图形界面的计算机就是在这里开发的：施乐奥托（Xerox Alto），1973 年完成。

要让计算机好用，光有花哨的图形还不够。它需要围绕一个人们已经熟悉的概念来设计，让人几乎不用培训，一眼就明白怎么用。施乐的答案是：把二维屏幕当成一张桌面（desktop）。

就像桌上可以摊开很多张纸一样，用户可以同时打开好几个程序。每个程序都待在自己的框里，这个框提供了看向程序的视野，叫作窗口（window）。也像桌上的纸一样，窗口可以互相重叠，挡住后面的东西。还有桌面小配件，比如计算器和时钟，用户可以把它们放在屏幕上，随意挪动。

不过它并不是照搬真实的桌面，而是用桌面做一个隐喻。所以——毫不意外——它叫"桌面隐喻"（Desktop Metaphor）。

设计这样的界面有很多种方法，但 Alto 团队用的是窗口、图标、菜单和指针，所以叫 WIMP 界面（Windows、Icons、Menus、Pointer）。今天大部分桌面图形界面用的都是它。

它还提供了一套基本的部件（widget）：可复用的图形积木，比如按钮、复选框、滑动条和标签页。这些也都取材于现实世界的物品，让人觉得熟悉。图形界面程序就是由这些部件搭起来的。下面就用这种新的编程范式，写一个简单的例子试试。

第 3 节

事件驱动编程：掷一个二十面骰子

首先，得告诉操作系统，为我们的程序新建一个窗口。这要通过 GUI API 来做，需要指定窗口的名字和大小，比如 500×500 像素。

然后加几个部件：一个文本框和一个按钮。创建它们需要几个参数。首先要指定它们出现在哪个窗口里，因为一个程序可以有多个窗口；还要指定默认文字、在窗口里的 X、Y 位置，以及宽度和高度。

好，现在我们有了一个看起来像图形界面程序的东西，但它还没有任何功能。点 "Roll" 按钮，什么也不会发生。

之前讨论的例子里，代码基本是从上到下执行的。而图形界面用的是所谓的事件驱动编程（event-driven programming）：代码可以在任何时候、以不同的顺序执行，来响应事件。这里是用户触发的事件，比如点按钮、选菜单项、滚动窗口。要是一只猫踩过你的键盘，那就是一下子来了一大堆事件！

假设用户点 "Roll" 按钮时，我们想随机生成一个 1 到 20 之间的数，然后显示在文本框里。可以写一个函数专门做这件事。还可以玩得花一点：如果掷出 20，就把窗口背景变成血红色！

最后要做的，是把这段代码"挂"上去，让每次点按钮时都触发它。为此，要在初始化函数里加一行，声明我们的函数负责"处理"这个按钮的这个事件。这里事件的类型是点击事件，我们的函数就是这个事件的事件处理函数（event handler）。

第 4 节

  
施乐之星：剪切、复制、粘贴与所见即所得

  
奥托大约造了 2000 台，在施乐内部使用，也送给大学实验室，但从来没有商业出售过。PARC 团队不断改进硬件和软件，最终在 1981 年发布了施乐之星（Xerox Star）系统。

  
施乐之星扩展了桌面隐喻。现在文件看起来就像一张张纸，可以放进小文件夹里，这些都能摆在桌面上，或者收进数字文件柜。这是盖在底层文件系统之上的一层隐喻。从用户的角度看，这是一层新的抽象！

  
施乐是做复印机生意的，在文字和图形制作工具上也有很多进展。比如，是他们提出了"剪切""复制""粘贴"这些术语。这个比喻来自人们修改打字机文档的方式：真的是用剪刀把文字剪下来，再用胶水贴到另一份文档里你想要的位置。然后把这一页复印一遍，压回单独一层，修改的痕迹就看不出来了。


  

    
  


  
谢天谢地有了计算机！文字处理软件出现后，这种手工做法就没有意义了，Apple II 和 Commodore PET 这样的平台上都有文字处理软件。但施乐比竞争对手走得远得多，他们的理念是：你在计算机上做出来的任何东西，打印出来都应该和屏幕上一模一样。他们把这叫作"所见即所得"（What You See Is What You Get，WYSIWYG）。

  
不幸的是，就像恩格尔巴特的 oN-Line System 一样，施乐之星也领先于时代。销量很差，因为在办公室配一套，价格相当于今天的将近 20 万美元。而且同一年 IBM PC 发布了，紧接着便宜的"IBM 兼容"克隆机像海啸一样涌来，这也没帮上忙。







  
第 5 节

  
苹果：Lisa 与 Macintosh

  
但 PARC 研究人员培育了将近十年的好点子并没有白费。1979 年 12 月，施乐之星出货前一年半，一个你可能听说过的人来参观了：史蒂夫·乔布斯。

  
关于这次参观有很多传说，很多人说乔布斯和苹果偷了施乐的创意。但这根本不是事实。实际上，是施乐主动找苹果，希望合作。最终施乐在苹果备受期待的首次公开募股（IPO）之前，买下了价值一百万美元的苹果股份——但附带一个额外条款："公开施乐 PARC 正在做的一切酷东西"。

  
史蒂夫知道 PARC 有计算机领域最聪明的一批人，但他还是没想到会看到那些东西。其中有一个演示：在清晰的位图显示器上运行着施乐的图形界面，全靠直观的鼠标操作。史蒂夫后来说：

  
"就像蒙在眼前的一层纱被揭开了。我看到了计算机注定要走向的未来。"

  
史蒂夫带着随行的工程师回到苹果，开始发明新功能，比如菜单栏，以及存放待删除文件的垃圾桶——满了还会鼓起来，又是隐喻。


  

    
  


  
苹果第一款带图形界面和鼠标的产品，是 1983 年发布的 Apple Lisa。一台超级先进的机器，配了一个超级先进的价格——差不多相当于今天的 2.5 万美元。这比施乐之星便宜多了，但在市场上同样失败。

  
幸运的是，苹果手里还有另一个项目：一年后、1984 年发布的 Macintosh。价格大约相当于今天的 6000 美元，是 Lisa 的四分之一。它打中了，开售头 100 天就卖了 7 万台。

  
但最初的狂热过去后，销量开始下滑，苹果卖出的 Apple II 比 Mac 还多。一个大问题是：没人给这台界面激进的新机器写软件。情况还在变糟——竞争对手很快追了上来。不久，价格只有 Mac 几分之一的其他个人计算机，也有了简陋但能用的图形界面。消费者买账，PC 软件开发者也买账。随着苹果的财务状况越来越糟，加上和苹果新任 CEO 约翰·斯卡利的矛盾越来越深，史蒂夫·乔布斯被赶出了苹果。







  
第 6 节

  
Windows 与界面的"自然选择"

  
几个月后，微软发布了 Windows 1.0。它也许不如 Mac OS 漂亮，但这是一场激烈竞争的第一枪，微软后来几乎统治了这个行业：十年内，将近 95% 的个人计算机上运行着微软 Windows。

  
起初，Mac OS 的粉丝可以理直气壮地说 Mac 的图形和易用性更好。Windows 早期版本都建立在 DOS 之上，而 DOS 设计时从没想过要跑图形界面。但在 Windows 3.1 之后，微软开始开发一个新的、面向消费者的操作系统，带升级版图形界面，叫 Windows 95。这是一次重大的重写，提供的不只是更精致的图形，还有 Mac OS 当时没有的高级功能，比如程序多任务和受保护内存（第 18 集讲过）。Windows 95 引入了很多今天的 Windows 里还能看到的界面元素，比如开始菜单、任务栏和 Windows 资源管理器。

  
不过微软也不是没失过手。为了让桌面隐喻更简单友好，微软做了一个叫 Microsoft Bob 的产品，把隐喻用到了极致：屏幕上是一整个虚拟房间，程序变成了物品，可以放在桌子上、书架上。甚至还有噼啪作响的壁炉，和一只提供帮助的虚拟小狗。看到两边的门了吗？对，它们通向计算机里的其他房间，那里有别的程序。你可能猜到了，它没有成功。


  

    
  


  
这个好例子说明，我们今天用着顺手的用户界面，本质上是自然选择的产物。不管你用的是 Windows、Mac、Linux 还是别的桌面图形界面，它几乎一定是施乐奥托首创的 WIMP 范式的进化版。这一路上，人们试过很多糟糕的点子，失败了。一切都必须被发明、测试、改进，然后被采纳或者被抛弃。

  
今天图形界面无处不在。它们不错，但并不总是很好。你肯定也遇到过和设计有关的糟心时刻：下载了某个 App、用别人的手机，或者打开某个网站。正因如此，计算机科学家和界面设计师还在努力，想做出既更容易用、又更强大的计算体验——最终，朝着恩格尔巴特"增强人类智力"的愿景前进。我们下周见！

    一句话
    图形界面把"记住命令"变成"看见选项"，核心是借用熟悉事物的隐喻（桌面、窗口、文件夹、垃圾桶、剪切粘贴）和 WIMP 范式；写图形界面程序要换一种思路——事件驱动：不按从上到下的顺序跑，而是事件来了，就调用挂在它上面的处理函数。
  


  
合上页面，试着回答

  

    

      
1. WIMP 指什么？"桌面隐喻"为什么能让人不经培训就会用？

      
      
窗口（Windows）、图标（Icons）、菜单（Menus）、指针（Pointer）。桌面隐喻借用人们熟悉的办公桌：窗口像摊开的纸、可以互相重叠，文件像纸、可以放进文件夹，还有计算器时钟等小配件，人们一看就能联想到怎么用。

    

    

      
2. 事件驱动编程和之前"从上到下执行"有什么不同？Roll D20 的例子里，哪一行把代码和按钮连起来？

      
      
事件驱动的代码可以在任何时间、以任何顺序执行，取决于发生了什么事件（点击、选菜单、滚动）。在初始化函数里加的那一行——声明 rollD20 是这个按钮"点击事件"的处理函数——把两者连了起来，此后每次点击都会派发执行 rollD20。

    

    

      
3. "剪切""复制""粘贴"这几个词从哪来？什么是"所见即所得"？

      
      
来自修改打字机文档的做法：用剪刀剪下文字，用胶水贴到另一份文档，再复印一遍抹平痕迹。施乐把这些词用到了计算机上。所见即所得（WYSIWYG）指屏幕上做出来的东西，打印出来和屏幕上一模一样。

    

    

      
4. 施乐奥托和施乐之星技术领先，为什么商业上没成功？Macintosh 初期又遇到了什么问题？

      
      
奥托从没商业出售；施乐之星太贵（一套相当于今天近 20 万美元），又赶上同年 IBM PC 和大量便宜的兼容机。Mac 价格降到 Lisa 的四分之一，开局很好，但没人为它写软件，而价格低得多的 PC 很快也有了能用的图形界面。
