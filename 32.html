黑客与攻击

Hackers & Cyber Attacks

上一集讲了怎么保护系统，这一集反过来，看看攻击者是怎么进来的。最常见的办法根本不是"黑"，而是骗人；其余的则是钻程序的漏洞。了解这些经典套路，不是为了去攻击谁，而是为了认得出它们、挡得住它们。

第 0 节

不是所有黑客都是坏人

嗨，我是 Carrie Anne，欢迎收看计算机科学速成课！上一集我们讲了计算机安全的基础知识，也就是用来让系统平安无事的各种原则和技术。但尽管大家尽了最大努力，新闻里还是充满了个人、公司和政府被黑客攻击的故事。这些黑客，凭着自己的技术知识，闯进了计算机系统。

不过，并不是所有黑客都是坏人。有些黑客专门寻找漏洞、设法堵上软件里的安全漏洞，让系统更安全、更有韧性，他们常被公司和政府雇来做安全评估。这些黑客叫白帽（White Hat），他们是好人。另一面是黑帽（Black Hat）：怀着窃取、利用、贩卖计算机漏洞和数据的意图的恶意黑客。黑客的动机也千差万别：有人是为了好玩和好奇；网络罪犯大多是为了钱；还有黑客行动主义者（hacktivist），用技术去推动某个社会或政治目标。而这些还只是冰山一角。

基本上，那种"黑客是一个待在堆满披萨盒的黑屋子里、不受欢迎的小孩"的刻板印象，拿来形容大学时代的 John Green 可能还更贴切些，而不是真正的黑客。

今天，我们不会教你怎么成为黑客。我们要做的，是讨论几个经典的例子，说明黑客是怎么闯进计算机系统的，让你对这件事有个大致概念——这样你才知道该防什么。

第 1 节

社会工程学：骗，比黑更容易

保护计算机系统、网络和数据的办法有很多，但黑客进入系统最常见的方式，根本不是去"黑"——而是骗用户把他们放进来。这叫社会工程学（social engineering）：通过操纵，让一个人泄露机密信息，或者把计算机系统配置成允许攻击者进入的样子。

最常见的一种攻击是网络钓鱼（phishing）。你最常遇到的形式是一封邮件，叫你登录某个网站的账户，比如你的银行。邮件会让你点里面的一个链接，把你带到一个在不仔细看的人眼里很正规的网站，但它其实是个恶意的克隆。当你输入用户名和密码时，这些信息就直接发给了黑客，然后他们就能以你的身份登录真正的网站。坏消息！即使成功率只有千分之一，发一百万封钓鱼邮件，也可能骗到一千个账户。

页面内容能一字不差地照抄，唯一骗不了人的是地址栏。
浏览器和习惯怎么帮你挡钓鱼 真正要看的是域名的主体部分：mybank.secure-login.com 的主体是 secure-login.com，mybank 只是它的子域名，和真正的 mybank.com 毫无关系。此外：地址栏的小锁只代表"传输加密"，不代表"这家是真的"；浏览器的安全浏览（Safe Browsing）会拦下已知的钓鱼站；而密码管理器有个隐藏的好处——它只在域名完全匹配时才自动填充，域名一不对就不填，相当于替你多看了一眼。

另一种社会工程学攻击叫假托（pretexting）：攻击者打电话给一家公司，然后信心十足地假装自己是他们 IT 部门的人。攻击者常常先打第一个号码，再请对方把电话转接到第二个号码，这样接电话的人看到的号码就像是公司内部的。然后，攻击者就能指挥一个毫不知情的用户把电脑配置成容易被攻击的样子，或者让他们泄露密码、网络配置之类的机密细节。

——不好意思，等一下。哦，嘿，我是 IT 部门的 Susan。我们这边遇到点网络问题，你能帮我查一个设置吗？……然后，就开始了。

攻击者可以装得非常像真的，尤其是事先做一点功课，查到关键员工的名字之类的信息。也许要打十个电话才能找到一个上当的人，但只要一个人中招就够进去了。

第 2 节

木马与恶意软件

邮件也是木马（trojan horse）常见的投送方式。木马是伪装成无害附件的程序，比如一张照片或一份发票，实际上却装着恶意软件，也就是 malware。恶意软件有很多种形态：有的会偷你的数据，比如你的银行凭证；有的会加密你的文件，然后勒索赎金，这就是所谓的勒索软件（ransomware）。

这里的关键词是伪装：文件图标、后缀、名字都可以造假，一个叫 发票.pdf.exe 的文件，在默认隐藏后缀的系统里看起来就是一张 PDF。所以上一集那条底线依旧成立——永远不要点陌生邮件里的附件和链接。

第 3 节

硬闯：暴力破解与 NAND 镜像

如果攻击者没法运行恶意软件，也骗不到用户放他进来，那就只能用别的手段强行闯入了。其中一种方法我们上一集简单讲过，就是暴力破解密码：把所有密码组合挨个试一遍，直到进去为止。大多数现代系统会这样防御这类攻击——每失败一次，就让你等更久一点，甚至在失败一定次数后干脆把你锁在外面。

最近有一种绕过这种防御的攻破方法，叫 NAND 镜像（NAND Mirroring）：如果你能物理接触到这台计算机，就可以往它的内存芯片上接几根线，把里面的内容完整复制一份。有了这套装置，你就可以试一串密码，直到设备开始让你等待；一旦这样，你就把之前复制的原始内容重新刷回内存，相当于把它重置了，于是可以立刻、不用等待地继续试更多密码。这项技术曾被证明在 iPhone 5C 上奏效，但许多更新的设备已经加入了阻止这类攻击的机制。

第 4 节

缓冲区溢出

如果你没法物理接触一台设备，就得想办法远程攻击它，比如通过互联网。一般来说，这需要攻击者找到并利用系统里的一个 bug。成功利用一个 bug 来获得某种能力或访问权，就叫一次漏洞利用（exploit）。

一种常见的漏洞利用是缓冲区溢出（buffer overflow）。"缓冲区"是个统称，指预留出来存放数据的一块内存。我们在第 23 集讲过存像素数据的视频缓冲区。举个简单的例子，想象一个操作系统的登录界面，有用户名和密码两个输入框。在幕后，这个操作系统用缓冲区来存放输入进来的文本值。为了方便说明，假设这些缓冲区被定在大小为 10。于是在内存里，这两个文本缓冲区大概长这样。当然，操作系统记录的远不止用户名和密码，所以内存里这两个缓冲区的前后还会存着别的数据。

当用户输入用户名和密码时，这些值会被复制进缓冲区，在那里接受校验。而缓冲区溢出攻击做的正是它名字所说的事：把缓冲区撑爆。在这个例子里，任何长度超过 10 个字符的密码，都会覆盖掉内存里相邻的数据。有时这只会让程序或操作系统崩溃，因为重要的值被一堆乱码覆盖掉了。让系统崩溃是坏事，也许一个搞恶作剧的黑客想要的就只是这个——当个讨厌鬼。

但攻击者也可以更聪明地利用这个 bug，往程序内存里注入有意的新值，比如把一个"是否管理员"（is_admin）的变量设成 true。一旦有了任意篡改程序内存的能力，黑客就能绕过登录之类的检查，有时甚至能利用那个程序劫持整个系统。

动手：把密码撑出缓冲区

防御

对付缓冲区溢出的方法有很多。最简单的是在把输入复制进缓冲区之前，总是先检查它的长度，这叫边界检查（bounds checking）。许多现代编程语言会自动做边界检查。程序还可以把变量（比如我们假设的那个 is_admin 标志）在内存里的位置随机化，这样黑客就不知道该覆盖哪块内存，结果更可能是把程序搞崩，而不是拿到访问权。程序也可以在缓冲区后面留一些不用的空间，盯着这些值看它们有没有变化；一旦变了，就知道有攻击者在乱动内存。这些不用的内存区域叫金丝雀（canary），得名于矿工从前带下矿井、用来预警危险的小鸟。

为什么你写前端时不太会碰到它 缓冲区溢出几乎是 C/C++ 这类"你自己管内存"的语言的专利。JavaScript、Python、Java、Rust 等语言默认就做边界检查、或根本不让你直接操作裸内存，数组越界会抛异常而不是悄悄覆盖别的数据。所以前端日常很少直接遇到它——但你用的运行时、解析库底层往往还是 C 写的，这也是为什么浏览器的安全更新那么频繁。
第 5 节

代码注入

另一种经典手段是代码注入（code injection）。它最常用来攻击使用数据库的网站，而几乎所有大网站都用数据库。我们这个系列不会专门讲数据库，所以这里用一个简单的例子来说明这类攻击。我们会用结构化查询语言（Structured Query Language，SQL，也念作 sequel），一种流行的数据库接口。

想象我们的登录界面现在跑在一个网页上。当用户点"登录"时，文本值被发到服务器，服务器执行代码，检查这个用户名是否存在，如果存在，再核对密码是否匹配。为此，服务器会执行一段叫 SQL 查询的代码。首先，它要指明我们从数据库里取什么数据——在这个例子里，我们要取密码（SELECT password）。它还要指明从数据库的什么地方取——这里假设所有用户数据都存在一个叫 users 的表里（FROM users）。最后，服务器不想取回数据库里每个用户的一长串密码，所以它指定只要用户名等于某个值的那条数据（WHERE username='...'）。用户输入的值会被服务器复制进这条查询里。还要注意，SQL 命令以分号结尾。

那怎么破解这个？办法是提交一个嵌了 SQL 命令的恶意用户名！正如前面提到的，分号用来分隔命令。当服务器把这个古怪的用户名复制进查询，整条语句就被拆成了两条命令：第一条去查一个多半不存在的用户（于是被拒绝，但攻击者根本不在乎），真正想要的是下一条命令——DROP TABLE users，一条我们通过摆弄用户名输入框注入进去的命令，它指示数据库把存着所有用户数据的那张表删掉。全删干净！这在银行之类的地方会造成天大的麻烦。注意，我们甚至都没有闯进系统——我们并没有猜对某个用户名和密码。即使没有任何正式的访问权，我们也靠利用一个 bug 制造了一场灾难。

这是代码注入一个非常简单的例子，如今几乎所有服务器都会防御这种手段。用更复杂的指令，有可能往数据库里添加记录（比如一个新的管理员账户），甚至让数据库吐出数据，使黑客能窃取信用卡号、社保号之类的东西。但我们不会教你具体怎么做。和缓冲区溢出一样，程序员应该始终假定来自外部的输入是危险的，并仔细检查它。网页上大多数用户名和密码表单，作为第一道防线，不让你输入分号或引号（字幕作"括号"，英文原文是 quotes，即引号）这样的特殊符号。好的服务器还会在执行数据库查询之前，通过删除或修改特殊字符来清理（sanitize）输入。

今天真正的防法：别把输入当代码 现代做法的核心是参数化查询（prepared statement）：把 SQL 语句的骨架和用户填的值分开传给数据库，数据库从头到尾只把用户输入当"数据"，绝不当"命令"，于是 '; DROP TABLE 只会被当成一个（很奇怪的）用户名去查，什么也删不掉。各种 ORM 框架默认就这么做。顺带一提，前端还有个同源的毛病叫 XSS（跨站脚本）——把用户输入当 HTML/JS 执行了。防法也类似：输出到页面前先转义；React、Vue 默认转义文本，再配一条 Content-Security-Policy 响应头，就挡掉了大半。
第 6 节

漏洞、零日、蠕虫与僵尸网络

可用的漏洞利用常常在网上被贩卖或分享。一个 bug 越普遍，或者一个漏洞利用危害越大，它能卖出的价钱或带来的名气就越高。甚至连政府有时也会买漏洞利用，好让他们能侵入计算机做间谍之类的事。当一个可被利用的新 bug 被发现，而软件的制造者还不知道它的存在，这就叫一个零日漏洞（zero day vulnerability）。黑帽黑客会抢在白帽程序员为这个 bug 发布补丁之前，争分夺秒地利用它谋取最大利益。这就是为什么及时更新你电脑的软件如此重要——那些下载里有很大一部分是安全补丁。

如果足够多的系统上留着没堵上的 bug，黑客就能写一个程序，让它自动从一台计算机跳到另一台计算机，这种程序叫蠕虫（worm）。如果黑客能控制大量计算机，这些计算机就能被合起来使用，组成所谓的僵尸网络（botnet）。它可以有很多用途：比如发送海量垃圾邮件；用别人的算力和电费去挖比特币；以及对服务器发起分布式拒绝服务（Distributed Denial of Service，DDoS）攻击。DDoS 就是让僵尸网络里的所有计算机一起发出一大堆假消息，把服务冲垮下线，要么逼服务的主人交赎金，要么纯粹是为了作恶。

动手：一个僵尸网络能压垮多大的服务器

僵尸网络规模

尽管白帽们辛勤工作、漏洞利用的资料都记录在网上、软件工程也有种种最佳实践，网络攻击还是每天都在发生。它们每年给全球经济造成大约五千亿美元的损失，而且随着我们越来越依赖计算机系统，这个数字只会上升。这尤其让各国政府担心，因为基础设施越来越由计算机驱动：发电厂、电网、红绿灯、水处理厂、炼油厂、空中交通管制，以及许许多多其他关键系统。

许多专家预测，下一场大战将在网络空间里打响：一个个国家不是被物理攻击击垮，而是通过网络战在经济上、基础设施上被瘫痪。也许不会有一颗子弹射出，但人员伤亡的可能性依然很高——甚至可能高于传统战争。

所以，我们都应该养成良好的网络安全习惯。作为一个通过互联网彼此相连的共同体，我们应该确保自己的计算机，能抵御那些想把计算机的巨大潜能用于作恶的人。所以，也许别再忽略那条更新提示了？我们下周见。

第 7 节

本集小结

概念要点
白帽 / 黑帽同样的技术，差别在动机和是否获得授权；动机有好奇、牟利、黑客行动主义
社会工程学钓鱼（假登录页）、假托（假冒 IT 打电话）；骗人比黑系统容易
木马 / 恶意软件伪装成无害附件；偷数据、勒索软件（加密文件要赎金）
暴力破解 / NAND 镜像挨个试密码；靠锁定、增量等待防御；NAND 镜像靠刷回内存绕过锁定
缓冲区溢出超长输入覆盖相邻内存，可篡改 is_admin；防御：边界检查、地址随机化、金丝雀
代码注入 / SQL 注入把 SQL 命令塞进输入框；防御：清理输入、参数化查询
零日漏洞制造者还不知道的新漏洞；黑帽抢在补丁前利用，所以要及时更新
蠕虫 / 僵尸网络 / DDoS蠕虫自动传播；僵尸网络发垃圾邮件、挖矿、用海量假请求冲垮服务器
一句话 攻击者进系统最省力的办法是骗人（社会工程学），其次才是钻程序的漏洞（缓冲区溢出、代码注入）；拿下很多机器后还能组成僵尸网络发起 DDoS。对应的防线也很朴素：不轻信陌生链接和来电、把外部输入一律当危险品检查、及时打补丁。没有绝对安全，只能层层设防、把损害关小。

1. 为什么说"骗人比黑系统容易"？钓鱼和假托各骗的是什么？
因为技术防御再强，也挡不住用户自己把门打开。钓鱼用一个假登录页骗你亲手输入用户名和密码；假托靠假冒 IT 部门打电话，骗你泄露密码、配置，或者把电脑设置成容易被攻击的样子。
2. 系统"错几次就锁定"，为什么挡不住 NAND 镜像？
锁定靠的是"越错越慢"的计时器，而计时器的状态也存在内存里。NAND 镜像事先把内存复制了一份，一旦开始被迫等待，就把原始内容刷回去，相当于把计时器清零，于是可以不受限制地继续试密码。前提是攻击者能物理接触设备。
3. 缓冲区溢出是怎么把 is_admin 改成 true 的？有哪些防御？
缓冲区大小固定（比如 10），如果不检查长度就把更长的输入复制进去，多出来的字符会覆盖相邻内存，正好盖在 is_admin 这个变量上，把它改成 true。防御：复制前做边界检查、把变量位置随机化、在缓冲区后放"金丝雀"值监测是否被改动。
4. whatever'; DROP TABLE users; -- 这个用户名为什么能删库？
服务器把用户名直接拼进 SQL 查询，分号又能分隔命令，于是整条语句被拆成两条：先查一个不存在的用户（被拒），再执行注入进来的 DROP TABLE users 删掉整张用户表；末尾的 -- 把原来的收尾注释掉。攻击者根本没登录，只是利用了"输入被当成代码"。
5. 为什么"参数化查询"能挡住 SQL 注入？
参数化把查询的骨架和用户填的值分开传给数据库，数据库始终把用户输入当"数据"而不是"命令"。于是哪怕输入里有分号和 DROP TABLE，也只会被当成一个奇怪的用户名去查，什么都执行不了。
6. "零日漏洞"为什么危险？普通用户能做什么？
零日是制造者还不知道、还没补丁的漏洞，黑帽会抢在补丁发布前利用它。普通用户能做的最重要的一件事就是及时更新软件——很多更新本身就是安全补丁；再加上开启双因素认证、用密码管理器、不点陌生链接。
