# Java 后端课 · 主线草案

状态：**方向和篇幅已确认**（2026-11-12）。逐篇写，写一篇确认一篇；具体篇目写的过程中可以合并或拆分。

## 一、这门课是什么

- **读者**：会编程的前端开发者。前端知识只在一句话能说清的地方顺带提，不当主线。
- **终点**：走到后端的核心，并且能上手公司项目（BladeX，Java 8、Spring Boot 2、Spring Cloud、Nacos、MyBatis-Plus、Redis）。
- **不求速成**：约 85 篇，每篇是一次能读完的量。篇数是内容决定的，不是目标。
- **不讲**：人人都会的编程基础只用一篇带过；和后端无关的旧内容（Swing 界面等）不讲。

## 二、设计思路

后端代码可以分三层看：

| 层 | 是什么 | 例子 |
|---|---|---|
| 表层 | 你每天亲手写的 | Controller、Service、Mapper、实体类 |
| 中层 | 框架替你做的 | Spring、MyBatis-Plus、BladeTool |
| 底层 | 框架之所以能做到的原因 | 对象和类型、集合、并发、JVM、网络、数据库 |

速成课只讲表层，所以学完会写但不知道为什么。这门课先给一眼表层的全貌，然后从底层往上搭，搭到中层时，框架的每个功能都是“前面已经见过的东西”，最后回到表层和你们的项目。

贯穿全程的四个写法：

1. **每一部分回答一个问题**，这个问题是上一部分留下的。
2. **先亲手造一个小的，再用现成的大的**。计划造的有：`ArrayList`、`HashMap`、HTTP 服务器、Mapper、依赖注入容器。
3. **一个小项目从第 5 部分起一直长到最后**，每篇给它加一块。
4. **代码全部实际运行过**（本机 JDK 8）。
5. **每篇末尾列参考资料**，写明每条支撑的是文中哪句话；链接和原文逐条打开核对。没有出处、只凭推断的地方在页面上标出来。
6. **不写空话**：每句话说具体的东西，不编数字，不下笼统的结论。

## 三、依据

### 1. 实测：开源版 SpringBlade 3.7.1

BladeX 源码不公开，用它的开源版 SpringBlade 代替。取 v3.7.1，这是最后一个 Java 8 版本（Spring Boot 2.7.18、Spring Cloud 2021.0.8、Nacos 2.1.2）。统计范围是它的业务代码：223 个 Java 文件、14,358 行、23 个 Mapper XML。

| 统计项 | 数量 | 说明了什么 |
|---|---|---|
| `extends` / `implements` / `interface` | 121 / 71 / 58 行 | 一半以上的文件都在继承或实现别的东西，继承、接口、多态必须讲透 |
| 接口文档注解（`@ApiOperation` 等） | 400 行以上 | 出现最多的注解不是 Spring 的，是接口文档的 |
| `@GetMapping` / `@PostMapping` | 112 / 68 | 写接口是日常 |
| `@AllArgsConstructor` | 49 | 依赖注入用的是构造器注入，不是教程里常见的 `@Autowired` |
| MyBatis-Plus 的引用 | 182 处 | 引用最多的类库 |
| Mapper XML：`<select>` / 增删改 | 40 / 0 | 增删改全交给 MyBatis-Plus，手写 SQL 只用于查询 |
| `R.` / `IPage` / `Func.` / `Condition.` | 151 / 111 / 97 / 44 行 | BladeTool 的工具比 Java 标准库用得还多 |
| `->` / `::` / `.stream()` | 25 / 36 / 17 行 | Lambda 和 Stream 有，但不算多 |
| `synchronized`、线程相关 | 0 | 见下方说明 |
| 自己定义的泛型、`abstract class`、`while` | 0 | 同上 |
| `try` / `@Transactional` | 4 / 5 | 同上 |
| 启动类 | 14 个 | 14 个独立服务 |
| Feign 客户端 / 降级类 | 15 / 5 | 服务之间互相调用是常态 |
| Dockerfile | 12 个 | 部署方式是容器 |
| 配置文件 | dev、test、prod 各一套 | 多环境配置必须讲 |

**这组数字怎么用**：它说明表层长什么样，决定例子怎么选、先讲什么。它**不能**用来决定砍掉什么。并发、泛型、异常、事务在业务代码里几乎为零，是因为框架把它们接过去了，而不是因为不重要：每个 Controller 都是被很多线程同时调用的。这正是要讲底层的理由。

**这组数字的局限**：

- 它是开源版，不是你们的 BladeX。
- 它是示例规模的代码，业务逻辑很薄，真实项目里异常处理、事务、金额计算会多得多。
- BladeTool 本身的源码没有统计（下载被中断，没有再下）。

## 四、主线

### 第 0 部分 · 出发前（3 篇）

- 0.1 一个请求的一生：从点下按钮到数据落库，全景图
- 0.2 Java 是怎么跑起来的：源码、字节码、JVM；命令行编译运行，再搬进 IDEA
- 0.3 语法速览：变量、分支、循环、方法、数组在 Java 里怎么写

依据：读者会编程。黑马上部用约 15 小时讲的基础语法（P17–P73），这里压成 0.3 一篇。

### 第 1 部分 · 对象与类型（10 篇）

要回答的问题：Java 为什么什么都要写成类，还要标类型？

- 1.1 数值类型和它的坑：整数除法、溢出、浮点误差、`BigDecimal`
- 1.2 引用和内存：栈、堆、参数传递到底传了什么、`null`
- 1.3 `String`：不可变、常量池、`==` 和 `equals`
- 1.4 类和对象：字段、方法、构造器、封装、包和访问修饰符
- 1.5 `static` 和 `final`
- 1.6 继承和多态：运行时到底调用了谁
- 1.7 接口和抽象类：面向接口编程
- 1.8 `equals`、`hashCode`、`toString`
- 1.9 枚举、内部类、匿名类
- 1.10 异常：体系、受检和非受检、怎么抛、怎么接

依据：实测里一半以上的文件在继承或实现；《Head First Java》第 2–10、13 章。

### 第 2 部分 · 集合与函数式（8 篇）

要回答的问题：一堆对象放在哪、怎么加工？

- 2.1 泛型：为什么需要、怎么读尖括号、类型擦除
- 2.2 `List`：亲手写一个 `ArrayList`，看它怎么长大
- 2.3 `Map` 和 `Set`：亲手写一个 `HashMap`
- 2.4 排序和比较：`Comparable`、`Comparator`、`TreeMap`
- 2.5 Lambda 和函数式接口
- 2.6 Stream
- 2.7 `Optional` 和空值
- 2.8 日期时间和常用工具类

依据：`java.util` 是引用第三多的包；分页结果 `IPage` 出现 111 行；MyBatis-Plus 的条件写法依赖方法引用。哈希表的原理后面讲 Redis 和数据库索引时还要用。

### 第 3 部分 · 语言之下：IO、网络、并发、JVM（11 篇）

要回答的问题：一个程序怎么同时服务成千上万人？

- 3.1 IO：字节、字符、编码、文件、缓冲
- 3.2 网络：Socket，然后亲手写一个最小的 HTTP 服务器
- 3.3 线程：为什么服务器必须多线程
- 3.4 线程安全：竞态条件、`synchronized`、`volatile`、原子类
- 3.5 线程池、`Future`、`CompletableFuture`
- 3.6 锁和并发容器
- 3.7 `ThreadLocal`：一次请求里“当前用户是谁”存在哪
- 3.8 JVM 内存和垃圾回收：对象的一生
- 3.9 类加载
- 3.10 反射和注解：框架靠什么读懂你的代码
- 3.11 动态代理：不改代码就给方法加功能

依据：业务代码里线程相关为零，是因为 Tomcat 和 Spring 接管了，风险还在。实测里有 23 个 Mapper、15 个 Feign 客户端只有接口没有实现类，它们能工作靠的就是 3.10 和 3.11。

### 第 4 部分 · 工程（5 篇）

要回答的问题：一个人的代码怎么变成一个团队的工程？

- 4.1 Maven：依赖、生命周期、仓库
- 4.2 多模块工程和版本管理
- 4.3 单元测试
- 4.4 日志：打什么、怎么打、怎么查
- 4.5 在框架里认出设计模式

依据：SpringBlade 是二十多个 Maven 模块组成的工程。

### 第 5 部分 · 数据库（10 篇）

要回答的问题：数据放在哪，怎么保证不丢、不乱、查得快？

- 5.1 关系模型和 SQL 入门
- 5.2 查询进阶：联表、分组、子查询
- 5.3 表设计
- 5.4 索引：B+ 树、最左前缀、读懂执行计划
- 5.5 事务：ACID、隔离级别、MVCC
- 5.6 锁和并发更新
- 5.7 JDBC 和连接池：亲手写一个最小的 Mapper
- 5.8 MyBatis：Mapper、XML、动态 SQL
- 5.9 MyBatis-Plus：通用增删改查、条件构造器、分页
- 5.10 MyBatis-Plus 进阶：逻辑删除、自动填充、多租户

依据：MyBatis-Plus 是引用最多的类库；XML 里只有查询，所以 5.8 重点放在查询和结果映射上。

### 第 6 部分 · Spring（13 篇）

要回答的问题：为什么大家都不自己 `new` 对象了？

- 6.1 从 Servlet 到 Spring MVC：把 3.2 的小服务器换成 Tomcat
- 6.2 控制反转和依赖注入：亲手写一个迷你容器
- 6.3 Bean：生命周期、作用域、三种注入方式
- 6.4 Spring Boot：自动配置和 starter 是怎么回事
- 6.5 配置文件和多环境
- 6.6 Web 层：路由、参数绑定、JSON
- 6.7 参数校验、统一返回、全局异常处理
- 6.8 接口设计和接口文档
- 6.9 AOP：原理和用法
- 6.10 声明式事务：原理、传播行为、失效场景
- 6.11 过滤器和拦截器
- 6.12 认证和授权：Session、JWT、OAuth2、密码怎么存
- 6.13 文件上传、Excel 导入导出、定时任务、异步

依据：路由注解和接口文档注解是出现最多的两类；注入方式以构造器注入为主，所以 6.3 不能只讲 `@Autowired`。

### 第 7 部分 · 缓存和消息（6 篇）

要回答的问题：数据库扛不住了怎么办？

- 7.1 Redis：数据结构和常用命令
- 7.2 缓存怎么用：读写策略、穿透、击穿、雪崩
- 7.3 缓存和数据库的一致性
- 7.4 Redis 的其他用法：分布式锁、限流、计数
- 7.5 消息队列：为什么要异步，基本模型
- 7.6 消息的可靠性和幂等

依据：Redis 在技术栈里。消息队列在 SpringBlade 里没有出现，讲多深取决于你们项目用没用。

### 第 8 部分 · 微服务（9 篇）

要回答的问题：一个服务变成几十个之后，多出了哪些问题？

- 8.1 为什么拆，拆的代价
- 8.2 注册和发现：Nacos
- 8.3 远程调用：OpenFeign、负载均衡、超时和重试
- 8.4 配置中心
- 8.5 网关：路由、鉴权、限流
- 8.6 容错：熔断和降级
- 8.7 分布式事务和最终一致
- 8.8 分布式下的登录状态、ID 生成、定时任务
- 8.9 链路追踪和日志汇总

依据：实测里有 14 个独立服务、15 个 Feign 客户端、5 个降级类，以及分布式事务的示例模块。

### 第 9 部分 · 上线和运行（6 篇）

要回答的问题：代码写完以后呢？

- 9.1 Linux：进程、端口、权限、常用命令
- 9.2 打包和部署
- 9.3 Docker
- 9.4 Nginx：反向代理和负载均衡
- 9.5 线上排查：日志、线程和内存快照、慢 SQL
- 9.6 安全清单：注入、越权、敏感数据

依据：实测里有 12 个 Dockerfile 和容器编排文件。

### 第 10 部分 · 回到你们的项目（5 篇，另加附录）

要回答的问题：BladeX 替我做了什么？

- 10.1 工程结构：一个服务为什么拆成接口模块和实现模块
- 10.2 BladeTool：基类、统一返回、工具类
- 10.3 登录、权限、多租户在 BladeX 里的样子
- 10.4 代码生成器生成的代码，逐行读
- 10.5 从零做一个需求：一张表、一组接口、一次跨服务调用
- 附录：接手若依老项目

依据：`R`、`Func`、`Condition` 这些 BladeTool 工具出现得比标准库还多。这一部分写之前必须和你们的 BladeX 版本核对。

## 五、还没确定的事

- 你们的 BladeX 是哪个版本（已确认是微服务版，有几十个服务）。
- 你们用不用消息队列、Elasticsearch、工作流，决定第 7 部分的深度和要不要加篇。
- 第 1–3 部分和《Head First Java》重合的地方写多细。
