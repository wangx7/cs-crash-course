第 0 节

从硬件到"更软"的东西

嗨，我是 Carrie Anne，欢迎收看计算机科学速成课！到目前为止，这个系列大部分时间都在讲硬件——计算的物理部件：电和电路、寄存器和 RAM、ALU 和 CPU。但在硬件层面编程既麻烦又不灵活，所以程序员想要一种更通用的方式给计算机编程——一种你可以称之为"更软"的媒介。没错，我们要讲软件了！

第 8 集里，我们一步步走了一个给我们设计的 CPU 的简单程序。第一条要执行的指令，也就是内存地址 0 里的那条，是 0010 1110。之前说过，指令的前 4 位是操作码（opcode）。在我们假想的 CPU 上，0010 表示 LOAD_A 指令——把一个值从内存移到寄存器 A。后 4 位定义内存位置，这里是 1110，也就是十进制的 14。所以这 8 个数字真正的意思是"把地址 14 读进寄存器 A"。

我们只是在用两种不同的语言。你可以把它想成英语和摩尔斯电码："Hello"和"···· · ·−·· ·−·· −−−"意思一样——都是你好！——只是编码方式不同。英语和摩尔斯电码的复杂程度也不同：英语有 26 个字母和多得多的发音，摩尔斯电码只有点和划，但它们能传达同样的信息。计算机语言也类似。

第 1 节

机器码与伪代码

我们已经看到，计算机硬件只能处理原始的二进制指令。这是计算机处理器的"母语"，事实上，也是它唯一会说的语言。这叫机器语言或机器码（machine code）。

在计算的早期，人们得用机器码写出整个程序。更具体地说，他们会先在纸上用英语写一个高层次版本的程序，比如："从内存取下一笔销售额，然后把它加到当天、当周、当年的累计总额上，然后计算要加的税"……等等。像这样非正式的、高层次的程序描述，叫伪代码（pseudo-code）。然后，等程序在纸上完全想清楚后，他们再用操作码表之类的东西，费力地手工把它展开、翻译成二进制机器码。翻译完成后，程序才能被送进计算机运行。

第 2 节

助记符、汇编语言和汇编器

可以想象，人们很快就受够了这个过程。所以到 1940 年代末、进入 50 年代，程序员开发出了稍微高层次一点、人更容易读懂的语言。操作码被赋予了简单的名字，叫助记符（mnemonic），后面跟着操作数，组成指令。于是程序员不必再把指令写成一堆 1 和 0，而是可以写成"LOAD_A 14"这样的东西。我们在第 8 集就用了这种助记符，因为它好懂多了！

当然，CPU 根本不知道"LOAD_A 14"是什么，它不懂基于文字的语言，只懂二进制。所以程序员想出了一个巧妙的办法：他们用二进制写了一些可以反复使用的辅助程序，读入文字形式的指令，自动把它们组装（assemble）成对应的二进制指令。这种程序叫——你猜到了——汇编器（assembler）。它读入用汇编语言（assembly language）写的程序，把它转换成原生的机器码。"LOAD_A 14"就是一条汇编指令的例子。

随着时间推移，汇编器有了让编程更轻松的新功能。一个很棒的功能是自动算出跳转地址。这是我在第 8 集用过的一个示例程序：注意 JUMP_NEGATIVE 指令跳到地址 5，普通 JUMP 跳到地址 2。问题是，如果我们在这个程序的开头再加一些代码，所有的地址都会变。想更新程序时这就太痛苦了！所以汇编器不再使用写死的跳转地址，而是让你插入可以跳转过去的小标签（label）。当程序被送进汇编器时，它会负责算出所有的跳转地址。

这是第 8 集的求余数程序，跳转目标写成了标签 LOOP、END。点"在开头插一行"再汇编：所有地址往后挪了一格，但你一个跳转地址都不用改

现在程序员可以把精力更多地放在编程本身，而不是底层的机械细节上，通过隐藏不必要的复杂性，能做出更复杂的东西。就像这个系列里做过很多次的那样，我们又往上爬了一层抽象。

然而，即使汇编器有自动把 JUMP 连到标签这样的好功能，汇编语言仍然只是机器码外面薄薄的一层。一般来说，每条汇编指令都直接转换成一条对应的机器指令——一一对应——所以它天生和底层硬件绑在一起。汇编器仍然强迫程序员去想要用哪些寄存器和内存位置。如果你突然需要多一个值，可能得改很多代码才能把它塞进去。

第 3 节 · 思想泡泡

葛丽丝·霍普与第一个编译器

这个问题没有逃过葛丽丝·霍普（Grace Hopper）博士的眼睛。作为美国海军军官，她是哈佛马克一号计算机最早的程序员之一，这台机器我们在第 2 集讲过。它是一头巨大的机电野兽，1944 年作为盟军战时努力的一部分建成。程序存在穿孔纸带上送进计算机。顺便说一句，你可以看到，他们给这个程序"打补丁"修 bug 的方式，就是字面意义上在纸带的孔上贴纸片。

马克一号的指令集非常原始，甚至没有 JUMP 指令。要写重复执行同一操作的代码，你得把穿孔纸带的两头粘在一起，做成一个实体的循环。换句话说，给马克一号编程简直是噩梦！

战后，霍普继续在计算领域的最前沿工作。为了释放计算机的潜力，她设计了一门高级编程语言，叫"算术语言版本 0"（Arithmetic Language Version 0），简称 A-0。汇编语言和机器指令是直接的一一对应，但高级编程语言的一行代码，可能会变成 CPU 执行的几十条指令。为了完成这种复杂的翻译，霍普在 1952 年造出了第一个编译器（compiler）。这是一个专门的程序，把用编程语言写的"源代码"转换成低级语言，比如汇编，或者 CPU 能直接处理的二进制"机器码"。

所以，尽管编程变容易了很诱人，很多人还是对霍普的想法持怀疑态度。她曾说：

"我有一个能用的编译器，可没人愿意碰它。他们小心翼翼地告诉我：计算机只会做算术，不会做程序。"—— 葛丽丝·霍普

但这是个好主意，很快就有许多人着手打造新的编程语言——今天已经有好几百种了！

第 4 节

编译器替你管寄存器：变量

可惜 A-0 的代码一个例子都没留下来，所以我们用 Python 这门现代编程语言来举例。假设我们想把两个数加起来并保存结果。记住，用汇编代码时，我们得从内存取值、跟寄存器打交道，还有其他底层细节。但同样的程序用 Python 可以这样写：

a = 3
b = 14
c = a + b

注意，这里没有寄存器或内存位置要处理——编译器会处理这些，把大量底层的、不必要的复杂性抽象掉。程序员只需要为需要的内存位置创建抽象，叫变量（variable），并给它们起名字。于是我们可以把两个数存进我们起了名字的变量里——这里我选了 a 和 b，但变量可以叫任何名字——然后把它们加起来，结果存进另一个我创建的变量 c。编译器在底层也许会用寄存器 A 来存 a 的值，但我不需要知道！眼不见，心不烦！

第 5 节

  
FORTRAN 与 COBOL

  
A-0 是一个重要的历史里程碑，但它和后来的版本并没有被广泛使用。几年后的 1957 年，IBM 发布了 FORTRAN，名字来自"公式翻译"（Formula Translation），它主宰了早期的计算机编程。FORTRAN 项目负责人 John Backus 说过：

  
"我的很多工作都来自懒惰。我不喜欢写程序，所以……我开始做一个编程系统，让写程序更容易。"—— John Backus

  
你懂的，典型的懒人——他们总是在打造自己的编程系统。总之，平均来说，用 FORTRAN 写的程序比等价的手写汇编代码短 20 倍，然后由 FORTRAN 编译器把它翻译、展开成原生机器码。圈内人怀疑它的性能能不能和手写代码一样好，但程序员能更快地写出更多代码，这让它在经济上成了一个很容易做的选择：用计算时间的小小增加，换来程序员时间的大幅减少。

  
当然，IBM 是卖计算机的，所以起初 FORTRAN 代码只能在 IBM 计算机上编译和运行。1950 年代的大多数编程语言和编译器，也都只能在一种计算机上运行。所以如果你升级了计算机，往往还得把所有代码重写一遍！

  
为此，来自工业界、学术界和政府的计算机专家在 1959 年组成了一个联盟——数据系统语言委员会，我们的朋友葛丽丝·霍普担任顾问——来指导开发一种能在不同机器上通用的编程语言。成果就是高级、易用的"面向商业的通用语言"（Common Business-Oriented Language），简称 COBOL。

  
为了应对不同的底层硬件，每种计算架构都需要自己的 COBOL 编译器。但关键在于，这些编译器都能接收同一份 COBOL 源代码，不管它在什么计算机上运行。这个理念叫"一次编写，到处运行"（write once, run anywhere）。今天的大多数编程语言都是如此，这是远离汇编和机器码的好处，因为后两者仍然是特定于某种 CPU 的。


  

    
  


  
这一切最大的影响，是降低了计算的门槛。在高级编程语言出现之前，编程是计算机专家和发烧友的专属领域，而且往往是他们的全职工作。但现在，科学家、工程师、医生、经济学家、教师，以及很多其他人，都能把计算融入自己的工作。多亏了这些语言，计算从一门繁琐深奥的学科，变成了一种通用、人人可用的工具。同时，编程的抽象也让那些计算机专家——现在叫"专业程序员"——能做出越来越复杂的程序，如果用汇编来写，那可能要几百万、几千万甚至更多行代码。







  
第 6 节

  
编程语言的黄金时代

  
当然，这段历史并没有在 1959 年结束。实际上，编程语言设计的黄金时代才刚刚开始，和计算机硬件的飞速进步齐头并进。


  

    
  


  
1960 年代有 ALGOL、LISP 和 BASIC 这样的语言。70 年代，Pascal、C 和 Smalltalk 发布了。80 年代给我们带来了 C++、Objective-C 和 Perl。90 年代有 Python、Ruby 和 Java。新千年则见证了 Swift、C# 和 Go 的兴起——别和《冰雪奇缘》的 Let it Go 或 Pokémon Go 搞混了。其中有些你可能听着耳熟，很多今天还在用。你现在用的网页浏览器，极有可能就是用 C++ 或 Objective-C 写的。

  
我刚才列的只是冰山一角，带着新奇功能的语言一直在被提出来。每一门新语言都试图利用新的、巧妙的抽象，让编程的某些方面更容易或更强大，或者利用新兴的技术和平台，让更多人能更快地做出更惊人的事情。

  
很多人认为编程的"圣杯"是用"普通的英语"：你只要说出想让计算机做什么，它就能弄明白并执行。这种智能系统目前还是科幻小说里的东西，《2001 太空漫游》的粉丝们也许觉得这样也挺好。

  

    2017 年之后的变化
    课程制作于 2017 年。之后出现的大语言模型，已经能根据自然语言描述写出相当像样的代码——你正在读的这个图文版，正文整理、示意图和交互演示，就是由 AI（Claude）按中文要求写出来的 HTML 和 JavaScript。但请注意它没有跳过本集讲的任何一层：AI 写出的是 JavaScript 源代码，浏览器的引擎再把它编译成机器码，CPU 依然只认 0 和 1。抽象又往上加了一层，下面那些层一层都没少。

    一句话
    汇编语言和机器码一一对应，只是换了个好读的写法；编译器才真正让一行代码变成很多条指令，并替你管寄存器和内存地址（变量）。高级语言降低了门槛，也让"一次编写，到处运行"成为可能。

1. 汇编器和编译器有什么区别？

      
      
汇编器把汇编语言翻译成机器码，基本是一一对应：一条汇编指令 → 一条机器指令，程序员仍要自己管寄存器和地址。编译器把高级语言翻译成低级语言，一行可能变成几十条指令，寄存器和内存位置由编译器决定。

    

    

      
2. 汇编器的"标签"解决了什么问题？

      
      
如果跳转地址写死成数字（JUMP 2），在程序前面插入代码后所有地址都会变，得一个个改。写成标签（JUMP LOOP），由汇编器在翻译时自动算出 LOOP 现在在哪个地址。

    

    

      
3. 程序员为什么愿意用 FORTRAN，哪怕它生成的代码可能比手写汇编慢一点？

      
      
FORTRAN 程序平均短 20 倍，写得快得多。用计算时间的小小增加换程序员时间的大幅减少，在经济上很划算。

    

    

      
4. "一次编写，到处运行"是怎么实现的？

      
      
每种计算机架构有自己的编译器，但它们都接受同一种语言的源代码。程序员只写一份源码，各台机器用自己的编译器把它翻译成本机 CPU 的机器码。汇编和机器码则绑定在某种 CPU 上，换机器就得重写。
