万维网

The World Wide Web

万维网不等于互联网：它是跑在互联网上的最大的一个应用。一个个页面靠超链接连成网，靠 URL 找到、靠 HTTP 取回、用 HTML 写成、由浏览器画出来；网页多了要靠搜索引擎来找——最后，聊聊"网络中立性"。

第 0 节

万维网 ≠ 互联网

嗨，我是 Carrie Anne，欢迎收看计算机科学速成课！前两集我们深入讨论了组成互联网的电线、信号、交换机、数据包、路由器和协议。今天我们再往上抽象一层，来讲万维网（World Wide Web）。

万维网和互联网不是一回事，尽管人们经常混用这两个词。万维网运行在互联网之上，就像 Skype、Minecraft 或 Instagram 一样。互联网是底层的"管道"，为所有这些不同的应用传送数据。而万维网是其中最大的一个——一个庞大的分布式应用，运行在全球数百万台服务器上，用一种叫网页浏览器的专门程序来访问。今天我们就来了解它，以及更多相关内容。

第 1 节

超链接与超文本

万维网（简称 Web）的基本组成单位是单个页面：一份包含内容的文档，内容里可以有指向其他页面的链接，这些叫超链接（hyperlink）。你们都知道它们长什么样：可以点击的文字或图片，点一下就跳到另一个页面。这些超链接形成了一张巨大的、互相连接的信息之网，"万维网"这个名字就是这么来的。

这个想法现在看来再明显不过了。但在超链接被实现之前，每次你想在计算机上切换到另一条信息，都得在文件系统里翻找，或者把它输进搜索框。有了超链接，你可以轻松地从一个相关话题流向另一个。

超链接信息的价值，早在 1945 年就被万尼瓦尔·布什构想出来了。他发表了一篇文章，描述了一台假想的机器 Memex，我们在第 24 集讲过。布什把它描述为"关联式索引……任何一个条目都可以随意地、立即地、自动地选中另一个条目"。他进一步解释说：

"把两样东西联系在一起的过程，才是最重要的……此后任何时候，只要其中一样出现在眼前，只需轻按一个按钮，另一样就能立即被调出来。"

1945 年的计算机连屏幕都没有，所以这个想法远远领先于它的时代！带超链接的文字如此强大，它也得到了一个同样酷的名字：超文本（hypertext）！今天最常见的超文本文档就是网页，由网页浏览器取回并渲染，我们待会儿讲。

第 2 节

URL 与 HTTP：取回一个页面

为了让页面能互相链接，每个超文本页面都需要一个唯一的地址。在万维网上，这个地址由统一资源定位符（Uniform Resource Locator），简称 URL 来指定。一个网页 URL 的例子是 thecrashcourse.com/courses。

上集讲过，你请求一个网站时，计算机做的第一件事是 DNS 查询：输入一个域名，比如 "thecrashcourse.com"，返回对应计算机的 IP 地址。有了想要的那台计算机的 IP 地址，你的浏览器就打开一个 TCP 连接，连到一台运行着一种叫网页服务器（web server）的专门软件的计算机。网页服务器的标准端口号是 80。

到这一步，你的计算机做的只是连上了 thecrashcourse.com 这个地址的网页服务器。下一步是向这台网页服务器请求 "courses" 这个超文本页面。为此要用一个名字起得很贴切的协议：超文本传输协议（Hypertext Transfer Protocol），简称 HTTP。最早有文档记载的版本 HTTP 0.9 创建于 1991 年，只有一个命令：GET。幸好，这基本上就是你需要的全部了。因为我们要获取 "courses" 页面，就给服务器发送这个命令：GET /courses。这个命令以原始的 ASCII 文本发给网页服务器，服务器回复我们请求的网页超文本，你电脑上的网页浏览器把它解释出来，渲染到屏幕上。如果用户点了一个链接去往另一个页面，计算机只需再发一个 GET 请求。你在网站上四处浏览时，就这样一直进行下去。

动手：浏览器取回一个页面的全过程

① DNS 查询域名 → IP 地址
② TCP 连接连到 IP 的 80 端口
③ HTTP 请求发 GET
④ 服务器回复状态码 + 超文本
⑤ 渲染浏览器画到屏幕上

在后来的版本里，HTTP 加入了状态码（status code），放在 GET 请求之后发回的超文本前面。比如状态码 200 表示"好的，页面找到了，给你！"；四百多的状态码表示客户端错误，比如用户向网页服务器请求一个不存在的页面，就是那个可怕的 404 错误！

在 DevTools 里看真正的 HTTP 打开开发者工具的 Network 面板刷新页面，点第一个请求，能看到 "Request Method: GET"、"Status Code: 200"。常见的还有 301/302（页面搬家了，去新地址）、304（没变，用你缓存的就行）、500（服务器自己出错了——5 开头是服务器的锅，4 开头是请求方的问题）。今天的网站基本都用 HTTPS，默认端口是 443 而不是 80，第 33 集讲加密时会讲到它多出来的那一层。
第 3 节

HTML：给文本加上标记

网页超文本是以普通文本的形式存储和发送的，比如用 ASCII 或 UTF-16 编码，我们在第 4 集和第 20 集讲过。因为纯文本文件没法指明哪些是链接、哪些不是，所以需要发明一种办法，用超文本元素给文本文件做"标记"（mark up）。为此，人们开发了超文本标记语言（Hypertext Markup Language，HTML）。HTML 的第一个版本 0.8 创建于 1990 年，提供了 18 种 HTML 命令来标记页面。就这些！

我们用它们来做一个网页吧！首先，给网页一个大标题。输入字母 "h1"，表示一级标题的开始，再用尖括号括起来，这就是一个 HTML 标签（tag）的例子。然后输入想要的标题文字。我们不想让整个页面都是标题，所以要像这样"关闭" h1 标签：前面加一个小斜杠。

现在加点内容。访客可能不知道克林贡人是什么，所以我们把这个词做成一个超链接，链接到克林贡语言研究院，让他们了解更多。这要用 A 标签，在里面加一个属性，指定超链接的引用地址（href），也就是点击链接时要跳转的页面。最后关闭 A 标签。接着加一个二级标题，用 "h2" 标签。HTML 还提供了创建列表的标签：先加一个有序列表（ordered list）的标签，然后想加多少项就加多少项，每项用 <li> 标签包起来，li 代表列表项（list item）。人们可能不知道 bat'leth 是什么，所以也把它做成超链接。最后，为了格式规范，关闭有序列表标签。

第 4 节

浏览器

这就把我们带回了网页浏览器：电脑上让你和所有这些网页服务器对话的应用程序。浏览器不仅请求页面和媒体，还要把返回的内容渲染出来。

第一个网页浏览器和网页服务器，是（现在的爵士）蒂姆·伯纳斯-李在 1990 年花两个月写出来的。当时他在瑞士的欧洲核子研究中心（CERN）工作。为了完成这一壮举，他同时创建了今天讨论的几项最基本的网络标准：URL、HTML 和 HTTP。两个月的成果，还不赖！不过公平地说，他研究超文本系统已经十多年了。他先在 CERN 的同事之间传用这个软件，1991 年向公众发布。万维网诞生了。

重要的是，万维网是一个开放标准，任何人都可以开发新的网页服务器和浏览器。这让伊利诺伊大学厄巴纳-香槟分校的一个团队在 1993 年做出了 Mosaic 浏览器。它是第一个能把图片嵌在文字旁边的浏览器——之前的浏览器要在单独的窗口里显示图片。它还引入了书签这样的新功能，图形界面也很友好，因此大受欢迎。尽管它看起来很古旧，但已经能认出就是我们今天熟悉的网页了！

到 1990 年代末，已经有很多浏览器在用，比如 Netscape Navigator、Internet Explorer、Opera、OmniWeb 和 Mozilla。也开发出了很多网页服务器，比如 Apache 和微软的互联网信息服务（IIS）。每天都有新网站冒出来，亚马逊和 eBay 这些网络巨头都创立于 1990 年代中期。那是一个黄金时代！

第 5 节

搜索引擎

万维网蓬勃发展，人们越来越需要找东西的办法。如果你知道要去的网址——比如 ebay.com——直接在浏览器里输入就行。但如果你不知道该去哪儿呢？比如你只知道你想看可爱猫咪的图片。现在就要！去哪儿找？

起初，人们维护一些网页，充当目录，用超链接指向其他网站。其中最有名的是"杰瑞和大卫的万维网指南"，1994 年改名叫 Yahoo。随着网络变大，这些人工编辑的目录开始变得难以管理，于是人们开发了搜索引擎。

思想泡泡

最早像今天这样运作的网页搜索引擎是 JumpStation，1993 年由乔纳森·弗莱彻在斯特林大学创建。它由三个协同工作的软件组成。第一个是网络爬虫（web crawler），一个跟着它在网上能找到的所有链接走的软件：每当它顺着链接到了一个有新链接的页面，就把这些新链接加进自己的列表。第二个部分是一个不断扩大的索引（index），记录爬虫访问过的页面上出现了哪些词。最后一个部分是查询索引的搜索算法：比如我在 JumpStation 里输入 "cat"（猫），所有出现过 "cat" 这个词的网页都会列出来。

早期搜索引擎用非常简单的指标给搜索结果排序，通常就是搜索词在页面上出现的次数。这还算好用，直到人们开始钻空子，比如在自己的网页上把 "cat" 写几百遍，就为了把流量引过来。谷歌的成名，很大程度上归功于一个聪明的算法，它绕开了这个问题：与其相信网页上的内容，不如看其他网站是怎么链接到这个页面的。如果是一个把 cat 写了一遍又一遍的垃圾页面，没有网站会链接它；但如果这个页面是关于猫的权威，其他网站很可能会链接它。所以这些所谓"反向链接"（backlinks）的数量，特别是来自有信誉网站的反向链接，往往是质量的好标志。这最初是 1996 年斯坦福大学的一个研究项目，叫 BackRub，两年后独立出来，成了今天我们熟知的谷歌。谢谢思想泡泡！

    第 6 节

    网络中立性

    最后，我想花点时间谈一个你最近可能常听到的词："网络中立性"（Net Neutrality）。现在你对数据包、互联网路由和万维网都有了理解，足以弄懂这场大争论的本质，至少是技术上的本质。

    简单来说，网络中立性的原则是：互联网上的所有数据包都应该被平等对待。不管这些包是我的邮件，还是你在看的这个视频，都应该以同样的速度和优先级前进。但很多公司更希望自己的数据能优先送到你这里。以 Comcast 为例，它是一家大型 ISP，同时也拥有很多电视频道，比如 NBC 和 The Weather Channel，这些频道都在网上播放。不是要找 Comcast 的茬，但如果没有网络中立性的规定，它们就可以说：自己的内容要以高优先级丝滑送达……而其他的在线视频则会被限速（throttled），也就是故意给更少的带宽和更低的优先级。再强调一下，这只是假设。

    动手：同一条线路，两种规则

    大体上，网络中立性的支持者认为，让互联网服务提供商拥有这种能力——实际上就是在互联网上设收费站、提供"高级"数据包投递——会埋下剥削性商业模式的种子。ISP 可能成为内容的"守门人"，有强烈的动机去为难竞争对手。而且，如果 Netflix 和谷歌这样的大公司能花钱买到特殊待遇，小公司——比如初创公司——就会处于劣势，扼杀创新。

    另一方面，也有很好的技术理由，让你可能希望不同类型的数据以不同的速度流动：那通 Skype 通话需要高优先级，但一封邮件晚几秒到也没什么大不了。网络中立性的反对者还认为，市场力量和竞争会抑制不良行为，因为客户会离开那些限速他们喜欢的网站的 ISP。

    这场争论还会持续一段时间。正如 Crash Course 一贯鼓励的，你应该自己去多了解一些，因为网络中立性的影响复杂而深远。我们下周见！

    第 7 节

    本集小结

    • 1945万尼瓦尔·布什构想 Memex 和"关联式索引"
    • 1990伯纳斯-李在 CERN 用两个月写出第一个浏览器和服务器，同时创建 URL、HTML、HTTP；HTML 0.8 有 18 种命令
    • 1991万维网向公众发布；HTTP 0.9 只有 GET 一个命令
    • 1993Mosaic 浏览器：图文混排、书签；JumpStation 搜索引擎：爬虫 + 索引 + 搜索算法
    • 1994"杰瑞和大卫的万维网指南"改名 Yahoo
    • 1990s 中亚马逊、eBay 创立；Netscape、IE、Opera……Apache、IIS
    • 1996斯坦福的 BackRub 项目，靠反向链接排序，两年后成了谷歌
    一句话 万维网是跑在互联网上的超文本应用：URL 给每个页面一个地址；浏览器先 DNS 查 IP，再 TCP 连上服务器（80 端口），用 HTTP 的 GET 取回页面，服务器带着状态码（200、404……）回复用 HTML 标记的纯文本，浏览器把它渲染出来。网页太多就要靠爬虫、索引和排序算法来搜索。

    合上页面，试着回答

    1. 万维网和互联网是什么关系？
    互联网是底层"管道"，负责为各种应用传送数据；万维网是运行在互联网之上的一个应用（最大的一个），和 Skype、Minecraft、Instagram 一样，用浏览器访问。
    2. 在浏览器里打开 thecrashcourse.com/courses，背后依次发生了什么？
    DNS 查询把 thecrashcourse.com 换成 IP 地址 → 浏览器和这个 IP 上的网页服务器（80 端口）建立 TCP 连接 → 用 HTTP 发送 ASCII 文本 "GET /courses" → 服务器回复状态码和页面的超文本（HTML）→ 浏览器解释并渲染到屏幕上。
    3. 为什么需要 HTML？<a href="..."> 是做什么的？
    网页以纯文本存储和发送，纯文本没法表示哪些是标题、哪些是链接，所以要用标签给文本"加标记"。A 标签把包住的文字变成超链接，href 属性指定点击后跳转的页面地址。
    4. 早期搜索引擎按什么排序？有什么漏洞？谷歌怎么改进的？
    按搜索词在页面上出现的次数排序，于是有人在页面上把关键词写几百遍来骗流量。谷歌不相信页面自己的内容，而是看有多少其他网站（特别是有信誉的网站）链接到它，也就是反向链接的数量。
